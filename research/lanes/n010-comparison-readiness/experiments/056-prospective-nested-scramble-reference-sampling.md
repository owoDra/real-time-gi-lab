## Exact candidate and unchanged integral

Start from the original cached cosine oracle generated by the frozen
`generate_cached_oracle.py`, not primary-direction guide build 151. Keep the
same 16-dimensional 32-bit Sobol table, direction numbers, sample indices,
fixed per-bounce dimension consumption and nested power-of-two levels.
Only the uniform generator's scrambling changes; there is no guidance pilot,
Renderer training output, proposal rejection, sample splitting or extra
scored paths per spp.

For each uniform value at dimension d, define 64-bit key
`mix(seed XOR mix(pixel) XOR mix(d + 0x4e303130))`, using the existing unsigned
64-bit mix function. Read the ORIGINAL Sobol integer x. Set node=1 and y=0.
For b=31 down to 0, let input_bit=(x>>b)&1 and
flip=mix(key XOR node)&1; append input_bit XOR flip to y, then replace node
by (node<<1)|input_bit. All node operations use unsigned 64-bit integers.
Return `(double(y)+0.5)*2^-32`. No original digital shift is additionally
applied. Nodes include depth through their leading one; the permutation at
a bit depends only on the original higher input bits, key and depth. For
each key this is an invertible binary-tree permutation, preserving dyadic
prefix occupancy and strictly interior finite uniform values. The key is
fixed for a replicate/pixel/dimension and independent of requested spp.

Keep the original BVH/intersections, signed-zero behavior, sidedness,
offset/inset, camera, point lighting, radiance accumulation, moments and
finite B2/B8 transport verbatim. No geometry/light/direct cache change.
Retain a zero-valued `proposal_null_samples` diagnostic field solely to use
the existing five-counter prefix format; no null event is introduced.
Change only the metadata oracle name to identify this separate variant.
Uncertainty still uses the four fixed replicate outputs, never iid
per-sample second moments. All images/pixels, including reference zeros,
remain in scoring. No uncertainty correction or post-hoc selection.
