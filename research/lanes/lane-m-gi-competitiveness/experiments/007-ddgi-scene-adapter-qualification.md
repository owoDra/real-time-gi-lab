## Physical and finite-depth design

New isolated HLSL supplies inline ray-query probe production and surface gather around the unmodified SDK `DDGIGetProbeRayDirection`, ray-data encoding, probe blending and `DDGIGetVolumeIrradiance`. Source scene/frame bytes remain the original M001 lock. Grey rho=1, opaque two-sided geometry, black miss, original point-light regularization, four-ULP offset, self rejection, primary rays and finite ray extent are preserved. No sample-harness albedo0.95 or saturate-HDR clamp is imported. SDK distance/irradiance atlas interpolation remains its approximate estimator, whose error must be scored without masks.

Proposed B2 has one probe-production/blending stage from zero irradiance, then primary surface gather. B8 has seven finite stages; stagek reads only a separate immutable atlas from stagek−1. Distinct ping-pong SDK volumes/resources prevent within-stage feedback. `previousReady=0` suppresses all prior irradiance on the first stage. This is a proposed finite composition, not yet a demonstrated finite-depth implementation. Hysteresis0, classification/relocation/variability off, no reused history across separate static images. Any later temporal/history reuse or changed-light/geometry path needs its own explicit state schedule and evidence, including reset/invalidation costs. Do not claim temporal support from static shader preparation.

Before any heldout acquisition, freeze the host implementation, all descriptors/formats, full probe/ray budgets, origin/spacing derived only from frozen geometry, atlas encoding/bias/clamp constants, RNG/rotation sequence, finite-stage count, complete tile coverage and operational guards, image/output lifecycle and total persistent/true-peak resource accounting. No budget ladder is selected by this development document; the exact comparison budget registration must precede the first DDGI candidate image. The host adapter and actual-scene runtime remain to be implemented. CPU shader compilation alone does not instantiate the method.

1. Rehash every pinned SDK/compiler file; compile both adapter entries on CPU to new private outputs, preserving source snapshots, command, diagnostics, binary hashes and descriptor reflection. No native/GPU process. Compilation failure is retained and fixed in a new identified CPU attempt; never overwrite its bytes.

Implement/build a standalone host on CPU and test source/frame layout, resource and finite-stage state machines, disjoint ray tile coverage, output refusal and failure/timeout handling before any GPU invocation. Keep the official SDK shaders unchanged and verify descriptor/resource compatibility. Account all AS, buffers, images, staging, simultaneous old/new atlases and zero teardown.
3. Freeze separate bounded GPU semantic controls before running them: original primary/direct comparisons against eligible physical state, black and constant-field behavior, HDR non-clamping, one-stage/no-feedback and seven-stage/no-in-place-feedback identities, full capture bytes and finite-value checks, memory lifetime/cap, and explicit unsupported features. Preserve every PASS/FAIL/operational partial and do not acquire heldout quality images if required semantics fail.

Only after valid controls and a separately committed fixed budget ladder, acquire one named scene/transport/budget at a time, audit full physical reference provenance/all pixels, and stop at first quality PASS or exhausted loss. Do not fabricate supported finite-depth or history capability from this source design. Retain unsupported boundaries and do not hide quality losses.
