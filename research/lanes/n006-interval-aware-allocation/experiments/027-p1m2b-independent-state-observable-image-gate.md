# N006 P1m2b — bounded independent-state observable-image feasibility screen (PROSPECTIVE; DESIGN ONLY)

2026-10-11, Issue #42. Registered **after** the completed P1m2a original GPU result [037](../results/037-p1m2a-fixed-tetra-octant-null-image.md); **no P1m2b code or GPU result exists yet**. This protocol is a deliberately **bounded** attempt to test whether any +4-ray intervention changes accepted PFM bytes outside the original static/C3 convenience sample. It is not a predictor quality study, statistical independence claim for geometry, or P2 scheduler.

## Why the previous frozen static keys are exhausted
Both original P1a uniform and alternative tetra-octant jitter hit sampling passed correctness but **all six treated static/C3 outputs were byte-identical to the common control**. The alternative produced 2 positive new ray contributions/sum16=5 on the high-consumer key but the merged 8+4 16-bit rounded mean stayed 1. *Any fixed reference* gives signed global RGB RMS improvement 0 for those six treatments. Stop direction/cascade/key tuning on this frozen set.

## Pre-committed distinct test state / key / arm selection, before reading any new candidate outcome
1. **Scenarios only**: `camera-motion` and `light-motion` under accepted `lane-e-final-software` canonical lean-hash Sponza. Use fixed existing repository camera/light motion paths and deterministic target-frame parameters. Preserve source scene SHA `2a86fdc2dc92d7c6a740682c61ec97f3101f489a06443c6823aff85bb990e5f6`. These are different camera/light trajectories but **not** an independent scene geometry. Reserve `moving-rigid`, `deforming-control` and a **separate geometry** as future holdouts, which remain sealed until an observable signal is demonstrated. Do not call these two scenarios a sufficient P1 evaluation.
2. **Key selector**: on each scenario's canonical control **prior to extra ray tracing**, collect full accepted M0 `key_rows` with `consumer_pixels` and `producer_owner_outputs`; among each cascade 0..3, select (a) lowest token among maximum-consumer rows, (b) lowest token among zero-consumer rows. Deduplicate if the same token. If a stratum has no matching key, retain an explicit `missing_stratum` and never substitute a post-hoc value. At most **8 keys/scenario ×2 scenarios =16 selected keys**. Selector is frozen by these rules, not the existence or magnitude of observed GPU hits, image deltas or reference labels. Record key-selection table before intervention execution.
3. **Controls**: for every scenario run two independent-process, clean, 32-source+8-target-warmed **control** frames and require PFM byte equality and original M0 key-row parity across controls before any candidate arm. If controls themselves differ, retain invalid noise baseline and stop.
4. **Each selected key**: isolate M1a-original **uniform** and M2a **tetra-octant** direction arms, both exactly +4 additional rays on canonical 8-ray base. Run separately, preserving all source/target warmups, original shaders, 3008 is static-only and **must NOT be hardcoded across changed trajectories**, same per-scenario original canonical output count, N004 hit oracles, unique output/key identity, owner conservation, counter and 12-sample merge closure. Compare each arm only with **its matching scenario** control. If the completed PFM hash is byte-identical, record exactly zero influence; a new direction hit/radiance count alone is no quality label.
5. **Primary feasibility indicator**: *any changed float32 RGB channel* in the entire canonical output PFM, reproducible across a repeated isolated candidate run with the same frozen scene/key/arm, and control-control exact parity. Also report `extra_hit_count`, `extra_positive_radiance_rays`, base/extra sum16, rounded means, changed pixel/channel counts, max absolute RGB difference and all retained PFM SHA. No arbitrary crop, display-space quantization or threshold selected after seeing effects. A nonzero difference is **causal influence only**, NOT a quality gain.
6. **Bounded STOP**: If none of the at-most-32 treatment cells (16 keys×2 arms) produce *reproducible nonzero PFM influence*, STOP this specific 4-ray/present-quantization allocation family in the current renderer; retain zero/negative results, do not adaptively search more directions/keys/scenes. A different output representation or multi-key/budget change would require an independent new research hypothesis and correctness/ROI protocol, not a silent extension. If ≥1 cell produces valid nonzero effect, **freeze those cells** and obtain one common independently-converged HDR reference per scenario under prior [024](./024-p1m1b-independent-reference-signed-gain-protocol.md), matched-repeat noise, signed global RGB RMS vs that reference and then evaluation on sealed geometry+trajectory. A negative signed gain does not count as success.
7. **Performance separate**: P1m2a's ~625–632 µs single-thread key scan is scaffolding, never a valid scheduler. No P2 allocation until a measured GPU-indexed dispatch, pre-secondary consumer cost, extra-ray traversal/merge overhead, quality effect and independent ROI all pass. M0b existing GPU count pass can inform cost but not quality.

**Status: prospective protocol only.** Future implementation must extend the CLI source authorization beyond the old 3 frozen static tokens safely, preserve existing M1a/M2a behavior byte-for-byte, add fail-closed regression tests and a separate N006-only pilot runner. No accepted shaders, no PR/Actions; no GPU command should be given for P1m2b until implementation exists.
