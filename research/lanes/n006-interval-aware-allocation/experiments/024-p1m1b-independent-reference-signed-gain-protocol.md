# N006 P1m1b — independently converged HDR reference and signed marginal-ray labels (PROSPECTIVE)

Issue #42; source-pre-registered on 2026-10-11 after M0/M0b 5/5 success but **before** any P1m1a GPU intervention outcomes. P1m1a [023](./023-p1m1a-single-canonical-key-extraray-preflight.md) is a correctness stage; it does NOT establish quality improvement or the predictive signal. **This document authorizes no new P2 scheduler without P1 independent ranking evaluation and sealed holdout.**

1. Mechanism gate: P1m1a must 4/4 PASS (accepted baseline PFM SHA, original 8-ray compact prefix, 4 added to exactly one canonical output, same key/owner weighting, N004 hit and 12-sample accumulator closure). If not, fix mechanism and repeat the same *prospective* key set without cherry-picking replacements or ignoring zero/no-effect outcomes.
2. Reference: Generate one **independently converged 8-bounce** reference from the unchanged static control scene/camera/light using the existing N001 CPU `n001_render_reference` and its verified `converged` flag, report SPP, reference PFM SHA256 and original `replicate_p99_abs_luminance`/`replicate_p99_relative_luminance`. The *same* reference target image is used for control and all three isolated interventions; never generate separate references from candidates, never treat candidate's result as reference.
3. Signed marginal image-label for each fixed token `zero/low/high`: `gain = RGB_RMS(8-ray control, reference) - RGB_RMS(12-ray selected key, reference)`; negative outcomes mean worse, zero outcomes remain zero. Also report RGB RMS pre/post, count and fraction of changed RGB pixels, p99 absolute per-pixel luminance change, and number of exact-equal pixels. No post-hoc spatial crop, per-pixel color threshold or cascade-filtered metric chosen to favor one token.
4. Repeat baseline control GPU frames and reference rendering with frozen deterministic seeds if needed to bound noise. Pre-register a **calibration-derived** minimum detectable signed gain before any distinct evaluation/holdout trajectory is inspected. Do not compare a reference *p99 absolute luminance* noise quantity directly to a **global RGB RMS** without a principled unit-consistent conversion; compute a matched metric under reference replicate variability or mark formal precision unavailable. Report float precision and SHA of each raw PFM.
5. Split discipline: three static/C3 original frozen keys are **calibration only**. Any predictor calibration, thresholds, weighting of `consumer_pixels` by cascade/multiplicity must use calibration labels only. Next evaluate on distinct trajectories, scenes and light/camera paths specified before outcomes; finally sealed independent held-out trajectories (not merely a different RNG seed of the same frozen Sponza frame). Report all 4 cascades in independent evaluation, including zero coverage and negative gains.
6. Null hypothesis: consumer count as computed before secondary predicts *whether selected extra rays improve reference RGB RMS*. Test ranking against simple cascade-only, random-seeded and uniform-budget baselines at equal K, with cost `14–23 µs` counter overhead from M0b included in GPU ROI but not confused with a complete scheduling loop. One-key gains need not add linearly; combined-key test is required before P2.
7. **STOP/REFINE** if no gain exceeds calibrated repeat/reference noise, or if correlation/ranking on independent evaluation fails, or if payback is less than signal-extraction+decision+extra-ray overhead. A zero-consumer key could still affect a future camera path, so do not claim universal invalidity of its base rays from single-frame evidence.

Current state: **design frozen only**; CPU reference creation, signed RMS results, uncertainty calibration, independent evaluation and P2 are not implemented or GPU validated at the time of writing. No PR/CI/Actions, no changes to accepted historical shaders.
