Issue #42. **Prospective experimental contract; frozen 2026-10-10 AFTER P1l-B0 five-scene result, BEFORE any candidate shader build or GPU timing.** Evidence `../results/021-p1l-b0-five-scene-software-work-counts.md`. Existing N003 software primary shader `shaders/research/lane_n_end_to_end_renderer/n003_primary_software.comp.glsl` always does `stack[stack_size++] = node.data.x; stack[stack_size++] = node.data.y;`; LIFO always visits right first, regardless of ray origin/direction or child bounds. This is a hypothesis for avoidable closest-hit traversal and best-t pruning, **not proof of inefficiency**.

## Candidate and falsifiable hypothesis

**B1a (one candidate only):** Clone N003 software-primary shader into a new **N006-only** SPIR-V variant with **approximate near-first child scheduling**, using child AABB center projected along the current ray direction to choose which child to pop first. Sort ONLY the push order of the two existing child IDs; do not change node/leaf topology, triangle test math, hit tie-break tolerances, bounds test or published result format. Pushing the farther estimated child first means LIFO visits estimated nearer child first. This intentionally avoids adding ray/child slab intersections just to sort, although two additional child-node reads can reduce performance; the test determines the sign. **Center projection is a heuristic**, not guaranteed true ray/AABB near-entry ordering. Keep the untouched N003 default as arm 0 and distinct opt-in N006 shader as arm 1; *never* change accepted N003/E003 SPIR-V targets, N004/N005 or GitHub Actions.

**Hypothesis:** previously logged **1.57–2.48 million primary BVH node pops** and p99 247–301 per screen-pixel rays can be reduced by visiting closer branch first and improving closest-hit `best_t` pruning, while preserving PFM image and primary hit buffer byte-for-byte. Could fail due to extra bounds memory reads, ray divergence or conservative pruning; fail means REJECT/REFINE, not accept a plausible story.
