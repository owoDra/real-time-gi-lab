# N006 P1l-B1b — bounded near-first pruning attribution (frozen before implementation)

Issue #42. **Prospective COUNTS-ONLY diagnostic**, frozen after REJECTED B1a (accepted result `../results/023-p1l-b1a-matched-near-first-reject.md`) and before any B1b GPU run. This is **not** permission to rehabilitate the B1a code or loosen its previously failed acceptance gates.

## Research question

The original N003 software-primary shader popped fixed-order binary BVH children; B1a's ray-projected child-center sort changed only the LIFO push order but added two child-node loads. B1a had **5/5 valid scene images/hits and 15/15 matched processes**, yet **0/5 primary win gates** and **4/5 full renderer median regression gates failed**, including a consistent moving-rigid regression. We do not know if B1a *decreases visits and is instruction/memory-bound*, or *fails even to reduce visits*. Find out **before trying new node-order heuristics**.

## B1b experiment (small, strict and separate from timing)

- The **N006-only** B0 primary count shader (`n006_p1l_primary_count.comp.glsl`) reports each screen pixel's `uvec4(node_pops, triangle_tests, accepted_hit, stack_overflow)`. Create a **separate instrumented N006-only B1a clone** using *identical counters/outputs*, modifying ONLY the child LIFO push ordering to match frozen B1a candidate (`n006_p1l_b1_primary_near_first.comp.glsl`). Leave all three existing accepted N003/E003 shaders and B0 original untouched.
- On five existing Lane-E-final SOFTWARE Sponza scenes (static/camera/light/moving-rigid/deforming), compare B0 fixed-child-order and B1b B1a-near-first **on exactly the same target geometry, GPU rays, primary pixel count and camera**. Keep 32 source+8 target warmups and one canonical P1j-A lean-copyback target for each scenario. A separate diagnostic command AFTER the original uninstrumented GPU frame dispatches both instruments to **private count and hit buffers**. If the B1a original GPU candidate pipeline is also run for a byte-parity control, its timing is not mixed into instrumentation times.
- On every pixel and both arms, require the independent instrumented `GpuHit` bytes exactly match the **same accepted original uninstrumented GPU primary hit bytes**, and final frozen Software HDR PFM SHA exact. Freeze 320×180 pixels and one `uvec4` counter row per pixel per arm; no atomics, unbounded allocations or writes into accepted renderer/hit/storage buffers. Zero stack overflow; unchanged triangle tie-break math. Record original and near-first **sum/mean/p50/p90/p99/max/nonzero** for node pops, triangle tests, hit, stack overflow, plus per-pixel signed differences and the count of pixels with fewer/equal/more node visits. Attribute primary geometry/rays from original N006 evidence, not a new reference.
- Only **one separate GPU process per scenario for the first diagnostic campaign (5 processes)**, with hard 10-minute timeout/process and checkpointing. If any invalid count/output, mark `invalid-retained` and stop. This counts *stable geometric work* and does not claim stable per-frame GPU runtime. If counter metrics suggest unexpectedly unstable work, isolate a two-process smoke repeat before changing design.
- **No GPU performance claim from instrumented shader times.** Add an *optional* offline compiled SPIR-V instruction/statistics audit (shader size/instructions/branch/memory loads; tool and commands pinned, do not mislabel counts as physical memory transactions). If device-side occupancy/register-count profiling is unavailable, mark `unmeasured`, do not fabricate counters.

## Go/no-go questions for later candidate designs

1. If B1a does **not** reduce N003 primary node visits/triangle tests in the five scenes, **do not pursue** this approximate center heuristic or another costly pointer chase first. Prefer independent secondary E003 quantized child AABB or workload-directed shadow traversal experiments.
2. If B1a reduces node/triangle work **despite slower GPU time**, classify it as an **instruction/memory-load tradeoff failure**, not a successful optimization. Evaluate a precomputed near-child proxy / conservative child AABB ordering only with explicit bound and objective; any B1c implementation requires a **new frozen protocol and a tiny GPU smoke** before full 15-process matched repetition. Do not assert causal memory bandwidth without measured counters.
3. If a subset of scenes differs, report the full five-scene distribution; **no** retroactive static-only pass or elimination of moving-rigid. Keep prior B1a rejection unchanged even if a mechanism is diagnosed.
4. Shadow N003 and secondary E003 are separate work domains. B0 indicated 0 camera/moving shadow rays, 251 static/deforming shadow rays with ~63–65 node pops per launched ray, and 9,797 light rays with ~4.3 nodes each; *do not* optimize the zero-query paths. E003 had ~25.5–26.3 quantized child AABB tests per actual canonical ray, ~3.4 hash probes; counts alone do not prove GPU cycle cost.
