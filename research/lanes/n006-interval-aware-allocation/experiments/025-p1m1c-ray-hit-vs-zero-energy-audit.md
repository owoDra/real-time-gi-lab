# N006 P1m1c — frozen 3-key added-ray hit/miss vs zero-energy audit (prospective)

Issue #42, authored **after** [034](../results/034-p1m1a-canonical-key-causal-null-4of4.md) and **before** any M1c GPU outcome. **Exploratory mechanism diagnosis**; this is neither a rerun/relabel of the frozen M1a results nor a new predictive quality experiment. Nulls are retained.

## Research question
In M1a, **all 12 total extra rays** (4 rays for each of three static/C3 keys) yielded `extra_radiance_sum16=0`, even for 875-consumer key; all three candidate HDR PFMs were bitwise identical to their common control. Distinguish **miss** from **hit with zero 16-bit radiance** in the actually traced GPU work, without changing directions or reference image.

## Design frozen before GPU
- Exact same accepted SW/static/C3 key triplet, 32+8 source/target warmups per isolated process, same 8 base octant directions plus four deterministic P1a hashed directions with ordinals 0..3, original `N006` GPU ray/traversal/radiance/merge/storage/composite shaders unchanged, reference SKIPPED.
- Inject exactly one key via the same already-PASSED M1a mechanism, no new rays or sampling policy; read back N006 `impl.hits` from the completed frame in the debug CPU readback **only** (32-byte GpuHit per actual ray), and classify exact 8 base/4 tail rays of that one canonical output. No extra GPU shader or instrumented stage. `GpuHit.metadata[3]==1` is traversal hit; reject any hit flag other than 0 or 1 and non-finite hit distance on any hit. `contributions[id].y>0` is a post-radiance 16-bit positive sample. Distinguish hit-and-zero-radiance from miss; do not infer it was exclusively a shadow/normal/light issue unless separately computed.
- Per target: `base_hit_count`, `extra_hit_count`, `base_positive_radiance_rays`, `extra_positive_radiance_rays`, `extra_hit_zero_radiance_rays`, `extra_miss_count`. Enforce `extra_hit_count + extra_miss_count == 4`, `positive_sample => hit` for direct-Lambert shader; all 12 samples, sum16/mean16 and per-work output identity validated as P1m1a.
- The M1a image and reference SHA must remain identical to the accepted control and original M0 keys; all three paired HDR deltas remain **zero**. A classification difference is **not** quality improvement.
- Report GPU append cost separately; the current `layout(local_size_x=1)` serial scan of 3008 keys costs ~620–634 µs, is diagnostic scaffolding, not an efficient allocator. Do not interpret as four-ray traversal cost. No timing pass/ROI gate in M1c.
- **Outcomes**: (A) 0/4 extra hits -> target interval/direction/empty-space sampling cause; (B) >0 hit and 0 contributions -> shading/quantization cause; (C) positive extra radiance but identical image -> integer mean/weight or downstream masking; (D) changed image vs control -> fail frozen M1c exact parity, investigate nondeterminism. Negative/zero evidence retained as-is. **No post-hoc token replacement, new strata, scene switch, or altered direction distribution.**

After M1c either (i) pre-register an alternative *sampling* pilot with independent keys and controls or (ii) proceed to P1m1b signed HDR reference for any **nonzero image intervention**. Frozen calibration zero/low/high already have **exact signed RMS gain=0 for any shared reference**, so do not consume significant compute merely to reprove those same zeros. P1 ranking/heldout/P2 must remain blocked until an independently reference-positive signal exists; no accepted shaders, PR, or GitHub Actions are permitted.
