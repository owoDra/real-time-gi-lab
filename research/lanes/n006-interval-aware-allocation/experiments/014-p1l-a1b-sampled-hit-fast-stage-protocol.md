# N006 P1l-A1b — sampled CPU-hit verification, full GPU/HDR per-frame gates

Issue #42. **New prospectively defined protocol**, because P1l-A1's original 30-process runner was *not* economically executable. The user reported P1l-A1 stopped at **4/30 complete after ~8h**, with the current `phos-n006-intervention` process CPU-bound at ~99.6% for 36 minutes. The old protocol and its saved 4 finished raw cases are retained; **do not merge, re-label or extrapolate them as completed P1l-A1**.

## Source-supported root cause

The inherited accepted N004 diagnostic `I001Runtime::n004_hit_diagnostics()` downloads every ray/hit and does **a per-ray CPU `traversal::trace_reference(scene.triangles, ray)`**. The original P1l-A1 added this heavy validator to all 31 later source warmups, all 8 target-state warmups and all 12 measurement frames (52 frames/process including initial source). On HWRT, these are mostly ~133,000-ray *current* source/target frames. The helper also constructs a new CPU software BVH and runs a GPU validator BVH cross-check on each call. The measured ~8 hours / 4 completed experiments, active 99.6% CPU renderer, and code agree with a major **CPU-side validation overhead**, not necessarily slow GPU shader performance. No profiler was attached, so do not claim a measured percentage of CPU time without sampling stack.

## Distinct A1b protocol and safety tradeoff

Use the **same 5 fixed scenarios × HWRT/Software × 3 fresh processes = 30**, same 32 source warmups + 8 stable target warmups + **12 canonical P1j-A lean-copyback target frames** at motion=1. Same scene SHA, GPU, accepted backend-specific PFM SHA, 32,768 hash slots/4,489,304 B scratch, owner/ray/cascade counts and GPU timestamp closure on **all 360 measured frames**. No source and target warmup image readback required, but their per-frame GPU/counter internal safety guards must pass.

- **One full accepted N004 CPU-vs-GPU hit diagnostic only:** run on **first measured canonical frame** (index 0), verify `substantive_mismatches == 0`; other 11 measured frames have `hit_diagnostics=null` (explicitly **not executed**, never silently pass 0). Source hit diagnostic also `null`. Source and target warmups skip N004 and check shader-visible counts/storage/overflow; the already accepted P1i/P1j-A/P1j-B ten-case study independently validated original+canonical hit checks and bit-identical images on all 10 cases. Thus A1b validates steady-state per-frame performance without repeating a costly CPU *oracle*, at the documented cost of **not freshly CPU-validating every warmup or measured ray**.
- One real per-process CPU/GPU hit cross-check, zero substantive mismatches, plus **every measured PFM SHA exact to backend-specific accepted output**, full visible owner/weights/hash/rays, storage and hit-stage shader internal correctness, stage-level GPU timestamps and no repeated traversal maintenance. Sampled diagnostic is **not included** in GPU timestamps and never counted as renderer GPU processing speed.
- Require explicit `p1l_stage_fast=true`, `p1l_stage_probe=false`, `p1l_hit_diagnostic_frame=0`, no zero-copy/canonical alternate schedule/extra mode or topology, exact 32+8+12 schedule. Keep original P1l-A1 mode untouched as a negative retained performance-cost study; do not mix old A1 and A1b frames.
- **Fail-fast and timeout:** each subprocess has a maximum wall time (default e.g. 20 min, may be set lower for local constraints); upon timeout mark `invalid-retained`, preserve partial output, never count a timed-out process in the results. The timeout must not silently kill a still-running orphan GPU child.
- All ten cells must pass full 3-run replication. Aggregate identical per-scene median/p10/p90 and all process medians; backend ratios descriptive/unpaired. If a single case exceeds timeout, investigate with a **CPU profiler stack** instead of blind longer waiting.
- Do not mutate historical N004/N005 implementation, accepted old runs, renderer semantics, image bytes, or GitHub Actions. **No GPU results for A1b yet.**
