# S0 — 土台

- 期間：2026-11-13
- 問い：ツールチェーン、参照レンダラ、テストシーンを決める。Sponza の G-buffer を 1080p で描き、
  GPU タイムスタンプをネイティブとブラウザの両方で取れるか。先行研究の本文が仮説を変えるか。
- 打ち切り基準：なし（土台。出口は [roadmap](../roadmap.md) の S0）。

## やったこと

- **先行研究**：Split RC（arXiv 2607.20384 v2、PDF 本文）、Chalmers 修士論文 2 本（Gavras は本文、
  Abou Dan & Jensen は本文非公開で要旨のみ）、Godot HDDAGI（PR とシェーダ）、three-rc（ソース）、
  gpuweb ray query（提案文書）を確認し、[architecture](../../docs/architecture.md) を改訂した。
  - H1：スクリーン配置プローブをやめ、可視画素近傍のワールド格子プローブ（Split RC の Sparse RC）にした。
    履歴なしのスクリーン配置は、3 実装すべてでカメラ移動時のちらつきが最大の問題になっている。
  - 区間長はカスケードごとに ×4（先行 3 件が一致）。H3 の「層を区間長に揃える」は ×2 を暗黙に
    仮定していたので、層とカスケードの対応を S2 の決定事項にした。
  - ボクセルトレーサのブリック内部は HDDAGI（占有ビットマスクの 3 段構成、分岐しない階層 DDA）を手本にする。
  - 予算のリスク：Split RC は HWRT ありの RTX 3080 Laptop で Sponza 8.6 ms（トレース以外が 7.3 ms）。
- **ツールチェーン**：TypeScript ＋ WebGPU（WGSL）。ネイティブは npm の `webgpu@0.6.2`（Dawn、Vulkan）、
  ブラウザは Chrome 系。ネイティブとブラウザが同じ Dawn と同じコードになることを重視した（ユーザー判断）。
  比べた案：Rust ＋ wgpu（同じ WGSL から WebGL2 へ変換できるが、ネイティブとブラウザで実装が別）、
  C++ ＋ Dawn（ビルドが重い）。WebGL2 ティアは GLSL を別に書く。
- **テストシーン**：Khronos glTF-Sample-Assets の Sponza（26.2 万三角形、103 プリミティブ、25 材質、
  1024² テクスチャ 68 枚）。Vulkan-Samples-Assets 版はテクスチャが ASTC で、RADV
  （`textureCompressionASTC_LDR = false`）とデスクトップ WebGPU では読めないので替えた。
  広さ・密度を変える合成ワールドの生成器は作っていない（S2 で必要になったときに作る）。
- **参照レンダラ**：未決。S0 の出口には不要なので、S1 の品質計測の前に決める
  （候補は [evaluation](../../docs/evaluation.md#参照レンダラ)）。
- **G-buffer**（`src/core/`）：albedo＋metallic（rgba8unorm-srgb）、法線＋roughness（rgba16float、
  法線マップ適用済みのワールド法線）、深度（depth32float、逆 Z・遠方面なし）。材質ごとのテクスチャは
  役割別の 2D 配列 3 本にまとめ、1 つのバインドグループで全材質を引ける（後の GI パスでヒット点の
  材質を読むため）。アルファマスクと両面材質に対応。103 ドローコール。
- **計測**：G-buffer パスの `timestampWrites`。ウォームアップ 120 フレーム、計測 600 フレーム、
  同時に 2 フレームまで投入。GPU のクロックは固定しない。カメラは固定（atrium の端から長軸方向）。

## 結果（探索値）

画像（albedo、法線、深度）を目で見て、テクスチャ、アルファマスクの植物、法線マップ、深度が
正しいことを確認した。ブラウザ版の出力は、SwiftShader で描いたものがネイティブ版とほぼ一致する
（間引いた画素の平均差 albedo 0.47/255、法線 0.56/255）。

| 実行 | 実装 | 中央値 | p5 | p95 | 最大 | タイムスタンプの最小刻み |
|---|---|---|---|---|---|---|
| ネイティブ 1 | Dawn / Vulkan（RADV、Mesa 26.1.2） | 0.634 ms | 0.594 | 0.714 | 1.204 | 7.7 µs |
| ネイティブ 2 | 同上 | 0.634 ms | 0.605 | 1.053 | 1.286 | 6.3 µs |
| ネイティブ 3 | 同上 | 0.640 ms | 0.628 | 0.691 | 1.282 | 7.7 µs |
| ブラウザ | 未計測（下記） | | | | | |

ブラウザでの GPU 時間は取れていない。この作業機ではブラウザの WebGPU が SwiftShader（CPU）に落ちる。
nix 版 Brave は `libvulkan.so.1` を読めず、Claude Code から起動したものは ANGLE / EGL の初期化に失敗する。
ブラウザ版のコードは SwiftShader で最後まで動き、画像がネイティブと一致することだけを確認した
（SwiftShader での時間は 1 フレーム約 200 ms で、GPU の数値ではないので捨てた）。

- 「最小刻み」は異なる生タイムスタンプ間の差の最小値で、量子化（100 µs）されていないことの確認に使った。
- 60 フレームだけの試走では中央値 1.03 ms だった。クロックの立ち上がりが効くので、ウォームアップは省けない。
- 確保した GPU メモリ（作成したリソースの合計で、実測のピークではない）：シーン 415 MB
  （ほぼテクスチャ。未圧縮 RGBA8 とミップ）、G-buffer 33 MB。
- 読み込み 5.7〜6.6 s（Node での JPEG デコードが大半）。
- 数値の要約：[s0-foundation/](s0-foundation/)。

## 判断

S0 の出口のうちネイティブ側は満たし、ブラウザ側は満たしていない。ユーザー判断で、ある程度実証
できるまではネイティブだけで進める（[決定](../decisions/2026-11-13-s0-toolchain-native-first.md)）。
G-buffer は 1080p で約 0.63 ms。ツールチェーンは TypeScript ＋ Dawn で進める。
