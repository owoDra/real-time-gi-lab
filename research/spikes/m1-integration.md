# M1 — 統合（DDGI 系の比較相手、局所更新、完全動的な Sponza）

- 期間：2026-11-14〜
- 問い：C2 の条件（[C1 の決定](../decisions/2026-11-14-c1-checkpoint.md)）を判定する材料。同じ 4 ms で DDGI 系に対して
  品質（参照に対する誤差、移動時ちらつき、リーク）か対応範囲（R1 の応答、履歴なしでの破綻のなさ）で優位があるか。
  完全動的な Sponza で、局所更新を入れて GI が 4 ms に入るか。
- 止める条件（ユーザー指示）：同じ 4 ms で DDGI 系に勝てないと分かった時点で止めて報告する（C2 の前倒し）。

## 1. DDGI 系の比較相手

### やったこと

- **実装**（[ddgi.ts](../../src/core/ddgi.ts)）。RTXGI の DDGI に寄せた：ワールド固定の一様格子、プローブごとに R 本の
  レイ（球面フィボナッチ、フレームごとに全プローブ共通の乱数回転）、放射照度 6×6 と距離モーメント 14×14 の八面体
  （境界 1 texel）、ヒステリシス 0.97、RTXGI の適応則（暗くなる変化でヒステリシスを下げ、明るくなる変化は 1/4 に抑える。
  ガンマ 5 で符号化した値に対して）、チェビシェフ可視性（3 乗、0.2 未満は押しつぶす）、裏面の重み、面のバイアス
  （0.2 n + 0.8 v）× 0.75 × 間隔 × 0.3。トレースと時間混合は 1 プローブ 1 ワークグループで融合した。
- **RC と揃えたところ**：レイは S2 のボクセルの区間トレーサでトレースする。1 本のレイを区間 [b_k, b_k+1] × 0.4 m
  （b_k = (4^k − 1)/3）に分け、区間 k は層 k（0.1 m × 2^k）で引く。RC のカスケードの層の対応（円錐の太さ）と同じ。
  ヒット点の放射は同じ 1 バウンスの太陽（`shadeHit`）、抜けたら空。プローブからの多重バウンスは入れない（参照と RC にもない）。
- **RTXGI と違うところ**：プローブの押し出しと活性判定をボクセルの占有から決める（視点によらず、毎フレーム決め直すので
  動く物体に追従する）。押し出しは占有されたボクセル（間隔 / 4）にいるプローブを 26 方向 × 0.15 / 0.3 / 0.45 間隔の
  最初の空きへ（`rg`：S2 の vrel と同じく近傍の占有の重心から離れる向きを先に試し、曖昧なら上向きから）。活性は
  ±1 間隔の箱に占有ボクセル（間隔 / 2）があること。非活性のプローブはトレースせず、活性に戻ったら履歴なしから始める。
  体積はシーンの外接箱に固定（スクロールなし）。
- **掃引**（[m1_sweep.sh](../../scripts/m1_sweep.sh)、[m1_summary.py](../../scripts/m1_summary.py)）：間隔 0.5〜2 m、
  レイ 64〜256 本、更新の間引き（1/2〜1/8 のプローブを毎フレーム）、ヒステリシス、時間混合の符号化（ガンマ 5 / 線形 `g1`）、
  視点バイアス、押し出し。RC は rc2（方向の伸びを c2 で止める）と rc2-vrel を P = 32 / 48 / 64 で。計測は S2・S3 と同じ
  （1080p、ウォームアップ 60 ＋ 240 フレーム、静止と移動）。参照は S2 で描いた Mitsuba（太陽だけ / 空あり、512 spp × 2）。
  リークは S2 の閉じた部屋（厚み 0.02 / 0.1 m）。GPU 時間の計測中に参照は描いていない。

### 結果（探索値、1920×1080、Radeon 8060S、Dawn / Vulkan、Sponza、各 1 回の中央値。実行ごとに 20% 程度ずれる）

- **RTXGI 既定のガンマ 5 の時間混合は暗い側に偏る**（符号化した値の平均を戻すので Jensen の不等式で下がる。レイ 128 本の
  ノイズが大きい空の寄与で特に効き、空ありの偏り −31%）。線形（`g1`）にすると偏りが −17〜−20% → 太陽だけで −4% になり、
  誤差は 0.39 / 0.45 → 0.36 / 0.38。代わりに静止時のちらつきが 0.7 → 1.9% に増える。比較相手はこちらを使う。

  ボクセル（13 MiB）と合わせると予算 128 MB に入らない。
- DDGI の時間はレイのトレースが支配的（1 m 間隔、9,117 プローブ：128 本で 4.9 ms、64 本で 2.7 ms）。ボクセルの区間トレーサで
  全長のレイ（最大 136 m）を引くため、1 本あたり RC の区間の 4〜5 倍かかる。
- 画像：DDGI は滑らかで、柱・アーチの明暗は参照と同じ位置。吊り布の下面と奥のアーチは参照より暗い。空ありでは中庭の床が
  参照より暗い（押し出しを変えても同じ）。リーク部屋では DDGI は辺と隅だけが光り内部は黒、RC（vrel）は床のまだらと壁の
  グラデーション。移動時のちらつきは両方とも左右のカーテン（暗い面）に集中し、DDGI は時間方向の斑点、RC は塊。

### 判断（手順 1）

- **勝ち負けは field に何 ms 残るかで決まる。** ボクセルを毎フレーム全部作り直す今の形（1.9〜2.1 ms）では field に約 2 ms
  しか残らず、そこで RC が入るのは vrel なしの rc2 P48 だけ。その点では **DDGI が誤差（0.36 / 0.38 対 0.41 / 0.41）、
  移動時ちらつき（18.7 対 32.2%）、リーク（0.87 / 0.41 対 1.69 / 1.16%）で上**で、RC が上なのは静止時ちらつき（0 対 2.6%）
  だけ。
- 局所更新で作り直しが小さくなり field に 3.3〜3.9 ms 残れば、RC は vrel を使えて、**移動時ちらつき（14〜16 対 17〜18%）と
  静止時ちらつき（0 対 0.7〜1.9%）で上、誤差は DDGI が上か同等（P48 で 0.40 / 0.41 対 0.37 / 0.37、P32 で同等）、
  リークは同等**。
- したがって「同じ 4 ms で勝てない」とはまだ言えない。判定は局所更新の費用（手順 2）を待つ。止めずに手順 2 へ進む。
- 対応範囲（R1 の応答、履歴なしでの破綻のなさ）は DDGI の弱点として予想されるが未測定（手順 3）。

## 2. 局所更新と H4

### やったこと

- **局所更新**（[voxel.ts](../../src/core/voxel.ts)、`--vox '{"anchor":"scene","local":true}'`）。静的な三角形で全層を一度だけ作り、
  ポインタ格子と代表三角形を残す。毎フレーム、前フレームの複製ブリックのポインタを静的なものへ戻し、動的三角形（三角形表の末尾）
  が重なるブリックだけを静的ブリックから複製（占有と代表三角形）して、動的三角形だけをボクセル化し、複製したブリックだけ属性を
  割り当てて解決する。代表三角形の規則（番号最大）と動的三角形が末尾にあることで、全再構築と同じ結果になる。
  クリップマップの窓はシーンの中心に固定した（Sponza は層 0 の窓 51 m に入る。窓のスクロールの更新は M2 のストリーミング）。
- **完全動的な Sponza**（[scenes.ts](../../src/core/scenes.ts) の `sponza-dyn`）：S3 のトゥーン物体 3 つが動き（球が横へ ±1.6 m、
  リングが鉛直軸まわりに回転、人形が前後に ±1.5 m。周期 160〜320 フレーム）、太陽が中庭の長軸方向に約 ±20° 振れる（周期 400）。
  頂点は CPU で変換して書き込む。`sponza-dynobj` は同じ物体を写実材質にしたもの。
- **H4**：局所更新の上で、層 L の動的三角形を 2^L フレームごとにだけボクセル化した場合の費用（`h4: cost`）と、層 L を最後に当番
  だったフレームの姿勢でボクセル化した場合の画像（`h4: stale`。1/2^L 更新の内容を再現する）を測った。

### 結果（探索値、動的 Sponza、静止カメラ、RC rc2-vrel P48、太陽だけ）

- **一致**：姿勢を固定した場合も、物体と太陽を 60 フレーム動かした後も、局所更新と全再構築（同じ固定窓）の放射照度は RC・DDGI
  ともビット単位で同じ（差のある画素 0）。
- **費用**：ボクセルの更新は全再構築 2.3〜2.6 ms（固定窓。カメラ中心の窓では 1.9〜2.1 ms）→ 局所更新 0.12〜0.16 ms。静的な部分の
  一度きりの構築は 2.3 ms。動的 Sponza で RC rc2-vrel P48 の GI 全体は 3.3〜3.5 ms（局所更新込み）で、4 ms に入った。
  常駐メモリは静的なポインタ格子の写し（5 MiB）と変更フラグ（5 MiB）、代表三角形（19 MiB、全再構築では一時領域）が増える。

| 局所更新の内容 | 1 フレームの平均 ms |
|---|---|
| 動的三角形なし（固定費：戻す、数え直し、間接ディスパッチ） | 0.036 |
| 層 0 だけ | 0.080 |
| 全層を毎フレーム | 0.124 |
| 層 L を 2^L フレームごと（H4） | 0.091 |

- **H4 の費用**：固定費を除くと、全層を毎フレーム更新しても層 0 の 2.0 倍、1/2^L なら 1.25 倍（固定費込みで 1.55 倍 / 1.14 倍）。
  「総更新コストは最下層の約 2 倍に収まる」は、更新頻度を下げなくても成り立つ。動く物体が小さい（2 万三角形）ので、頻度を下げて
  減らせるのは 0.03 ms。
- **H4 の画像**：1/2^L 更新（層 4 は最大 15 フレーム古い）と毎フレーム更新の差は、最後のフレームで平均 3.8%（参照に対する誤差
  37〜40% の一桁下）。静止カメラでの動的ちらつき（物体と太陽が動くので本物の変化を含む）は 19.8 → 17.3% と下がる。
  要約：[h4/](m1-integration/h4/)。

### 判断（手順 2）

- **局所更新で作り直しは 2 ms → 0.1 ms になり、field に約 3.85 ms 残る。** RC は vrel を P48 で使える（動的 Sponza で GI 3.3〜3.5 ms）。
- **H4 は費用の面では支持**（1/2^L で 1.25 倍、毎フレームでも 2 倍）。ただしこの規模では差が 0.03 ms しかなく、意味を持つのは
  動く三角形が多いとき（M2）。品質の面の影響（平均 3.8%）は小さい。既定は全層を毎フレームのままにする。
- 手順 1 の判定は field 3.3〜3.9 ms の側になる：RC（vrel）はちらつきで上、DDGI は誤差で上か同等、リークは同等。
