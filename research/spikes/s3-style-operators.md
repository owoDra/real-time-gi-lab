# S3 — スタイル演算子

- 期間：2026-11-14
- 問い：H5（スタイルを輸送の両端の演算子として定義すれば、輸送を共有したまま写実と非写実を混在でき、写実部分の正しさも
  保てるか）。具体的には、写実部分の誤差がトゥーン物体の有無で変わらないか（放出側プロキシ参照との比較）、場から取り出した
  支配方向をランプに通してもちらつかないか。
- 打ち切り基準（[roadmap](../roadmap.md)）：場から取り出した支配方向が不安定で、ランプを通すとちらつく。→ 場の角度表現を見直す。

## やったこと

- **演算子**（[style.ts](../../src/core/style.ts)）。輸送（ボクセル、カスケード、マージ）は線形のまま共有し、トゥーン材質
  （材質フラグ 4）にだけ両端で作用させる。
  - 放出側：太陽の項を帯に量子化し、albedo の彩度を上げる。`L = sat(albedo) / π · E_sun · ramp(n·l · V)`、ramp は 0 / 0.5 / 1
    （閾値 0.05、0.3）、彩度 1.6 倍。同じ関数で、見えている画素（直接光パス）と区間トレーサのヒット（ボクセルの albedo.a、三角形の
    材質）を塗る。場はカメラが見るのと同じ放射輝度を受け取る。
  - 受光側：c0 の照度 SH の L0 / L1 を 8 プローブで補間し、環境色（L0）、支配方向（L1 の輝度の勾配）、方向色（L1 を支配方向へ
    射影）を取り出す。支配方向を仮想のキーライトとして 2 段のランプに通す：`E = amb − dir + 2·dir·step(n·d)`。写実の画素は
    従来の SH の照度のまま。
- **シーン**（[scenes.ts](../../src/core/scenes.ts)）：Sponza の日なたの床に、移動カメラの経路に沿ってトゥーンの物体を 3 つ
  置いた（橙の球 r = 0.7 m、カメラに向いた青のリング R = 0.7 m、緑のカプセルの人形、計 2 万三角形）。`sponza-objects` は同じ
  物体を写実材質にしたもの（スタイルの効果と物体の形の効果を分けるため）。
- **参照**：Mitsuba の積分器で、トゥーン材質へのヒットは放出側演算子の値を返す（放出側プロキシ）。トゥーン、写実物体、物体なし
  （S2 の参照）を各 512 spp × 2 本。
- **比較**（[compare_style.ts](../../src/native/compare_style.ts)）：写実の画素について、物体なしのシーンと物体ありのシーンで
  それぞれ参照との誤差を出す。全体と、物体が効く領域（2 つの参照が 10% 以上違う 8×8 ブロック）。その領域で、物体の効果
  （あり − なし）をどれだけ再現したかも出す。
- **ちらつき**（[post.ts](../../src/core/post.ts)）：トゥーンの画素を別に数える。輝度の帯（細 1/4 段、粗 1 段）、受光ランプの帯の
  切り替わり（方向成分が環境の 10% 以上ある画素だけ）、対照として固定方向に対するランプの帯の切り替わり（再投影と法線マップだけで
  出る分）。計測の条件は S1・S2 と同じ（1080p、60＋240 フレーム、静止と移動）。

## 結果（探索値、1920×1080、Radeon 8060S、Dawn / Vulkan、ワールド格子 P=32、ボクセル、方向の伸びは c2 で止める `rc2`）

- 「物体が効く領域」は 4990 ブロック（写実の画素の 65%）。トゥーンの放出は明るく（帯の中で n·l によらず平ら）、物体のまわりの
  写実部分の照度は参照で平均 +42%（全体で +22%）上がる。写実の物体の効果は参照のノイズと同程度に小さい。
- 参照自身のノイズ（独立な 2 本の差）は S2 と同じく画素あたり 17%。比較は 2 本の平均。
- 要約：[s3-style-operators/](s3-style-operators/)（`reference/` に比較、他はちらつきと時間）。

### 時間

演算子の追加費用は測れる大きさではない（直接光 0.20 ms で変わらず、gather は vrel で 1.15〜1.31 ms、実行ごとに 20% 程度ずれる）。
GI 全体はトゥーンの物体ありで vrel 5.1〜5.8 ms、G-buffer 4.1〜4.4 ms（物体なしと同じ）。

### 画像で確かめたこと

- 放出側：橙の球の照り返しが右の柱とカーテンに、緑が床に乗る。参照と同じ位置と色。三角形での効果の画像（あり − なし）は
  参照とほぼ同じ形（床の照り返しと、物体が遮る天井側の暗化）。ボクセルでは暗化がほとんど出ず、照り返しが広く強い。
- 受光側：2 段の帯が出る。光は日なたの床から来るので、球の下半分が明るい帯。ただし帯の境界の形は場の粗さに従い、カプセルでは
  不規則な塊になる。帯は移動しても動かない（ちらつきの画像で、トゥーン物体の変化は境界の細い線だけ）。
- vrel では、近くの厚い物体（リング）に、全プローブが遮られた黒いギザギザの領域が出る（S2 の黒い斑点と同じ原因）。
  G-buffer の押し出しでは出ないが、球の赤道に色のついた帯（SH のリンギング）と上半分の暗さが出る。

### 途中で見つけたこと

- 手続きメッシュの巻き順が外から見て時計回りだと、両面材質でも G-buffer が法線を内向きに反転させ、物体が真っ黒になる。
  三角形ごとに幾何法線を頂点法線に揃えて直した（リングが黒かった原因）。
- 物体の中に残るプローブ（上のカスケードほど多い）を「自分の区間でほぼ全方向が当たる」で見分けて外す案は、画像も誤差も
  ほとんど変わらず捨てた。

## 判断

- **打ち切り基準には当たらない。** 支配方向は安定している：ランプの帯の切り替わりは移動時 0.17%（対照 0.11%）で、トゥーンの画素の
  細帯ちらつきはランプを通すほうが低い（2.9% 対 3.3%。空あり 2.6% 対 2.9%）。L1 を 8 プローブで線形に補間してから方向を取る
  ので、方向は場と同じだけ滑らか。場の角度表現（c0 の L2 SH）を変える必要はない。
- **H5 は、正確な可視性のもとでは支持する。** 三角形でトレースすると、トゥーンの効果の 95% を再現し、写実部分の偏りは物体なしと
  同じ（−13% → −12%）。輸送を共有して両端で演算子をかける形は成り立つ。放出側演算子を切ると効果の 17% しか出ず偏りが −29% に
  なるので、演算子が実際に場を通って届いている。
- **ボクセルでは、写実部分の誤差がトゥーン物体の有無で変わる**（偏り −21% → −1%、効果を 1.7 倍に過大）。ただしトゥーン固有では
  ない：ランバートの放出（`noemit`）でも物体の効果は三角形の 1.5〜2 倍、写実の物体でも偏りが 4〜5 ポイント動く（三角形は 1）。
  ボクセルは物体からの照り返しを過大に、物体による遮りを過小に見積もり、トゥーンの放出は明るいのでそれが大きく出る。層を 1 段
  細かくすると 1.45 倍に下がるので、粗い層で物体が膨らむことが一因。残りは、帯の段差がボクセルの法線と可視性の近似の誤差を
  増幅すること（閾値付近の n·l）と考えるが、切り分けていない。
- **写実部分の移動時ちらつきは物体があると増える**（vrel 14.1% → 18.0%、G-buffer 29.7% → 40.6%）が、写実の物体でも同じだけ
  増える（19.8%、39.8%）。スタイルではなく、厚い物体のまわりのプローブ配置による。
- 受光側の帯の形は場の解像度（c0 が画面上 32 画素）で決まり、トゥーンの意図した形（物体の形に沿う境界）にはならない。安定性の
  問題ではなく見た目の問題で、C1 では課題として扱う。

## 次

- C1 に進む（S1〜S3 を並べて、継続・方向転換・中止を決める）。
- ボクセルの物体の見積もり（照り返しの過大、遮りの過小）：粗い層の被覆率（部分透過）、方向別不透明度。トゥーン物体があると
  誤差に直結する。
- 厚い物体のまわりのプローブ：vrel の黒い領域、物体の中に残る上のカスケードのプローブ、写実部分の移動時ちらつきの増加。
  面の表裏を持つ占有で物体の内外を決める案（S2 の次と同じ）。
- 受光側の帯の形：c0 より細かい情報（画面空間の遮蔽や、物体ごとの方向）を足すか。
