## S2 の結果（[記録](spikes/s2-voxel-stratabrick.md)、探索値）

- 区間を多層ボクセル（v0 = 0.1 m、5 層、カメラ相対クリップマップ）でトレースする。全層を毎フレーム三角形から
  作り直して Sponza で 1.89 ms、常駐 12.8 MiB。打ち切り基準には当たらない（境界）。三角形 9〜10 倍で 3.6〜4.2 ms。
- 誤差（同じプローブ・区間を三角形 BVH でトレースした場合との差）：ボクセル −8〜−16%（遮蔽の過大）、
  深度バッファだけ（S1）は空ありで +1827%、太陽だけで −45%。リークは三角形より少ない（厚み 2 cm の壁でも）。
- 太陽だけの移動時ちらつき：深度バッファ 42% → ボクセル 29%（三角形でも 29%）。残りの主因だった視点に依存する
  プローブの押し出しを、ボクセルの占有から決める方式（`vrel`。壁の外に残るプローブはボクセルの可視性判定で外す）に
  替えると 14.1% になり、押し出しを止めた場合（16.2%）と同じ水準に下がった。参照に対する偏りは −22% → −17%、
  リークは増えない。代わりに GI が約 1.1 ms 増え（5.4〜5.6 ms）、全部のプローブが遮られる画素が黒くなる。
- 決めたこと：層はカスケードごとに 1 層、近距離もボクセル、方向の伸びは c2 で止める（GI 4.4〜4.7 ms、うち作り直し
  1.8 ms）。H4（層ごとの更新頻度）は未測定。
- 参照レンダラ（Mitsuba 3）との比較を始めた。参照に対する偏りは、太陽だけで三角形 −15%、ボクセル −22%、
  深度バッファ −53%（空ありで +1698%）。正確な可視性でも残る偏りは RC 自身のもの。

## S3 の結果（[記録](spikes/s3-style-operators.md)、探索値）

- Sponza の日なたにトゥーンの物体を 3 つ置き、放出側（太陽の項を帯に量子化、彩度を上げる）と受光側（c0 の SH の L1 から取った
  支配方向を 2 段のランプに通す）の演算子を実装した。輸送は共有のまま。参照は Mitsuba の放出側プロキシ。
- 打ち切り基準には当たらない：支配方向は安定。移動時のトゥーンの画素の細帯ちらつきはランプで 2.9%（物理のまま 3.3%）、ランプの帯の
  切り替わりは 0.17%（対照 0.11%）。演算子の費用は測れない大きさ。
- H5：正確な可視性（三角形）ではトゥーンの効果の 95% を再現し、写実部分の偏りは物体なしと同じ（−13% → −12%）。ボクセルでは
  物体の効果を 1.7 倍に過大に見積もり、偏りが −21% → −1% に動く。ランバートの物体でも 1.5〜2 倍なのでボクセル側の問題
  （粗い層の膨らみなど）。
- 写実部分の移動時ちらつきは物体があると 14% → 18%（vrel）に増えるが、写実の物体でも同じ（20%）。厚い物体のまわりのプローブ配置が
  原因。vrel は近くの厚い物体に黒い領域を出す。受光側の帯の形は場の解像度に従い、意図した形にならない。

## M1 の結果（[記録](spikes/m1-integration.md)、探索値）

- DDGI 系の比較相手（[ddgi.ts](../src/core/ddgi.ts)）：RTXGI に寄せた一様格子のプローブを同じボクセルの区間トレーサで引く。
  RTXGI 既定のガンマ 5 の時間混合は暗い側に偏る（空ありで −31%）ので、主な比較には線形の混合を使った。
- 局所更新（動的三角形が触るブリックだけ静的な写しから作り直す）は全再構築とビット単位で一致し、ボクセルの更新は 2 ms → 0.12 ms。
  H4 は費用の面で支持（1/2^L 更新で層 0 の 1.25 倍、毎フレームでも 2 倍）。この規模では差は 0.03 ms。
- 完全動的な Sponza（`sponza-dyn`：物体 3 つと太陽が動く）で RC rc2-vrel P48 の GI は 3.4〜3.5 ms（4 ms に入る）。
- GI 約 3.4 ms どうしで、**RC が上なのは R1（光源切替に 1 フレームで応答、動きの途中でも遅れなし）と静的なシーンでの時間安定性
  （静止時ちらつき 0）。DDGI が上なのは静的な参照誤差（0.37 対 0.40）と、動的なシーンでのフレーム間の安定性**（ちらつき 静止カメラ
  1.3〜4.8 対 19.6%、移動カメラ 15.8〜18.6 対 32.9%、トゥーンのランプの帯の切替 0.75〜1.2 対 3.4%、対照 0.88%）。リークは同等。
  DDGI は応答（11〜161 フレーム）・ちらつき・偏りを同時には満たせない。履歴なしでは 2〜4 フレームで収束値近くに届く。
- RC の動的なちらつきは vrel が原因ではない（押し出しなしでも同じ）。物体や太陽が動くと場が広い範囲で離散的に跳ぶ。
  R4 は完全動的な条件では今の形では満たせていない。

### archive-local の扱い

このリポジトリは **public** である。アーカイブにはローカルの絶対パスが大量に含まれ、
Python 仮想環境のソースも混ざっているので、**このまま GitHub に上げない**。退避するなら
非公開のストレージに置く。展開は
`zstd -dc --long=27 program-1-text-evidence.tar.zst | tar -xf -`、チェックサムは
`archive-local/SHA256SUMS`。
