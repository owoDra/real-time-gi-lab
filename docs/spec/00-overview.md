# 概要 — 目的、必須要件、止め方

Program 2 は 2026-11-13 に始めた。Program 1（2026-09-28〜2026-11-13）の記録はタグ `archive/program-1` にあり、
持ち越す知見は [reference/program-1/findings.md](../reference/program-1/findings.md) にある。

## 目的

次の 3 つを同時に満たすリアルタイム・グローバルイルミネーション（GI）を作る。

1. **完全動的なワールドで、高速・軽量・高品質に動く。** ジオメトリ、光源、カメラ、トポロジのすべてが毎フレーム
   変わってよい。建物そのもの（動かない物として置いた形状）が毎フレーム変わる場合まで含む（2026-11-14、ユーザー）。
   事前計算やベイクに依存しない。
2. **フォトリアルとノンフォトリアルを同じ空間で混在させられる。** トゥーンのキャラが写実的な部屋に立ち、互いに
   照り返しを与え合える。
3. **WebGPU で動く。** WebGL2 は機能を絞った縮退ティアとして、可能なら対応する。

## 必須要件

| ID | 要件 |
|---|---|
| R1 | 完全動的：履歴なしでも破綻しない。光源切替への応答は数フレーム以内（数フレームの短い履歴は使ってよい）。登録した動的物体だけでなく、建物を含む全形状が同じフレームに変わっても、予算に入る |
| R2 | 大規模ワールド：GI の時間とメモリがワールドの広さにほぼ依存しない |
| R3 | 高密度ワールド：GI の時間が三角形数ではなく表面積と解像度で決まる |
| R4 | 無ノイズ・時間安定：閾値処理（トゥーンのランプ）を通してもちらつかない。静止したシーンでも、物体や光源が動くシーンでも |
| R5 | スタイル混在：スタイルの異なる物体が同じ放射輝度場を共有する |
| R6 | WebGPU のコア機能だけで動く：ハードウェアレイトレーシングを前提にしない |

望ましいもの（必須ではない）：WebGL2 ティア、既存手法を越える新規の発想。

## 「高品質」の定義

パストレーシングと同等、という意味ではない。次を指す。

- 時間的に安定している（静止時にちらつかず、動かしても尾を引かず、跳ばない）。
- 光が壁を抜けない。
- 写実的な部分の誤差が測定されていて、同じコストの既存手法より小さい。

## 対象外（v1）

- パストレーシング同等の画質。
- 鏡面に近い光沢反射。拡散と粗いスペキュラまでを扱う。
- ニューラル手法、シーンごとの学習。
- 複数デバイスでの検証を完了条件にすること。開発機（AMD Radeon 8060S）での結果はその機種の結果として述べ、
  一般化しない。

## 成功条件

評価は「同じ品質での速さ」ではなく「**同じコストでの品質**」で行う（[10-evaluation.md](10-evaluation.md)）。

成功とは、固定予算の中で R1〜R6 を満たし、Web で実現可能な既存手法（SSGI、DDGI 系、ボクセルコーントレーシング）に
対して品質または対応範囲で優位を示すこと。

| 2026-11-14 | 同じ 4 ms での DDGI 系との比べ（Phase 16）：**優位は割れている。RC を続け、動的な安定性の列を閉じ、大規模・高密度の列へ進む。最初は動く物体 64 個を 4 ms に入れる。** P1 は `p1` のまま（物体 64 個の後に既定入りを測る）。多重バウンスは P1 の扱いを決めた後に RC と DDGI の両方へ入れる。理由：RC は応答と遅れのなさ（R1）で上、DDGI 系は動く場面の安定と静的な誤差で上で、DDGI 系は遅れなしと安定を同時に満たせない。動く場面の跳びの残りは P1 の読む層の粗さで決まり大きく下がる見込みが薄く、物体 24 個で RC も DDGI も 4 ms を超えている（[40-dynamic-stability.md](40-dynamic-stability.md)、[50-roadmap.md](50-roadmap.md)） |

## 止め方

Program 1 には停止規則がなく、使い捨ての評価データを消費しながら候補を作り直すループになった。次を守る。

- 各フェーズは完了条件を先に書く。方向を変えうるフェーズは、止める条件も先に書く。
- **継続・方向転換・中止**は、方向の確認（review）のフェーズで AI が理由をつけて決め、ユーザーに報告する
  （2026-11-14 から。ユーザーが変えたいと言えば従う）。中止は正当な結果である。
- 決めたことは、この `docs/spec/` に日付つきで書く。
