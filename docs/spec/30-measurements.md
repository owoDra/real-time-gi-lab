# 測った結果

**すべて探索値**（事前登録なし、各 1〜3 回）。条件は断りがなければ 1920×1080、AMD Radeon 8060S、Dawn / Vulkan
（RADV）、ネイティブ、ウォームアップ 60 ＋ 240 フレーム。GPU 時間は実行ごとに 20% 程度ずれる。開発機 1 台の結果で、
一般化しない。

- 数値の要約（JSON）：[reference/measurements/](../reference/measurements/)。
- 測ったときの記録の全文は、コミット `656e3ed2` の `research/spikes/*.md` にある
  （`git show 656e3ed2:research/spikes/m1-integration.md`）。そこに書いてある原因の推測と方針は、
  [40-dynamic-stability.md](40-dynamic-stability.md) と [50-roadmap.md](50-roadmap.md) が置き換えた。
- ここには測った事実だけを書く。解釈は 20 と 40 に置く。

## 1. 土台（2026-11-13）

- Sponza（26.2 万三角形）の G-buffer 1080p：中央値 0.63 ms（3 回、ウォームアップ 120 ＋ 600 フレーム）。
  60 フレームだけの試走では 1.03 ms（クロックの立ち上がり。ウォームアップは省けない）。
- 確保した GPU メモリ：シーン 415 MB（ほぼテクスチャ）、G-buffer 33 MB。
- **ブラウザでの GPU 時間は未計測。** この作業機ではブラウザの WebGPU が SwiftShader（CPU）に落ちる。ブラウザ版の
  コードが SwiftShader で動き、画像がネイティブとほぼ一致する（平均差 0.5/255）ことだけ確かめ、実行器は削除した
  （戻すときはコミット `876e2321` の `src/web/`、`tools/serve.ts`、`web/`）。

## 6. 局所更新（動的三角形を二値のブリックへ毎フレーム入れ直す方式。P2 で外した）
