# レンダラ — いまの構成（Strata Cascades、仮称）

ここに書くのは**いま実装されている構成**と、それを選んだ根拠である。挙動の正本はコード（`src/core/`）。
数値は [30-measurements.md](30-measurements.md)、動的なシーンでの弱点と対策は
[40-dynamic-stability.md](40-dynamic-stability.md)、先行研究は [reference/prior-work.md](../reference/prior-work.md)。

この構成を土台として続ける（2026-11-15、Phase 26 の比べ直し、AI 決定。[50-roadmap.md](50-roadmap.md)）。

## なぜこの形か

| 目標 | 帰結 |
|---|---|
| WebGPU / WebGL2 | ハードウェアレイトレーシングが使えない。トレースはソフトウェア前提 |
| スタイル混在 | トゥーンのランプは閾値処理で、小さなノイズを帯境界のちらつきに増幅する。「不偏」より「無ノイズ」が要る |
| 完全動的 | 履歴に頼ると遅延とゴーストが出る。毎フレーム決定的に解ける手法が有利 |

この条件から Radiance Cascades（RC）系を選んだ。確率的サンプリングなしで無ノイズ、光源数に依存しない固定コスト。

## 既定の構成

設定名 `world-48-voxel-rc2-vrel`（計測の記録では「RC rc2-vrel P48」）。**建物と物体を含む全形状を毎フレーム作り直す**（2026-11-15、Phase 21 から。
建物そのものが毎フレーム変わってよい）。ボクセルの層 0 は 0.2 m で、窓はカメラに付いて動く。動的物体は動的レイヤ（P2）。
多重バウンスが入っている（2026-11-15、Phase 23。下の「多重バウンス」）。
建物が毎フレーム波打ち、物体 64 個（変形を含む）が動く Sponza で GI 3.67〜3.75 ms（静止カメラ、独立 3 回の中央値の範囲、Phase 24）、移動カメラ 3.37〜3.41 ms。Phase 28 に空いた機械で測り直すと 3.83〜3.88 ms（移動 3.46〜3.51）。
建物の一部が現れて消える場面で 3.64 ms。Phase 29〜31 は機械が空かず、混んだ機械で 3.85〜4.20 ms（Phase 31 の既定は前と同じ費用。[30-measurements.md](30-measurements.md) の 35 節）、空いた機械の値は未計測。確保は作っている途中を含めて 76.8〜77.3 MiB（Phase 31 から 84.3 MiB）（予算 128 MB は作っている途中にも
当てはめる。2026-11-14、ユーザー）。4 ms に入る中で選び直した DDGI 線形（`ddgi-100-128-u8-g1-noadapt`）は同じ場面で 3.1〜3.2 ms・82.5 MiB（[30-measurements.md](30-measurements.md) の 29 節）。
WebGPU の既定の上限で動く（実行器は既定の上限でデバイスを作る。2026-11-14、Phase 15）。

## 放射輝度場（`src/core/rc.ts`）

- **プローブはワールド格子**。可視画素が自分の c0 セルの 8 隅をハッシュに登録し、カスケード i+1 はカスケード i の
  プローブから登録する（三線形の合成に要る点だけ）。c0 間隔は 0.05 m × 2^LOD で、画面上 P 画素以下になる LOD を
  距離から選ぶ。ボクセルを使う RC では c0 間隔を層 0 のボクセル（0.2 m）より細かくしない（Phase 21。細かいプローブはボクセルの
  占有から置き場所が決まらず、近くの吊り布で 8 プローブとも遮られて黒くなった）。プローブの値は「格子点とワールドの状態」だけで決まり、どの画素が登録したかに依らない。
- **カスケード**：5 段。間隔 ×2、区間 s0·[(4^i−1)/3, (4^(i+1)−1)/3]、方向は八面体 (4·2^i)²（c0 は 16 方向）。
  方向の伸びは c2 で止める（`rc2`）。
- **区間は方向ごとに 1 本のレイで決定的に埋める。** 静的な形状に対しては、1 本が 1 つの方向ビン全体を代表し、ヒットは
  二値（当たれば透過 0）。動的物体は、ビンの錐の幅で平均した被覆率と放射で混ぜる（下の「動的レイヤ」）。合成は上の
  カスケードの最大 8 プローブの平均（遮られた親は使わない）。
- **c0 は L2 球面調和の放射照度**にして、画素ごとに 8 プローブを補間する。
- **場の履歴は c0 の短い履歴だけ**（Phase 29）。c0 のプローブの SH を、前のフレームの同じ格子点と LOD のプローブの SH と混ぜる（新しいフレームの重み 0.5。
  切り替えの後、そのフレームを入れて 4 フレームで 90%）。前のフレームに同じ格子点が無ければ（最初のフレーム、LOD の切り替え、新しく登録された点）そのフレームの値。
  c0 のハッシュ（格子点 → プローブ）と SH を 2 枚持ち、フレームごとに入れ替える（`rc.hist`）。上のカスケードは履歴を持たない。
  2 バウンス目以降は跳ね返りボリュームの値で、3 バウンス目から 1 バウンスにつき 1 フレーム遅れる（下の「多重バウンス」）。
  静止したシーンでは収束した後、フレーム間で完全に同じ値になる（静止時のちらつき 0 は履歴を入れても保った）。
- **輸送**：ヒット点の放射は太陽の直接光（`shadeHit`）と、アルベド / π × そこの間接放射照度（多重バウンス）。静的なボクセルのヒットの影は、
  そのボクセルの面の太陽の可視性（下の「ボクセル StrataBrick」の `voxSun`、Phase 29）を読む。三角形のヒットと動的レイヤの点はシャドウマップ（4096²）を
  1 点で引く。最後の区間を抜けたレイは一様な空。

## 動く物体が跳ね返りを受け、遮る（設定のトークン `obj`、2026-11-15、Phase 31。既定ではない）

- 動的レイヤが面積 × アルベド（3 語）も配り、GI の方式ごとの `dynInject`（`DYN_INJECT_WGSL`）が、跳ね返りボリュームの光線とカスケードのトレースの前に、動的レイヤの
  ボクセルごとに、6 面の射影面積で重みを付けた放射照度 × アルベド / π を放射に足す。放射照度は RC では前のフレームの跳ね返りボリューム（`bnRead` と同じ決まり）、
  DDGI 系では前の更新の自分のプローブ（ヒットと同じ読み方）。トゥーンの物体も Lambert で返す（放出側の演算子は太陽の項だけ）。受けた光は 1 フレーム遅れる。
- RC の跳ね返りボリュームの放射照度の光線は、静的なヒットより手前の動的レイヤを 16 本の錐の幅で読む（物体が遮り、照り返す）。DDGI 系の光線は前から読んでいる。
- 費用：建物が波打ち物体 64 個の場面で GI 約 +0.15 ms（splat 0.24 → 0.33 ms、トレースの段 +0.02〜0.05 ms）、DDGI 線形 +0.16〜0.19 ms。混んだ機械で 4.0 ms を超え、
  空いた機械で判定できなかったので既定に入れていない。物体の近くの床は参照の 0.79〜1.12 倍、物体の偏りは姿勢 100 で +0.9%、姿勢 0 で −12.8%（35 節）。

## 多重バウンス（`src/core/bounce.ts`、2026-11-15、Phase 23）

- カメラに付いた粗いプローブの格子（跳ね返りボリューム）：1.2 m 間隔、32×16×32、面の近く（1 セル以内に層 3 の占有があり、自分は層 0 のボクセルの外）の
  プローブだけが働く（Sponza で約 3,500 個）。各プローブは固定の 16 方向（乱数なし）と 6 軸の光線を引き、6 軸の放射照度（ambient cube）と、6 軸それぞれの
  「何もない距離」を持つ。光線のヒットの放射は直接光 ＋ アルベド / π × 前のフレームのボリュームの放射照度なので、ボリュームは全バウンスを持つ。
  プローブは 2 フレームに 1 回ずつ引き（ワールドの位置で交互）、引かないフレームは前の値を写す。
- 引いた後、占有されたボクセルごとに、そのボクセルの表と裏の放射照度を周りの 8 プローブから求めて置く。プローブは、面のその側にあり、読む点が
  プローブから軸ごとに見えている距離の内にあるときだけ使う（壁の裏や横のプローブを使わないため）。読む点は層 0 ではボクセルの中心、粗い層では
  その側へ半ボクセル。読む点を法線方向へ半セルずらす形は、壁と床の境目で床の下へ抜けた（Phase 24）。ヒットがどちらの側を読むかは光線の入った点で決める。RC のヒットはそれを 2 語読むだけ。RC の 2 バウンス目は同じフレームのボリュームで遅れがない。
- 費用：建物が波打ち物体 64 個の場面で GI +0.34 ms（分類 約 0.09、更新 約 0.15、ボクセルごとの値 約 0.1）、確保 +6.5 MiB（ボクセルごとの値 5 MiB）。
- DDGI 系は自分のプローブを、前の更新の状態から gather と同じ重み（チェビシェフを含む）で読み返す。トレースと混合は 2 パスに分けた。
- **プローブの押し出し（`vrel`）**：位置と法線を静的なボクセルの占有から決める（視点に依らない。動的物体は見ない）。ボクセルは表面だけで
  表裏を持たないので、壁の外側の格子点は外側に残る。gather（画素 → c0）と合成（プローブ → 親）で、線分がボクセルに
  遮られるプローブを使わない。8 つとも遮られる画素は黒くなる（漏らさない側に倒した）。押し出しと親の遮り判定は 1 プローブ
  1 ワークグループで、占有の読みをスレッドに並べ、浮動小数の和は直列のときと同じ順で 1 スレッドが取る（並べる前と画像が
  ビット単位で同じ。[30-measurements.md](30-measurements.md) の 17 節）。

## 区間トレーサ

インターフェースは 1 つ：`trace(origin, dir, t0, t1) -> (radiance, transmittance)`。合成側は実体を知らない。

| 実体 | 用途 |
|---|---|
| ボクセル StrataBrick | 既定。全区間 |
| 三角形 BVH（`src/core/bvh.ts`） | ボクセル近似の正解器。CPU で 1 回だけ構築し（Sponza で約 115 ms）、動的なシーンでは動く三角形を毎フレーム CPU で再フィットする（位相は同じ、GPU 時間の外。計測専用） |
| 深度バッファ | 比較用。画面外へ出たレイが空になり、空ありで 18 倍明るい |

## ボクセル StrataBrick（`src/core/voxel.ts`）

- 層 L のボクセルは v0·2^L（**v0 = 0.2 m**、5 層。Phase 21 から。0.1 m では全形状を毎フレーム作ると 4 ms に入らなかった）。8³ ボクセルのブリック（占有ビット 16 語）、層ごとに **32³** の
  ブリックポインタ（密）＋占有ブリックのプール。空ブリックを飛ばす 2 段の DDA。窓は層 0 で 51 m、層 4 で 819 m（Phase 32 で 64³ から縮めた。64³ の層 0 の窓 102 m は
  広いワールドで建物 2 つ半を層 0 で作っていた。Sponza の間接光は 8 ビットの平均で 0.06 段変わった。[30-measurements.md](30-measurements.md) の 36 節）。
- **カスケードごとに 1 層**上げる（c0 のボクセル = 0.25 × c0 プローブ間隔）。レイは太さ 0 の線で、方向ビンの
  断面（c2 で 2〜9 ボクセル幅）より細い。
- 静的な三角形（建物）だけを保守的にボクセル化する（三角形と箱の重なり）。占有は二値。動的三角形はブリックに入れない。
- **全形状を毎フレーム作り直す**（Phase 21 から既定。建物そのものが毎フレーム変わってよい）。クリップマップの窓はカメラに付いて動く。
  変わっていない所を省く経路は無い（毎フレーム建物の全三角形をボクセルにする）。一度だけ作る固定窓（`local`、`anchor: 'scene'`）は消した。
  作成用の一時バッファ（`vox.rep`、`vox.big`）は毎フレーム使うので、確保の合計が作っている途中の最大になる。
- **粗い層は細かい層から作る**（Phase 21）：層 L ≥ 1 のセルのうち層 L−1 の窓に入るものは、8 つの子の占有の論理和で、代表三角形は
  子の代表の最大（三角形から作るときと同じ決まり。アルファマスクだけは最も細かいボクセルで判定する）。三角形からは層 0 と、細かい窓の
  外の粗いセルだけを作る（Sponza は全部が層 0 の窓に入る）。子の 1 語（8×4 ボクセル）の親は 1 つの親ブリックの 1 語に収まるので、
  1 スレッドが 1 語を受け持ち、原子操作は親の語ごとに 1 回。
- 占有ボクセルは**代表三角形 1 個**（重なる三角形のうち番号最大）の albedo（a はトゥーンのフラグ）と法線を持ち、
  ヒット時に演算子を評価する。
- **ボクセルごとの太陽の可視性（`voxSun`、Phase 29）**：占有ボクセルごとに、代表三角形の平面（保存した法線と、中心を三角形へ射影した点からのずれ 1 語）の上の
  2 × 2 点（中心の射影から 2 つの接線方向へ ±1/4 ボクセル、平面から太陽の側へ 1/4 ボクセル ＋ 3 cm 浮かせる。各点はハードウェアの 2 × 2 比較）の平均を、
  影の地図を描いた後に毎フレーム 1 語に書く。RC のカスケード、跳ね返りボリューム、DDGI のボクセルのヒットはそれを読む（共有のトレーサ）。
  動く太陽で影の地図の格子が動くと、1 点の可視性が影の縁で 0 と 1 を行き来していた分を、面の平均に置き換える前置フィルタ。ボクセルごとの語は
  属性 2 ＋ 跳ね返り 4 ＋ 平面 1 ＋ 太陽 1 の 8 語（使用量の表示も跳ね返りの 4 語を数えるように直した）。
- プールは広いワールドの速いカメラ移動と物体 64 個に合わせる（`maxBricks` 4608、`maxVoxels` 524288、動的 `dynBricks` 512。Phase 32。広さ 100 倍を 1 フレーム 0.5 m で
  進むと最大 4151 ブリック・45 万ボクセル、Sponza は約 1950 / 20 万、物体 64 個で動的 324）。`--dyn-stages` は建物の段（`vox.*`）も分けて測る。
- **あふれ（Phase 32）**：要るブリックが入りきらないときは、粗い層から、同じ層の中はポインタの番号の順に場所を割り当て（印の数を 64 個ずつ数えて前置き和を取る）、
  入らなかった細かいブリックは「落とした」印になる。落とした所は 1 つ粗い層で三角形から作り（子から作る規則を外す）、トレーサ、押し出し、遮り判定、跳ね返りボリュームと
  DDGI の占有は、その場所を粗い層で読む（`voxAt`）。同じ形なら同じ結果になる。入りきるときは前と同じ原子カウンタで割り当てる（順で結果は変わらず、前置き和は G = 64 で
  0.27 ms 掛かった）。ボクセルの属性のプール（`maxVoxels`）のあふれはこの扱いをしない（あふれの数を出す。プールはブリックより先にあふれない大きさにした）。

## 広いワールド（`src/core/world.ts`、Phase 32）

- 建物が欠けない（`-bcut` でない）場面は、すべてワールドとして持つ（区画とまとめた形。インスタンス 1 つ）。広いワールドは、建物（静的な三角形）を何か所にも置いたインスタンスで持つ（GPU に同じ形を複製しない）。インスタンス 0 は原点で、カメラと動的物体はそこにいる。
  インスタンスが 2 つ以上のときだけ、インスタンスの描画、カメラに付く影の 2 層、DDGI の巻き取る格子を使う。ラスタ（G-buffer、影の地図）は、カメラ（か影の層）の範囲に入るインスタンスの箱だけを描く。描画の `firstInstance` に材質とインスタンスの番号を入れ、頂点シェーダが位置をずらす。
- 建物の三角形は重心で 8 m の区画に分ける（CPU で 1 回）。ボクセルの作成は毎フレーム、窓に入る（インスタンス、区画）を CPU で選び、その区画の最も細かい窓の層から始める作業の
  並びを書き、三角形のパスはこの並びを読む（スレッド → 作業は二分探索）。窓に入らない区画は触らないので、作成の費用は窓の中の形の量で決まり、ワールドの広さに依らない。
- 窓の外側の層（区画の最も細かい窓が層 s ≥ 1）は、区画の三角形を頂点のまとめ（その層の半ボクセル v0·2^(s−1) の格子に揃えたセルごとに、同じ材質の頂点を平均の位置へ寄せ、
  重複を落とす。線や点に潰れた三角形も残す）で作った粗い形状から作る。セルはボクセルの格子に揃っているので、1 つのセルに入る三角形は層 s の 1 つのボクセルに入る。
  Sponza の 26.2 万三角形は層 1 用で 5.5 万、層 2 用で 2.3 万、層 4 用で 4300。粗い頂点は描かず、建物の波（`-bwave`）は粗い頂点も同じ場で動かす。`-bcut` はワールドにしない
  （欠ける三角形を遠い頂点へ寄せる形を、まとめた形が追わない）。
- **層 0 のまとめ（三角形数への依存を断つ）**：区画の三角形を 0.1 m（層 0 の半ボクセル）のセルでまとめ、三角形が半分以下に減る区画だけ、層 0 もまとめた形から作る
  （三角形がボクセルよりずっと細かい所）。層 0 では頂点の法線の主軸と符号もセルの鍵に入れ、薄い壁の表と裏を混ぜない（入れないとリークの部屋で 0.69 → 4.2%）。
  Sponza の区画はまとめても 67〜100% 残るので使わず（画像はビット単位で同じ）、`sponza-dense10` の大きい区画は 18〜47% に減る（262 万 → 58 万三角形）。
  全区画をまとめるとトゥーンの物体の帯の切り替わりが 1.157 → 1.22% に増えたので、この閾値にした。
- まとめた三角形の行の番号は、層ごとに元の三角形の順（線や点に潰れたものを先）で振る。ボクセルの代表は重なる三角形の行の最大なので、選ばれ方が元の三角形と同じになり、
  潰れた三角形は本物の三角形に勝たない（区画の順で振ると、2 cm の壁の外側の面が代表になり、リークの部屋が 2 倍漏れた）。
- 三角形の代表の番号は「インスタンス × 表の行数 ＋ 行」。インスタンス 0 では前と同じ番号なので、インスタンスの無い場面の画像はこの形で変わらない（ビット単位で確かめた）。
- 影の地図：インスタンスのワールドでは 2 層（4096² ずつ）。層 0 はカメラの周り ±32 m（1.6 cm の画素）、層 1 は ±410 m（20 cm）。どちらもカメラに付き、光の面の上で画素に揃えて動く。
  影を引く所はすべて同じ関数（`shadowCoord`）で層を選ぶ。インスタンスの無い場面は前と同じ 1 層（場面の外接球）で、画像は変わらない。

## 動的レイヤ（P2、`src/core/dynlayer.ts`）

動的物体（三角形表の末尾）だけを、二値の占有ではなく被覆率と平均放射で持つ。毎フレーム作り直す。

- 動的三角形を小三角形（辺が層の 1 ボクセル程度。Sponza の物体では三角形 1 つに小片 1 つ）に分け、重心の点を、その点の陰影
  （太陽、シャドウマップ、トゥーンは放出側演算子）とともに、最も近い 8 つのボクセル中心へ三線形で配る。ボクセルは 6 方向への
  射影面積、面積、面積 × 放射を持つ（固定小数の整数の和なので、足す順によらず決まる）。点は物体と一緒に動くので、ボクセルの値は
  姿勢について連続（0 と 1 の切り替わりがない）。小片の大きさは 2026-11-14（Phase 18）に半ボクセルから 1 ボクセルにした（作成の
  費用を下げるため。参照との誤差と超過変動は変わらない：[30-measurements.md](30-measurements.md) の 22 節）。
- 作り方（Phase 18）：動的三角形は静止姿勢の重心の Morton 順に並べ、連続する 64 個を 1 つの作業グループが受け持って、その箱の
  ボクセル（192 個まで）を作業グループのメモリで足してから一度だけレイヤへ足す（窓からはみ出す角は直接足す）。ブリックは三角形が
  置かれる層だけで印を付け、粗い層は印の付いたブリックの祖先として足す。層 0 は固定小数のまま読み、粗い層は中身のあるボクセル
  だけを子から足す。
- 細かい層から粗い層へ、親 = 8 つの子の和。
- ボクセルの語は 13（6 方向の射影面積、面積、面積 × 放射、面積 × アルベド。アルベドは `obj` の実行だけが書く。Phase 31）。作業グループの窓は 144 ボクセル
  （値は窓の大きさに依らない。13 語で 192 だと 0.03 ms 遅かった）。
- 区間のレイは、静的なヒットより手前を錐の幅 w = t·√(4π / res²) の半分の歩幅で進み、v ≈ w の 2 つの層を読んで
  補間する。被覆率は向かい合う面の射影面積 / v² × 歩幅 / v の和（1 で打ち切り）。カスケードのレイは起点から層 0 のボクセル 1 つ（0.2 m）以内の動的レイヤを
  読まない（Phase 31。物体の画素が登録したプローブは物体の表面の上にあり、その物体自身を見て、トゥーンの受光ランプを揺らしていた。凸の物体は自分を照らさない）。放射 = 動的の放射 + (1 − 被覆率) ×
  静的の結果、透過率 = (1 − 被覆率) × 静的の透過率。
- 閉じた物体を内側から見た面は覆わない（押し出しは静的なボクセルだけを見るので、物体の中に入ったプローブが残る）。
- DDGI 系も同じレイヤを、レイ 1 本の錐（4π / 本数）で読む。距離のモーメントには入れない。
- ブリックの上限は `--vox` の `dynBricks`（**既定 512**、Phase 21。シェーダには上書き定数 `DYN_MAX_BRICKS` で渡す）。層 0 が 0.2 m で、
  64 物体（変形を含む）で 324 個要る（0.1 m のときは最大 1219 個）。
- **あふれたときは落とすブリックを決定的に選ぶ**（Phase 18）：要るブリックをビット集合に立て、粗い層から、同じ層の中は番号の順に
  場所を割り当てる。入らなかった細かい層のブリックは「落とした」印になり、読む側はその場所で 1 つ粗い層を読む。同じ姿勢なら
  同じ結果になる（64 物体を上限 1024 で 152 個落として 2 回とも同じ値、22 節）。Phase 17 までは原子操作の順で決まり、あふれると
  場が跳んだ（19 節）。

## スタイル演算子（`src/core/style.ts`）

輸送は線形のまま共有し、トゥーン材質にだけ両端で作用させる。

- **放出側**：太陽の項を 3 段（0 / 0.5 / 1、閾値 0.05 と 0.3）に量子化し、albedo の彩度を 1.6 倍にする。見えている
  画素（直接光）と区間トレーサのヒットで同じ関数を使う。ブリックには放射ではなく材質を持つ。
- **受光側**：c0 の照度 SH の L0 / L1 を 8 プローブで補間し、L1 の輝度の勾配を支配方向として 2 段のランプに通す
  （`amb − dir + 2·dir·step(n·d)`）。写実の画素は SH の照度のまま。
- ライトグループは未実装。

## DDGI 系の比較相手（`src/core/ddgi.ts`）

RTXGI の DDGI に寄せた。差が場の作り方に絞れるように、トレーサと輸送は RC と共有する。

- ワールド固定の一様格子、プローブごとに R 本のレイ（球面フィボナッチ、フレームごとに全プローブ
  共通の乱数回転）、放射照度 6×6 と距離モーメント 14×14 の八面体、ヒステリシス 0.97、RTXGI の適応則、チェビシェフ可視性、
  面のバイアス。
- レイは同じボクセルの区間トレーサで引く（区間 k は大きさ segBase / 4 × 2^k = 0.1 m × 2^k のボクセルの層。層 0 が 0.2 m なので最初の 2 区間は
  層 0。Phase 21 で、層 0 を粗くしても比較相手のレイが一緒に粗くならないようにした）。全長のレイなので 1 本あたり RC の区間の 4〜5 倍かかる。
- 押し出しと活性判定は静的なボクセルの占有から決める（視点に依らず、毎フレーム決め直す）。動的物体は動的レイヤを
  レイ 1 本の錐で読む（2026-11-14 から。DDGI の超過変動は入れる前と同じ程度、[30-measurements.md](30-measurements.md) の 13 節）。
- 多重バウンス（Phase 23）：ヒットで自分のプローブの放射照度を読み返す。トレースと混合は別のパス（光線の結果はテクスチャ）。
- 設定名 `ddgi-<間隔 cm>-<本数>[-h<ヒステリシス>][-noadapt][-u<間引き>][-g<ガンマ>]…`（`src/native/rc.ts` の先頭）。
- **広いワールドではカメラに付いて巻き取る格子**（Phase 32、RTXGI の無限スクロールと同じ考え方）：32 × 16 × 32 m の格子（1 m 間隔で 16384 プローブ）を、水平の中心をカメラの前方へ
  幅の 1/4、カメラを高さの 1/4 に置き、格子の単位で動かす。ワールドの格子点 c は (c − base) mod dims の場所に置き、前のフレームの格子に無かった点はその場所の履歴を捨てて始める。
  格子の外の画素は DDGI の間接光が 0。場面の外接箱に収まる場面は前と同じ固定の格子（画像は変わらない）。

## WebGL2 ティア（`src/core/gl2.ts`、`src/web/gl2.ts`、2026-11-16、Phase 33）

WebGL2 にある物だけで作った縮退版。フラグメントパスとテクスチャだけを使い、計算シェーダ、ストレージバッファ、原子操作、ボクセルを使わない。
同じ処理を WGSL（ネイティブの実行器で WebGPU の版と同じ場面と指標で測る、設定 `gl2-8-8`）と GLSL（ブラウザの WebGL2、`src/web/gl2.ts`、ページ `web/gl2.html`、
駆動は `node build/native/browser.mjs --page gl2`）の 2 つで持つ。WebGPU の版のコードと既定の画像は変えていない。

- **画面のプローブ**：8 × 8 画素のタイルに 1 つ、タイルの中心の画素に置く。法線の半球に 8 × 8 方向（立体角で一様、タイルごとに固定のハッシュで回す。フレームで変わらない）。
  光線は半分の解像度の深度（2 × 2 の近い方）を 16 歩（2 次で間隔を広げ 8 m まで）たどり、手前から奥へ横切って厚み max(0.3 m, 0.05 × 奥行き) 以内なら当たり。
  プローブから半分の解像度で 2 画素以内は飛ばす（自分の面に当たらないため）。当たった所の直接光の放射（トゥーンの放出側の演算子を含む）を返す。
- **画面の外の光は RSM**（太陽から見た 512² の G-buffer）：太陽が照らす面の放射を mip の並びにし、プローブごとに太陽の視野の中の 8 つの輪（半径 2 テクセルから倍々、輪に 24 点）で
  集めて L0 + L1 の放射の SH にする。画面から出た光線、当たらなかった光線はその方向の値と、空 × 画面の空の割合を返す。**RSM には面とプローブの間の遮りが無い**（壁の向こうの光も来る）。
  1 回の跳ね返りだけで、多重バウンスは無い。
- プローブの放射を L0 + L1 の照度 SH（rc.ts と同じ並び）にし、同じ平面の近くのプローブ（5 × 5）で平均する。**短い履歴**：前のフレームの同じ平面のプローブへ投影し直し、新しいフレームの重み 0.5
  （WebGPU の版の c0 と同じ規則）。各画素は近い 4 プローブを平面と法線の重みで補間する。トゥーンの画素は受光側の演算子を通す（WebGPU の版と同じ）。
- 費用（1080p、探索値）：GI 1.95〜2.84 ms、確保 51.2 MiB（WebGPU の版は同じ時に 3.0〜4.0 ms、86 MiB）。段は RSM と準備 0.3〜0.45、トレース 0.85〜1.15、SH と平均 0.45〜0.53、補間 0.2 ms。
- できる事とできない事、画像と数値は [30-measurements.md](30-measurements.md) の 37 節。

## 既知の弱点（未解決）

- **物体や光源が動くと場が跳ぶ**（[40-dynamic-stability.md](40-dynamic-stability.md)）。物体が動く分は P2 で 95% 減った
  （超過変動 0.065 → 0.0030）。残るのは太陽が動く分（0.0090、ヒット点の太陽の可視性が 1 点）。ヒット放射の前置フィルタ（P1）で 0.0022 まで下がったが、
  費用が余裕に入らず、消した（2026-11-15、Phase 27。[40-dynamic-stability.md](40-dynamic-stability.md)）。
- **動的物体の近くの床**（多重バウンスの参照、`sponza-dynobj` 姿勢 0、Phase 31）：既定では接地点が参照の 0.48 倍と暗く、手前の陰 0.71、輪の下 0.89、離れた陰 1.07 倍
  （物体が跳ね返りを返さないため。`obj` で 0.79〜1.12 倍）。前の「1.0〜1.9 倍明るすぎる」は 1 バウンスの実装と参照の値（Phase 08）。
- **建物が動くと場が跳ぶ**（残っている限界、Phase 29）。大半はプローブの押し出しと gather・合成の遮り判定が二値の占有の切り替わりを拾う分（`town` 87%、Sponza 43%。Phase 28）。
  Phase 29 でヒットの太陽の可視性をボクセルの面の平均にし、c0 に短い履歴を入れて跳びは約 2〜5 割減ったが（`town` 0.239 → 0.194、波打つ Sponza 0.114 → 0.090、現れて消える 0.0345 → 0.017）、
  DDGI 線形（0.0062 / 0.038 / 0.0009）には届かない。押し出しと遮り判定を面の平面で決める直しは `town` を 0.057 にしたが、Sponza の跳びとリークを増やして既定に入れていない
  （[40-dynamic-stability.md](40-dynamic-stability.md)、[30-measurements.md](30-measurements.md) の 33 節）。
- 静的なボクセルは照り返しを過大に、遮りを過小に見積もる（三角形の 1.5〜2 倍）。
- `vrel`：全プローブが遮られる画素が黒くなる（アーチの上、葉、近くの厚い物体、壁と床の継ぎ目。面がちょうどボクセルの面に乗る `town-grid` では地面の 33%）。92〜99% は遮り判定の線分が面の手前にはみ出した保守的なボクセルに当たる分（32 節）。判定の費用は計 1.36 ms（16 節）から、押し出しと親の遮り判定を並べて約 0.9 ms になった。画素の遮り判定（約 0.67 ms）が残る（[30-measurements.md](30-measurements.md) の 16、17 節）。
- カメラ移動時のちらつき（静的な `sponza` で 19.0%）の大半は法線マップによる測定の見かけ（外すと 3.3%、床 0.93%）。Phase 27 から、移動カメラと建物が動く場面は法線マップを外した値で読む（[10-evaluation.md](10-evaluation.md)）。外した後の移動カメラの超過変動は RC 0.0144 対 DDGI 線形 0.0050 で、RC の残りは形の縁と手前の床の筋（[30-measurements.md](30-measurements.md) の 31 節）。出どころは未確定。
- 受光側の帯の形は場の解像度に従い、物体の形に沿わない。
- 剛体をオブジェクト局所のブリックで持つ方式（[legacy/object-local/](../../legacy/object-local/)）は未実装。
  動的レイヤは毎フレーム三角形から作り直している。
- 動的レイヤの点の陰影はシャドウマップを 1 点で引く（太陽が動くと物体の上が跳ぶ）。
- 動的レイヤの作成は物体の数にほぼ比例する（Phase 18 の後、層 0 が 0.1 m で 3 物体 0.11 ms、64 物体 0.70〜0.76 ms。0.2 m で 64 物体 0.45 ms。22、24 節）。
  建物も物体も毎フレーム作り多重バウンスを入れた既定の構成で、RC の GI の余裕は 0.2〜0.3 ms（27〜30 節）。
- カメラが動くときのちらつきが層 0 を 0.2 m にして増えた（静的な `sponza` で 15.8 → 18.0%、25 節）。
  作成の半分は小片を配る段（splat）で、作業グループのメモリへの原子加算と窓からはみ出す角の直接加算で決まっている。
- 多重バウンスでリークが増えた（閉じた部屋 0.39 / 0.12 → 0.77 / 0.36%。DDGI も 0.65 / 0.45 → 3.67 / 3.44%）。部屋の中の跳ね返りボリュームに太陽の約 0.3% の
  光が入っていて、出どころは見つかっていない（[30-measurements.md](30-measurements.md) の 28 節）。
- 既定では、動的物体は跳ね返りを受けず（動的レイヤの放射は直接光だけ）、跳ね返りボリュームの光線を遮らない。受けて遮る形（`obj`）は GI が約 0.15 ms 増え、空いた機械で
