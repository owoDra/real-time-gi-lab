# レンダラ — いまの構成（Strata Cascades、仮称）

ここに書くのは**いま実装されている構成**と、それを選んだ根拠である。挙動の正本はコード（`src/core/`）。
数値は [30-measurements.md](30-measurements.md)、動的なシーンでの弱点と対策は
[40-dynamic-stability.md](40-dynamic-stability.md)、先行研究は [reference/prior-work.md](../reference/prior-work.md)。

この構成を土台として続けるかどうかは未決である（[50-roadmap.md](50-roadmap.md)）。

## なぜこの形か

| 目標 | 帰結 |
|---|---|
| WebGPU / WebGL2 | ハードウェアレイトレーシングが使えない。トレースはソフトウェア前提 |
| スタイル混在 | トゥーンのランプは閾値処理で、小さなノイズを帯境界のちらつきに増幅する。「不偏」より「無ノイズ」が要る |
| 完全動的 | 履歴に頼ると遅延とゴーストが出る。毎フレーム決定的に解ける手法が有利 |

この条件から Radiance Cascades（RC）系を選んだ。確率的サンプリングなしで無ノイズ、光源数に依存しない固定コスト。

## 既定の構成

設定名 `world-48-voxel-rc2-vrel`（計測の記録では「RC rc2-vrel P48」）。**建物と物体を含む全形状を毎フレーム作り直す**（2026-11-15、Phase 21 から。
建物そのものが毎フレーム変わってよい）。ボクセルの層 0 は 0.2 m で、窓はカメラに付いて動く。動的物体は動的レイヤ（P2）。
P1（ヒット放射の前置フィルタ）は既定に入れておらず、Phase 21 から動かない（下の「P1」）。
多重バウンスが入っている（2026-11-15、Phase 23。下の「多重バウンス」）。
建物が毎フレーム波打ち、物体 64 個（変形を含む）が動く Sponza で GI 3.67〜3.75 ms（静止カメラ、独立 3 回の中央値の範囲、Phase 24）、移動カメラ 3.37〜3.41 ms。
建物の一部が現れて消える場面で 3.64 ms。確保は作っている途中を含めて 76.8〜77.3 MiB（予算 128 MB は作っている途中にも
当てはめる。2026-11-14、ユーザー）。DDGI 線形は同じ場面で 6.1〜6.5 ms・106.8 MiB（[30-measurements.md](30-measurements.md) の 27 節）。
WebGPU の既定の上限で動く（実行器は既定の上限でデバイスを作る。2026-11-14、Phase 15）。

## 放射輝度場（`src/core/rc.ts`）

- **プローブはワールド格子**。可視画素が自分の c0 セルの 8 隅をハッシュに登録し、カスケード i+1 はカスケード i の
  プローブから登録する（三線形の合成に要る点だけ）。c0 間隔は 0.05 m × 2^LOD で、画面上 P 画素以下になる LOD を
  距離から選ぶ。ボクセルを使う RC では c0 間隔を層 0 のボクセル（0.2 m）より細かくしない（Phase 21。細かいプローブはボクセルの
  占有から置き場所が決まらず、近くの吊り布で 8 プローブとも遮られて黒くなった）。プローブの値は「格子点とワールドの状態」だけで決まり、どの画素が登録したかに依らない。
- **カスケード**：5 段。間隔 ×2、区間 s0·[(4^i−1)/3, (4^(i+1)−1)/3]、方向は八面体 (4·2^i)²（c0 は 16 方向）。
  方向の伸びは c2 で止める（`rc2`）。
- **区間は方向ごとに 1 本のレイで決定的に埋める。** 静的な形状に対しては、1 本が 1 つの方向ビン全体を代表し、ヒットは
  二値（当たれば透過 0）。動的物体は、ビンの錐の幅で平均した被覆率と放射で混ぜる（下の「動的レイヤ」）。合成は上の
  カスケードの最大 8 プローブの平均（遮られた親は使わない）。
- **c0 は L2 球面調和の放射照度**にして、画素ごとに 8 プローブを補間する。
- **場は履歴を持たない。** 2 バウンス目以降は跳ね返りボリュームの値で、3 バウンス目から 1 バウンスにつき 1 フレーム遅れる（下の「多重バウンス」）。
  静止したシーンでは収束した後、フレーム間で完全に同じ値になる。
- **輸送**：ヒット点の放射は太陽の直接光（`shadeHit`）と、アルベド / π × そこの間接放射照度（多重バウンス）。影はシャドウマップ（4096²）をヒットごとに
  1 点で引く（`p1` では前置フィルタした放射を読む）。最後の区間を抜けたレイは一様な空。

## 多重バウンス（`src/core/bounce.ts`、2026-11-15、Phase 23）

- カメラに付いた粗いプローブの格子（跳ね返りボリューム）：1.2 m 間隔、32×16×32、面の近く（1 セル以内に層 3 の占有があり、自分は層 0 のボクセルの外）の
  プローブだけが働く（Sponza で約 3,500 個）。各プローブは固定の 16 方向（乱数なし）と 6 軸の光線を引き、6 軸の放射照度（ambient cube）と、6 軸それぞれの
  「何もない距離」を持つ。光線のヒットの放射は直接光 ＋ アルベド / π × 前のフレームのボリュームの放射照度なので、ボリュームは全バウンスを持つ。
  プローブは 2 フレームに 1 回ずつ引き（ワールドの位置で交互）、引かないフレームは前の値を写す。
- 引いた後、占有されたボクセルごとに、そのボクセルの表と裏の放射照度を周りの 8 プローブから求めて置く。プローブは、面のその側にあり、読む点が
  プローブから軸ごとに見えている距離の内にあるときだけ使う（壁の裏や横のプローブを使わないため）。読む点は層 0 ではボクセルの中心、粗い層では
  その側へ半ボクセル。読む点を法線方向へ半セルずらす形は、壁と床の境目で床の下へ抜けた（Phase 24）。ヒットがどちらの側を読むかは光線の入った点で決める。RC のヒットはそれを 2 語読むだけ。RC の 2 バウンス目は同じフレームのボリュームで遅れがない。
- 費用：建物が波打ち物体 64 個の場面で GI +0.34 ms（分類 約 0.09、更新 約 0.15、ボクセルごとの値 約 0.1）、確保 +6.5 MiB（ボクセルごとの値 5 MiB）。
- DDGI 系は自分のプローブを、前の更新の状態から gather と同じ重み（チェビシェフを含む）で読み返す。トレースと混合は 2 パスに分けた。
- **プローブの押し出し（`vrel`）**：位置と法線を静的なボクセルの占有から決める（視点に依らない。動的物体は見ない）。ボクセルは表面だけで
  表裏を持たないので、壁の外側の格子点は外側に残る。gather（画素 → c0）と合成（プローブ → 親）で、線分がボクセルに
  遮られるプローブを使わない。8 つとも遮られる画素は黒くなる（漏らさない側に倒した）。押し出しと親の遮り判定は 1 プローブ
  1 ワークグループで、占有の読みをスレッドに並べ、浮動小数の和は直列のときと同じ順で 1 スレッドが取る（並べる前と画像が
  ビット単位で同じ。[30-measurements.md](30-measurements.md) の 17 節）。

## 区間トレーサ

インターフェースは 1 つ：`trace(origin, dir, t0, t1) -> (radiance, transmittance)`。合成側は実体を知らない。

| 実体 | 用途 |
|---|---|
| ボクセル StrataBrick | 既定。全区間 |
| 三角形 BVH（`src/core/bvh.ts`） | ボクセル近似の正解器。CPU で 1 回だけ構築し（Sponza で約 115 ms）、動的なシーンでは動く三角形を毎フレーム CPU で再フィットする（位相は同じ、GPU 時間の外。計測専用） |
| 深度バッファ | 比較用。画面外へ出たレイが空になり、空ありで 18 倍明るい |

## ボクセル StrataBrick（`src/core/voxel.ts`）

- 層 L のボクセルは v0·2^L（**v0 = 0.2 m**、5 層。Phase 21 から。0.1 m では全形状を毎フレーム作ると 4 ms に入らなかった）。8³ ボクセルのブリック（占有ビット 16 語）、層ごとに 64³ の
  ブリックポインタ（密）＋占有ブリックのプール。空ブリックを飛ばす 2 段の DDA。
- **カスケードごとに 1 層**上げる（c0 のボクセル = 0.25 × c0 プローブ間隔）。レイは太さ 0 の線で、方向ビンの
  断面（c2 で 2〜9 ボクセル幅）より細い。
- 静的な三角形（建物）だけを保守的にボクセル化する（三角形と箱の重なり）。占有は二値。動的三角形はブリックに入れない。
- **全形状を毎フレーム作り直す**（Phase 21 から既定。建物そのものが毎フレーム変わってよい）。クリップマップの窓はカメラに付いて動く。
  変わっていない所を省く経路は無い（毎フレーム建物の全三角形をボクセルにする）。一度だけ作る固定窓（`local`、`anchor: 'scene'`）は消した。
  作成用の一時バッファ（`vox.rep`、`vox.big`）は毎フレーム使うので、確保の合計が作っている途中の最大になる。
- **粗い層は細かい層から作る**（Phase 21）：層 L ≥ 1 のセルのうち層 L−1 の窓に入るものは、8 つの子の占有の論理和で、代表三角形は
  子の代表の最大（三角形から作るときと同じ決まり。アルファマスクだけは最も細かいボクセルで判定する）。三角形からは層 0 と、細かい窓の
  外の粗いセルだけを作る（Sponza は全部が層 0 の窓に入る）。子の 1 語（8×4 ボクセル）の親は 1 つの親ブリックの 1 語に収まるので、
  1 スレッドが 1 語を受け持ち、原子操作は親の語ごとに 1 回。
- 占有ボクセルは**代表三角形 1 個**（重なる三角形のうち番号最大）の albedo（a はトゥーンのフラグ）と法線を持ち、
  ヒット時に演算子と影を評価する。薄い壁をまたぐボクセルは、影をレイ側（ボクセルの入口）で引くことで外側の光を拾わない。
- プールは Sponza と物体 64 個に合わせる（`maxBricks` 3072、`maxVoxels` 327680、動的 `dynBricks` 512。使うのは約 1950 / 20 万 / 324）。
  層 0 の窓は 102 m。`--dyn-stages` は建物の段（`vox.*`）も分けて測る。

## 動的レイヤ（P2、`src/core/dynlayer.ts`）

動的物体（三角形表の末尾）だけを、二値の占有ではなく被覆率と平均放射で持つ。毎フレーム作り直す。

- 動的三角形を小三角形（辺が層の 1 ボクセル程度。Sponza の物体では三角形 1 つに小片 1 つ）に分け、重心の点を、その点の陰影
  （太陽、シャドウマップ、トゥーンは放出側演算子）とともに、最も近い 8 つのボクセル中心へ三線形で配る。ボクセルは 6 方向への
  射影面積、面積、面積 × 放射を持つ（固定小数の整数の和なので、足す順によらず決まる）。点は物体と一緒に動くので、ボクセルの値は
  姿勢について連続（0 と 1 の切り替わりがない）。小片の大きさは 2026-11-14（Phase 18）に半ボクセルから 1 ボクセルにした（作成の
  費用を下げるため。参照との誤差と超過変動は変わらない：[30-measurements.md](30-measurements.md) の 22 節）。
- 作り方（Phase 18）：動的三角形は静止姿勢の重心の Morton 順に並べ、連続する 64 個を 1 つの作業グループが受け持って、その箱の
  ボクセル（192 個まで）を作業グループのメモリで足してから一度だけレイヤへ足す（窓からはみ出す角は直接足す）。ブリックは三角形が
  置かれる層だけで印を付け、粗い層は印の付いたブリックの祖先として足す。層 0 は固定小数のまま読み、粗い層は中身のあるボクセル
  だけを子から足す。
- 細かい層から粗い層へ、親 = 8 つの子の和。
- 区間のレイは、静的なヒットより手前を錐の幅 w = t·√(4π / res²) の半分の歩幅で進み、v ≈ w の 2 つの層を読んで
  補間する。被覆率は向かい合う面の射影面積 / v² × 歩幅 / v の和（1 で打ち切り）。放射 = 動的の放射 + (1 − 被覆率) ×
  静的の結果、透過率 = (1 − 被覆率) × 静的の透過率。
- 閉じた物体を内側から見た面は覆わない（押し出しは静的なボクセルだけを見るので、物体の中に入ったプローブが残る）。
- DDGI 系も同じレイヤを、レイ 1 本の錐（4π / 本数）で読む。距離のモーメントには入れない。
- ブリックの上限は `--vox` の `dynBricks`（**既定 512**、Phase 21。シェーダには上書き定数 `DYN_MAX_BRICKS` で渡す）。層 0 が 0.2 m で、
  64 物体（変形を含む）で 324 個要る（0.1 m のときは最大 1219 個）。
- **あふれたときは落とすブリックを決定的に選ぶ**（Phase 18）：要るブリックをビット集合に立て、粗い層から、同じ層の中は番号の順に
  場所を割り当てる。入らなかった細かい層のブリックは「落とした」印になり、読む側はその場所で 1 つ粗い層を読む。同じ姿勢なら
  同じ結果になる（64 物体を上限 1024 で 152 個落として 2 回とも同じ値、22 節）。Phase 17 までは原子操作の順で決まり、あふれると
  場が跳んだ（19 節）。

## P1 ヒット放射の前置フィルタ（`src/core/hitrad.ts`、トークン `p1`、既定では使わない）

静的なヒット点の放射を 1 点で陰影せず、毎フレーム注入して上の層へ平均したボクセルの放射から、錐の幅に合う層で読む。
RC と DDGI が共有する `voxShade` から読む。**Phase 21 から動かない**：注入する一覧を一度だけ作ったブリックから CPU で作る形で、固定窓を
消したため（`p1` を指定すると実行器が止まる）。全形状を毎フレーム作る形に合わせて直すか消すかは Phase 31 で決める。下の記述は固定窓
（層 0 が 0.1 m）のときのもの。

- 層 1（0.2 m）の占有ボクセルごとに、代表の法線の表と裏の 2 値を持つ。照らされる側の面（v × v）の 4×4 点でシャドウマップを
  線形比較して可視性を平均する（トゥーンは点ごとに放出側演算子）。層 0 は持たない（注入が約 0.5 ms で予算に入らなかった）。
- **交わるボクセル**：層 1 のうち、中の層 0 のボクセルに法線が 60° より離れたもの（壁と床の交わり、角。Sponza で 6%）は
  注入しない。そこに当たったレイは P1 の前と同じ 1 点の陰影。形状から一度だけ調べ、注入の一覧の後ろに寄せる。
- 層 2〜4 は 8 つの子の平均（重み |子の法線 · 親の法線|、向きが逆の子は表裏を入れ替える。親 1 つに 8 スレッド）。子の面のうち、
  その向きのすぐ隣（同じ層、法線の主軸）が占有されている側は重み 0（奥を向いた面を入れない。形状から一度だけ印を付ける）。
- ヒットしたボクセルの中心を含む、錐の幅 w = k·t に最も近い層（トレースの層と層 1 より細かくしない）から読む。面の表裏は
  当たったボクセル自身の法線で選び、読むボクセルの法線がそれから 60° より離れていればその層を読まず細かい層へ戻る
  （どの層もだめなら 1 点の陰影）。
- 層 1 以上の放射はブリックのスロット順（4 語）。注入と平均でボクセルの段が 0.28 → 0.62 ms、19.3 MiB。
- 太陽が動く跳びを 76% 減らし、リークと参照との誤差は保つ。まだ既定に入れていない。GI は Phase 10 で 4 ms を超えたが、
  Phase 12 で `vrel` の判定を軽くした後は 3.34〜3.52 ms（[30-measurements.md](30-measurements.md) の 14、15、17 節）。
  既定に入れない理由はカメラが動くときの静的な場のちらつき（15.8 → 19.6%、目安 17.0%）。隣り合う 2 層の補間で読む形は
  19.5% で下がらず、外した（18 節。ちらつきは読む層の粗さで決まる）。

## スタイル演算子（`src/core/style.ts`）

輸送は線形のまま共有し、トゥーン材質にだけ両端で作用させる。

- **放出側**：太陽の項を 3 段（0 / 0.5 / 1、閾値 0.05 と 0.3）に量子化し、albedo の彩度を 1.6 倍にする。見えている
  画素（直接光）と区間トレーサのヒットで同じ関数を使う。ブリックには放射ではなく材質を持つ。
- **受光側**：c0 の照度 SH の L0 / L1 を 8 プローブで補間し、L1 の輝度の勾配を支配方向として 2 段のランプに通す
  （`amb − dir + 2·dir·step(n·d)`）。写実の画素は SH の照度のまま。
- ライトグループは未実装。

## DDGI 系の比較相手（`src/core/ddgi.ts`）

RTXGI の DDGI に寄せた。差が場の作り方に絞れるように、トレーサと輸送は RC と共有する。

- ワールド固定の一様格子（スクロールなし）、プローブごとに R 本のレイ（球面フィボナッチ、フレームごとに全プローブ
  共通の乱数回転）、放射照度 6×6 と距離モーメント 14×14 の八面体、ヒステリシス 0.97、RTXGI の適応則、チェビシェフ可視性、
  面のバイアス。
- レイは同じボクセルの区間トレーサで引く（区間 k は大きさ segBase / 4 × 2^k = 0.1 m × 2^k のボクセルの層。層 0 が 0.2 m なので最初の 2 区間は
  層 0。Phase 21 で、層 0 を粗くしても比較相手のレイが一緒に粗くならないようにした）。全長のレイなので 1 本あたり RC の区間の 4〜5 倍かかる。
- 押し出しと活性判定は静的なボクセルの占有から決める（視点に依らず、毎フレーム決め直す）。動的物体は動的レイヤを
  レイ 1 本の錐で読む（2026-11-14 から。DDGI の超過変動は入れる前と同じ程度、[30-measurements.md](30-measurements.md) の 13 節）。
- 多重バウンス（Phase 23）：ヒットで自分のプローブの放射照度を読み返す。トレースと混合は別のパス（光線の結果はテクスチャ）。
- 設定名 `ddgi-<間隔 cm>-<本数>[-h<ヒステリシス>][-noadapt][-u<間引き>][-g<ガンマ>]…`（`src/native/rc.ts` の先頭）。

## ティア

| ティア | 区間トレーサ | 状態 |
|---|---|---|
| WebGPU | ボクセル StrataBrick | ネイティブ（Dawn）でだけ動かしている。ブラウザでの GPU 時間は未計測 |
| WebGL2 | スクリーン空間のみ＋空・環境のフォールバック | 未着手 |
| ネイティブ / 将来の ray query | 中距離を BVH に置換 | 未着手。gpuweb の ray query は提案段階 |

実行器は WebGPU の既定の上限（バインド 128 MiB、バッファ 256 MiB、ステージあたりストレージバッファ 8 本）でデバイスを作る。
RC の各エントリポイントは使うストレージバッファだけのレイアウトを持ち（全部で 13 本、最大はトレースの 8 本）、三角形 BVH は
節点と三角形を 1 本のバッファにまとめている。既定の構成、`p1`、DDGI 2 種で動くことを確かめた（2026-11-14）。三角形が多い
場面（`sponza-wide10` など）の三角形トレーサは BVH が 128 MiB を超えうる（未確認）。

## 仮説の状態

| 仮説 | 状態 |
|---|---|
| H1 可視サーフェス近傍の疎なワールド格子プローブと RC の区間合成で、履歴なしに無ノイズの拡散放射輝度場が得られる | **静止したシーンでは支持**（静止時ちらつき 0）。**物体や光源が動くシーンでは満たせていない**（場が広い範囲で跳ぶ） |
| H2 区間トレーサをワールド空間の表現にすれば、HWRT なしで画面外の光と遮蔽を扱える | 支持 |
| H3 多層ボクセルで、光線コストとメモリが広さと三角形数に依存しない | 部分的に支持（トレースとメモリは三角形数によらない。毎フレームの作り直しの時間は窓の中の三角形数に比例する） |
| H4 遠い層ほど更新頻度を下げてよく、総更新コストは最下層の約 2 倍に収まる | 二値のブリックへの局所更新では費用の面で支持（毎フレームでも層 0 の 2 倍、差は 0.03 ms）。P2 の動的レイヤは全層を毎フレーム作る（0.25 ms）。層ごとの間引きは試していない |
| H5 スタイルを輸送の両端の演算子にすれば、輸送を共有したまま混在でき、写実部分の正しさも保てる | 正確な可視性（三角形）では支持。ボクセルでは物体の効果を 1.7 倍に過大に見積もる |

## 採らなかったもの（測った結果）

| 案 | 理由 |
|---|---|
| スクリーン配置のプローブ | カメラ移動時のちらつきがワールド格子の約 1.6 倍。ワールドトレースでも 37〜39% |
| レイ分割（1 画素 1 本の乱数レイを区間に振り分ける） | 静止時でもちらつく（8.6〜8.9%）。この実装では速くもない |
| 深度バッファだけのトレース | 空ありで +1827%、太陽だけの移動時ちらつき 42% |
| c0 だけ深度バッファ（ハイブリッド） | 誤差は同じでちらつきが多い |
| カスケードごとに 2 層（`l2`、二値のまま） | 遮蔽の過大で誤差 −37〜−57% |
| G-buffer に平面を当てる押し出し | 視点に依存し、移動時ちらつき 29.7%（`vrel` は 14.1%） |
| 押し出しの途中案（判定なしで全カスケード、c0 だけ、遮られた親を残す、保存法線に平面を当てる） | 偏り −36〜−48% かリーク 4〜10% |
| 受光ランプに幅を持たせる | ちらつきが増えた（2.9 → 3.9%） |

## 既知の弱点（未解決）

- **物体や光源が動くと場が跳ぶ**（[40-dynamic-stability.md](40-dynamic-stability.md)）。物体が動く分は P2 で 95% 減った
  （超過変動 0.065 → 0.0030）。残るのは太陽が動く分（0.0090、ヒット点の太陽の可視性が 1 点）。P1 で 0.0022 まで下がるが、
  まだ既定に入れていない（`p1`。カメラが動くときのちらつきが 15.8 → 19.6% に増える）。
- **P2 の動的物体の近くの床が明るすぎる。** 参照（Mitsuba）に対して、接地点 1.9 倍、輪の下 1.5 倍、離れた陰 1.9 倍、
  手前の陰 1.0 倍（三角形トレーサは同じ場所で 0.53〜0.84 倍と暗い）。球の真下の暗がりが出ない。手前の床の間接光は
  ほぼ物体の照り返しで、それが強すぎる。放射を面の向きごとに持っても 11% しか変わらない（主因ではない）。原因は
  分かっていない。部分被覆の足し合わせの過小と、物体の中に残ったプローブが物体を透かして外を見ることが候補（未検証）。
- **建物が動くと場が跳ぶ。** 建物は二値の占有なので、動くとボクセルが入れ替わる（[50-roadmap.md](50-roadmap.md) の残っている課題）。
- 静的なボクセルは照り返しを過大に、遮りを過小に見積もる（三角形の 1.5〜2 倍）。
- `vrel`：全プローブが遮られる画素が黒くなる（アーチの上、葉、近くの厚い物体）。判定の費用は計 1.36 ms（16 節）から、押し出しと親の遮り判定を並べて約 0.9 ms になった。画素の遮り判定（約 0.67 ms）が残る（[30-measurements.md](30-measurements.md) の 16、17 節）。
- カメラ移動時のちらつきが測定の床（4.0%）より高い（静的なシーンで 14〜16%）。原因は切り分けていない。
- 受光側の帯の形は場の解像度に従い、物体の形に沿わない。
- 剛体をオブジェクト局所のブリックで持つ方式（[legacy/object-local/](../../legacy/object-local/)）は未実装。
  動的レイヤは毎フレーム三角形から作り直している。
- 動的レイヤの点の陰影はシャドウマップを 1 点で引く（太陽が動くときの物体の上の跳びは、P1 では扱っていない）。
- 動的レイヤの作成は物体の数にほぼ比例する（Phase 18 の後、層 0 が 0.1 m で 3 物体 0.11 ms、64 物体 0.70〜0.76 ms。0.2 m で 64 物体 0.45 ms。22、24 節）。
  建物も物体も毎フレーム作り多重バウンスを入れた既定の構成で、RC の GI の余裕は 0.29〜0.32 ms（27 節）。DDGI 線形は同じ場面で 6.1〜6.5 ms で入らない。
- カメラが動くときのちらつきが層 0 を 0.2 m にして増えた（静的な `sponza` で 15.8 → 18.0%、25 節）。
  作成の半分は小片を配る段（splat）で、作業グループのメモリへの原子加算と窓からはみ出す角の直接加算で決まっている。
- 多重バウンスでリークが増えた（閉じた部屋 0.39 / 0.12 → 0.77 / 0.36%。DDGI も 0.65 / 0.45 → 3.67 / 3.44%）。部屋の中の跳ね返りボリュームに太陽の約 0.3% の
  光が入っていて、出どころは見つかっていない（[30-measurements.md](30-measurements.md) の 28 節）。
- 動的物体は跳ね返りを受けず（動的レイヤの放射は直接光だけ）、跳ね返りボリュームの光線を遮らない。RC は参照より暗い（多重バウンスの参照に対して偏り −17%）。
