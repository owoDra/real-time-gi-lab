# 動的なシーンでの跳び — 見立て、切り分け、対策

**ここに書いてある原因と対策は、コードを読んで立てた見立てで、まだ測っていない。** 測った事実は
[30-measurements.md](30-measurements.md) の 7 節だけである。作業は [plan/dynamic-stability/](../plan/dynamic-stability/README.md)
で進め、測ったらこの文書の「状態」の列を更新する。

## 現象（測った）

- RC（履歴なし）は静止したシーンではちらつき 0。物体や太陽が動くと、床や壁の広い範囲が 1 フレームでまとめて跳ぶ。
  静止カメラのちらつきは 19.6%（太陽だけ 7.7%、物体だけ 17.9%）。DDGI は 1.3〜4.8%。
- プローブの押し出しを止めても変わらない（18.7 対 17.9%）。プローブを密にしても変わらない（P32 19.7、P48 19.6%）。
- 光源切替への応答は RC が 1 フレーム、DDGI は 11〜161 フレーム。
- 19.6% は、毎フレームの平均変化が約 0.05 段（3〜4%）であることに相当する
  （[10-evaluation.md](10-evaluation.md)「動的シーンのちらつきの読み方」）。

## 見立て

場は「格子点とワールドの状態」の決定的な関数である。静止時に 0 で、動くと跳ぶのは、その関数が不連続だからである。

**本命は、1 つの方向ビンの立体角を太さ 0 のレイ 1 本で、ヒット点の放射を 1 点で代表させていること**（角度と位置の
点サンプリング）。静止したシーンでは固定の偏りにしかならないが、不連続（物体の縁、影の縁）が動くとサンプルを 1 つずつ
またぎ、増える変化と減る変化が別々のフレームに届いて打ち消し合わない。上のカスケードの 1 サンプルは配下の広い領域で
共有されるので、跳びは面でそろう。DDGI も同じ 1 ビン 1 サンプルで、回転と時間平均によってこのエイリアシングを遅れに
換えている。

この見立てから次が導かれる（どれも未検証）。

- **サンプルを増やしても効きにくい。** 方向数、ヒット点のタップ数、プローブ密度を K 倍にしても、跳びは小さく多く
  なるだけで、ちらつきは 1/√K 程度でしか減らない。P32 と P48 が同じなのはこれと整合する。
- **占有を二値から被覆率に変えるだけでも足りない。** 階段が斜面になるだけで、総変動は同じである。
- **必要なのは、ビンの断面に合った大きさで平均すること**（空間・角度の前置フィルタ）。時間方向の平均ではないので、
  遅れは出ない。

## 原因の候補と切り分け

| # | 候補 | 根拠 | 切り分け | 予測 | 状態 |
|---|---|---|---|---|---|
| A | 角度の点サンプリング。c2 で方向ビンの幅は区間内で 2〜9 ボクセル分あるのに、レイは 1 本。物体がレイを横切るとビン全体が切り替わる | カメラ移動のちらつきは三角形でもボクセルでも同じ（28.9 対 29.4%）。Split RC も間隔より小さい物体は落ちると書いている | **E1**：三角形トレーサ（`tri`）で `sponza-dyn-objectsonly` を回す。BVH が動く頂点に追従しなければ、毎フレームの再構築を計測外で足す | 三角形でも約 18% なら A。大きく下がれば B・C | 未測定 |
| B | 占有の二値の切り替わり（保守的ボクセル化で物体が膨らむ） | ボクセルは物体の効果を 1.7 倍に過大に見積もる | **E2**：動的三角形を入れる層をマスクで掃引する（なし / 層 0 / 層 0〜1 / … / 全部）。`h4: 'l0' / 'none'` の一般化 | 層ごとの寄与が出る | 未測定 |
| C | 代表三角形の乗っ取り。番号最大が勝つので、動的三角形が触れた床や壁のボクセルが丸ごと物体の属性になる | 粗い層では 0.8〜1.6 m の床が一度に入れ替わる | **E3**：全再構築で、重なったときに静的三角形が勝つ規則にする | 下がれば C | 未測定 |
| D | ヒット点の太陽の可視性が 1 点（ボクセルの入口、バイアス 0）。影の縁が通るとビン全体が 0 と 1 を行き来する | 太陽だけで 7.7%。ちらつきは暗い面に集中 | **E4**：`sponza-dyn-sunonly` で、ヒット側の太陽の可視性を常に 1 にする（診断用。画像は正しくない） | 1〜2% に落ちれば D | 未測定 |
| E | 放出側トゥーンの量子化。帯が面ごとに切り替わる。これは仕様どおりの変化で、手法の欠陥ではない | DDGI は同じ変化を時間平均で均す | **E5**：`sponza-dynobj`（写実材質）と `noemit` で同じ分解を取る | 差があれば、その分は欠陥から除く | 未測定 |
| F | プローブ集合の変化と上限あふれ（あふれた先は実行順に依存する） | 可能性は低い | **E6**：動的な実行中のあふれと挿入失敗の計数（`counts[8..24)`）を読む。物体を除いた G-buffer でプローブを登録して比べる | 0 かつ変化なしなら除外 | 未測定 |

切り分けの前提：

- 最初に 7 節の値（19.6 / 7.7 / 17.9%）を再現する。
- 指標に超過変動を足し、動的物体の画素とその遮蔽・露出の画素を除く（[10-evaluation.md](10-evaluation.md)）。
- 層ごとの寄与は、更新を遅らせるのではなくマスクで測る。

## 対策の案

### 遅れ 0 のまま抑える

| 案 | 内容 | 費用の見積もり（未計測） | 合格の目安 | 外れの見分け方 |
|---|---|---|---|---|
| **P1 ヒット放射の前置フィルタ**（D 向け） | 毎フレーム、層 0 の占有ボクセルに直接光を注入し（表裏 2 値）、上の層へ平均する。ヒット時は錐の幅に合う層から読む。形状と放射の更新を分ける | 注入と平均で +0.1〜0.2 ms。トレース中の影の参照が消えるので相殺の見込み。+6 MB 程度 | `sunonly` の静止カメラ 7.7 → 3% 以下 | 下がらない。リーク部屋が悪化する（表裏の分離が効いていない） |
| **P2 動的物体だけ被覆率レイヤ**（A〜C 向け） | 静的な形状は今の二値のまま（動かないので固定の偏りにしかならず、リーク耐性を保つ）。動的三角形は軸別の被覆率と平均放射を固定小数の加算で書き、1〜2 層粗い層で透過率を積む | 動的ブリックを通るレイだけ追加で +0.1〜0.3 ms。メモリは誤差程度 | `objectsonly` の静止カメラ 17.9 → 5% 以下。物体の効果の過大 1.7 倍が 1 に近づく | 下がらない。動く遮蔽物でリークが増える |
| **P3 有限の履歴**（保険） | 方向セットを周期 N=4 の決定的な回転で回し、c0 の SH を直近 N フレームの箱型平均にする。プローブは格子のキーで引けるので再投影は要らない。静的なシーンでは全周期の平均が不変で、静止時ちらつき 0 を保つ | +0.05〜0.1 ms、SH の履歴で +10〜16 MB | 応答が N フレーム以内、遅れの差が参照ノイズ以下 | 応答が N フレームを超える。跳びが 1/√N 程度（約半分）にも減らない |

- P1 と P2 は構成上遅れが出ない。動かした値と止めた値のビット一致、応答 1 フレームがそのまま検証になる。
- P2 の前に、球を解析的な「錐と球の被覆」に差し替えて跳びが消えるかを見れば、A を直接確かめられる。解析プロキシは
  トポロジの変化に対応できないので本採用しない。
- P2 はボクセルコーントレーシングと同じ弱点（部分透過の積による遮蔽の過小）を持つ。動的レイヤに限るのはそのため。
- どの案も GI 4 ms と 128 MB の中で入れる。既定の構成は 3.4〜3.5 ms で、余りは約 0.5 ms。
- カメラ移動時のちらつき（静的なシーンで 15.8%）は LOD と登録の変化が候補の別問題で、P1・P2 では下がらない。

### DDGI 系の「応答・ちらつき・偏り」を崩す

| 案 | 内容 | 外れの見分け方 |
|---|---|---|
| D1 有限履歴 | P3 と同じ仕組み（周期 N=8 の決定的な回転と全周期の箱型平均、線形）。偏りなし、静止時ちらつきは理論上 0、応答は N × 更新間引きフレーム以内で長い尾がない。1 m 間隔で +18 MB 程度 | 動的なシーンのちらつきが 10% を超える |
| D2 時間勾配 | レイの 1 割を前フレームと同じ方向で引き直し、その差（ノイズを含まない変化量）でヒステリシスを線形・対称に決める。RTXGI の「明るくなる変化を 1/4 に抑える」規則をやめる | 太陽が連続して動くと全プローブが変化ありになり、h 0.8 相当のちらつきに戻る |
| D3 区間分割 | プローブは近距離だけ引き、遠方は粗い格子から合成する。レイ単価が 1/4〜1/5 になる分、本数を増やして h を 0.85 前後へ下げる。ほぼ RC になる | 合成の継ぎ目でリークか偏りが増える |

**P1 と P2 は DDGI のレイにも同じだけ効く**（被積分関数が滑らかになれば、低いヒステリシスでもちらつかない）。
RC にだけ入れて比べない。

## やらないこと

- サンプルを増やして抑える（方向数、タップ数、プローブ密度）。E の実験で 1/√K を外れる結果が出るまでは採らない。
- 占有の被覆率化だけを単独で入れる。
- 長い履歴（ヒステリシス 0.9 以上の指数平均）を RC に足す。R1 を失い、DDGI と同じ三すくみに入る。
- 予算（4 ms、128 MB）を緩める。

## 続けるかどうかの材料

切り分け（E1〜E6）の結果が出たら、方向の確認のフェーズでユーザーが決める（[50-roadmap.md](50-roadmap.md)）。
AI が先に決めておくことはしない。そのときに並べるもの：

- 原因ごとの寄与（どの候補が何 % を占めるか）。
- P1・P2 で届く見込み（同じ ms の DDGI 線形に対して静止カメラのちらつきが 2 倍以内か）。
- 届かない場合の残り：P3（有限の履歴）、DDGI 系を土台にする（D1〜D3）、中止。
