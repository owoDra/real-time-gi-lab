  → **2026-11-15（Phase 21）に数値の上では外れた**（建物が変わり物体 64 個が動く場面で RC 3.47〜3.65 ms、3 回とも）。2026-11-15 にユーザーの指示で
  Phase 26 を閉じた（できた物への指摘はない）。Phase 26 の 1 回の実行では 3.80 ms。余裕は 0.2〜0.3 ms で、ブラウザでの値は Phase 30 で確かめる。以下は経過：2026-11-14 は当たっていた。 建物が変わらない
  条件（建物を一度だけボクセルにする固定窓）では入っている：物体 3 つで 3.05〜3.20 ms、物体 64 個で 3.80〜3.94 ms。建物が
  変わると全再構築（Sponza で 1.9 ms）が毎フレーム要り、足し算の見立てで約 5.6 ms（場 約 3.0 ＋ 全再構築 1.9 ＋ 物体 64 個の
  動的レイヤ 0.7）。Phase 20（2026-11-15）で通しで測ると、建物が毎フレーム変わり物体 64 個が動く場面で RC 5.7〜6.7 ms（今の構成のまま）。
  層 0 のボクセルを 0.2 m にした形で 3.6〜4.0 ms になり、Phase 21 でこれを既定にした。
- 同じ 4 ms で、DDGI 系に対して品質（参照に対する誤差、ちらつき、リーク）でも対応範囲（応答、履歴なしでの破綻の
  なさ）でも優位がない。
  → **当たらない（2026-11-14、Phase 16）。** 割れている：応答（1 対 11〜161 フレーム）、動いている途中の遅れのなさ、静的な安定性、
  GI の軽さは RC、静的な誤差と動的な安定性（静止カメラで DDGI 線形の 13 倍、`p1` 4 倍、移動カメラで 1.75 倍、1.50 倍）は DDGI。
  DDGI 系は遅れなしと安定を同時に満たせない。
  → **当たらない（2026-11-15、Phase 26。全形状が毎フレーム変わる土台と多重バウンスを入れた後の判定）。** RC の優位：応答（1 フレーム対 DDGI 線形 268）、
  動いている途中の遅れ（0.05% 対 26%）、静止時のちらつき 0、リーク（0.77 / 0.36% 対 2.11 / 1.79%）、`town` での参照との誤差（0.228 対 0.297）、
  広さで増えないメモリ。DDGI 系の優位：Sponza での参照との誤差（0.346 対 0.283）、建物が動くときの安定（跳び 0.178 対 0.106、`town` 0.239 対 0.0074）、
  トゥーンの帯の切り替わり（1.26〜2.19% 対 1.03〜1.05%）、費用（3.7〜3.8 対 3.1〜3.2 ms）。応答を 14 フレーム以下にした DDGI 系は、物体が動く跳びも
  静止時のちらつきも RC より悪い（30 節）。スタイル混在（目的 2）では、トゥーンの帯の切り替わりが DDGI 系より多いことが欠点として残る。

## 5 以降に持ち越している事実

- 全再構築は窓の中の三角形数に比例する（Phase 20、層 0 が 0.1 m：Sponza 1.9〜2.3 ms、三角形 9 倍 3.3 ms、広さ 10 倍 4.3 ms。0.2 m：
  0.86、1.9、2.4 ms）。作成用の一時バッファは毎フレーム使うので解放できない。
- 動的レイヤは毎フレーム全層を作り直す。費用は物体（動的三角形）の数にほぼ比例する（3 物体 0.26 ms、12 物体 0.81〜0.88 ms、24 物体
  1.35〜1.65 ms、64 物体 3.33〜3.39 ms。64 物体で splat 77%）。Phase 18 の後は 3 物体 0.11 ms、64 物体 0.70〜0.76 ms。ブリックは 64 物体で
  最大 1219 個要り、上限の既定は 1536。上限を超えても落とすブリックは決定的に選ばれ、落とした場所は粗い層で読む。
- 動的物体の頂点（変形を含む）は CPU で動かして毎フレーム書き込んでいる（64 物体で 1 フレーム 1.3〜1.7 ms、変形ありで約 20 ms）。
  計測の実行器は全フレームの姿勢を計測の前に計算しておき、GPU を待たせない（Phase 18）。実際の使い方では頂点の変形は GPU の仕事になる見立て（未検証）
  （GI の時間には数えない）。
- 建物を含む全形状を毎フレーム作り直す（Phase 21 から既定）。変わっていない所を省く経路は無く、費用は窓の中の三角形の数に比例する。
- DDGI 系は固定格子のままではメモリが体積に比例する。広さを比べるにはスクロールする体積かカスケードが要る。
- 三角形 BVH の CPU 構築は Sponza で約 115 ms。

## 残っている課題（順番に入っていないもの）

- GI の余裕が 0.2〜0.3 ms しかない。ブラウザでの時間は未計測（Phase 30）。

  （参照の 1.0〜1.9 倍。球の真下の暗がりが出ない。原因は分かっていない）。

  ボリュームに太陽の約 0.3% の光が入り、出どころは見つかっていない。

  手前の柱は RC も DDGI も参照の半分以下（共有のトレーサの側の見立て、未検証）。動的物体は跳ね返りを受けない（Phase 31）。
