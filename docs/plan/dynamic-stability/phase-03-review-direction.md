## 目的

「同じ 4 ms で DDGI 系に対して優位があるか」が割れたままになっている（[`spec/50-roadmap.md`](../../spec/50-roadmap.md)）。
切り分けの結果を見て、続けるか、どの土台で続けるかをユーザーが決める。

## 前提

Phase 02（原因ごとの寄与の表）。

## 決定済みの方針

- 選べる案（Phase 02 の結果で、成り立たなくなった案は外し、理由を 1 行で残す）：
  - **A 前置フィルタで RC を続ける**：遅れ 0 のまま、寄与の大きい原因から P1（ヒット放射の前置フィルタ）、
    P2（動的物体だけ被覆率レイヤ）を入れる。届けば応答 1 フレームと安定性の両方が手に入る。届かない場合は
    作業が無駄になる。
  - **B RC に有限の履歴を足す**（P3）：実装は小さい。応答は数フレームに落ち、跳びは半分程度までしか減らない見込み。
  - **C DDGI 系を土台にする**：動的な安定性はいまの時点で上。応答の遅さを D1〜D3 で詰める。RC の「履歴なし・無ノイズ」
    は手放す。
  - **D 中止する**：正当な結果として記録する。
- Phase 02 の結果は、Phase 02 の終わりにここへ書く。

## 確かめる決定

| 決定 | 確かめ方 |
|---|---|
| 方向はユーザーが決める | AskUserQuestion の回答が会話にある。AI は回答の前に spec を書き換えない |
| 判断できる形で見せる | Artifact に、RC と DDGI の同じ画角・同じフレームの並べた画像（静止カメラの動的シーン、ちらつきの分布図、光源切替の直後）、原因ごとの寄与の図、各案の見込みと費用が載っている |
| 予算は変えない | どの案も GI 4 ms、128 MB の中 |
| 一方にだけ入れた改良で比べない | A を選んだ場合の後のフェーズに、同じ対策を DDGI 側に入れて比べ直すフェーズがある |

## やること

1. 準備：案をまとめ、画像と数値のページを Artifact に公開する。
2. 選択：AskUserQuestion で尋ねる。
3. 追加：求められた材料を足して同じ URL へ再公開する。
4. 反映：spec と後のフェーズを書き直す。

- ユーザーが方向を選び、spec に日付つきで書かれている。
- 列の README の 04 以降と、次のフェーズのファイルが、選んだ方向で書かれている。
