# 作業計画：動的な安定性

進め方、プロンプトの使い方、共通の完了定義は [`../README.md`](../README.md)。

物体や光源が動くと RC の場が広い範囲で跳ぶ（静止カメラのちらつき 19.6%、DDGI は 1.3〜4.8%）。原因の切り分けと
方向の確認は終えた。RC を続け、遅れ 0 の前置フィルタを P2（錐の幅で読む形）、P1 の順に入れて、DDGI 系と比べ直す。見立てと案の正本は
[`spec/40-dynamic-stability.md`](../../spec/40-dynamic-stability.md)、測った値は
[`spec/30-measurements.md`](../../spec/30-measurements.md) の 7、9、10、11 節。

ブランチは `p2`。

## この列で決めたこと

- 動的なシーンの跳びは、静止カメラの超過変動（log2、K = 16）で比べる（2026-11-14、Phase 01。定義は
  [spec/10-evaluation.md](../../spec/10-evaluation.md)）。
- 方向：RC を土台に続け、遅れ 0 の前置フィルタ（P2、P1）で跳びを抑える。最初に E7 で A を直接確かめ、その結果で
  P2 へ進むかを決め直す。有限の履歴（P3）、DDGI 系を土台にする案、中止は採らない（2026-11-14、Phase 03、ユーザー決定）。
- 次に作るのは P2 を錐の幅で読む形、その後に P1。錐の後に残る分の切り分け（E8）を先に置かない（2026-11-14、
  Phase 05、AI 決定。技術の選択は AI が決めて報告する。理由は
  [spec/40-dynamic-stability.md](../../spec/40-dynamic-stability.md) の「方向」）。
- 切り分けは終えた（2026-11-14、Phase 01・02・04）。原因ごとの寄与と書き直した見立ては
  [spec/40-dynamic-stability.md](../../spec/40-dynamic-stability.md)。E7（Phase 04）で、角度の点サンプリング（A）は
  一部（事前の目安で 30〜70%）。三角形で残る分には、物体の表面の 1 点の陰影（G）と、説明できていない残りもある。

## この列のきまり

- P2 を確かめる（07 の OK）まで P1 を実装しない。画像を変える auto を 2 つ続けない。
- 診断用のスイッチ（太陽の可視性を 1 にする、層のマスク、代表三角形の規則、解析的な球）は、結果を spec に書いたら消す。
  既定の構成（`world-48-voxel-rc2-vrel`、局所更新）の画像を変えない。
- 層ごとの寄与は、更新を遅らせるのではなくマスクで測る（遅らせても総変動は減らない）。
- 動的なシーンのちらつきは本物の変化を含む。DDGI の値を「本物の変化の上限」として使わない。超過変動で比べる。
- サンプルを増やす方向（方向数、タップ数、プローブ密度）は試さない。見立ての確認は Phase 02 で済んだ（方向ビンの
  レイ 4 倍で 0〜40% しか減らない）。
- 場の明るさを変える診断（可視性を 1 にするなど）は、log2 と相対値だけで読まない。線形の絶対値を併せて読む。
- 予算は GI 4 ms、128 MB。変えない。計測はネイティブ（Dawn / Vulkan）だけ。GPU ジョブは同時に 1 本。
  参照（Mitsuba）を描いている間は GPU 時間を測らない。
- 数値の要約は `docs/reference/measurements/dynamic-stability/` に置く。
