# 作業計画：動的な安定性

進め方、プロンプトの使い方、共通の完了定義は [`../README.md`](../README.md)。

物体や光源が動くと RC の場が広い範囲で跳ぶ（静止カメラのちらつき 19.6%、DDGI は 1.3〜4.8%）。原因の切り分けと
方向の確認は終えた。RC を続け、遅れ 0 の前置フィルタを P2（錐の幅で読む形）、P1 の順に入れて、DDGI 系と比べ直す。
P2 は入れた（Phase 06、物体が動く分の超過変動 0.065 → 0.0030）。Phase 07 でユーザーが見て OK。Phase 08 で別のモデル
（Claude Fable）が見直し、続けると決めた。Phase 09 で P1 を作って測り、太陽が動く分は 0.0090 → 0.0022、両方で
0.0119 → 0.0044 になったが、リーク（1.7 倍）と費用（移動カメラで 1 回 4.04 ms）で目安を外れ、既定に入れていない（トークン `p1`）。
Phase 10（built）でリークと暗さを直したが、GI が 4.20〜4.39 ms で 4 ms を超え、既定に入れない（ユーザーは画像を見て OK）。
Phase 11（review）で、P1 を 4 ms に入れる道を作って試すと決めた（`vrel` の判定 1.36 ms を画像を変えずに軽くする）。
Phase 12 で画像をビット単位で変えずに既定の GI を 0.35〜0.42 ms 下げ、`p1` が 3.34〜3.52 ms になった。Phase 13 で P1 の読む層を
2 層の補間にしたが、カメラが動くときのちらつきが下がらず（19.5%、目安 17.0%）、P1 は `p1` のまま。次は Phase 15（条件を広げる計測）。
見立てと案の正本は [`spec/40-dynamic-stability.md`](../../spec/40-dynamic-stability.md)、測った値は
[`spec/30-measurements.md`](../../spec/30-measurements.md) の 7、9〜18 節。

ブランチは `p2`。

## この列で決めたこと

- 動的なシーンの跳びは、静止カメラの超過変動（log2、K = 16）で比べる（2026-11-14、Phase 01。定義は
  [spec/10-evaluation.md](../../spec/10-evaluation.md)）。
- 方向：RC を土台に続け、遅れ 0 の前置フィルタ（P2、P1）で跳びを抑える。最初に E7 で A を直接確かめ、その結果で
  P2 へ進むかを決め直す。有限の履歴（P3）、DDGI 系を土台にする案、中止は採らない（2026-11-14、Phase 03、ユーザー決定）。
- 次に作るのは P2 を錐の幅で読む形、その後に P1。錐の後に残る分の切り分け（E8）を先に置かない（2026-11-14、
  Phase 05、AI 決定。技術の選択は AI が決めて報告する。理由は
  [spec/40-dynamic-stability.md](../../spec/40-dynamic-stability.md) の「方向」）。
- P2 を既定の構成に入れた（2026-11-14、Phase 06、AI 決定。事前の目安を両方満たした）。錐の後に残る分の切り分け（E8）は
  置かない（物体が動く分が 0.0030 まで下がったため）。
- P2 の結果をユーザーが見て OK（2026-11-14、Phase 07）。物体の近くの遮りが弱い件は直さずに進める。次に別のモデル（Claude Fable）の
  見直しを置く（ユーザー）。
- 見直し（2026-11-14、Phase 08、別のモデル（Claude Fable）による AI 決定）：RC と遅れ 0 の前置フィルタを続ける。P1 は
  共有のトレーサに入れて RC と DDGI を同じフェーズで測る。同じ 4 ms での比べの前に、条件を広げる計測（11）を置く。
  P2 の物体の近くの明るすぎは直さずに進める（参照に対して 1.0〜1.9 倍）。報告の Artifact：
  https://claude.ai/artifact/G38h8p6Kq7ZCboHC1MTbzc
- P1（2026-11-14、Phase 09、AI 決定）：RC と DDGI の共有のトレーサに入れて測った。D は取れた（太陽だけ 0.0022）が、リークと
  費用で目安を外れ、既定に入れない。注入は層 0 ではなく層 1 から（層 0 は注入だけで約 0.5 ms）。次は built で直す。
- P1 を直した（2026-11-14、Phase 10、AI 決定。ユーザーは画像を見て OK）：読む層の向きを当たった面に合わせ、向きの交わる
  ボクセルを注入せず、奥を向いた面を平均に入れない形で、リーク（0.74 / 0.41%）と暗さ（偏り −13.5%）は直った。GI は
  4.20〜4.39 ms で既定に入れない。次の条件を広げる計測の前に review（11）を置く。報告の Artifact：
  https://claude.ai/artifact/EmeHtnWw39ET5c9BaM2YKv
- 方向の確認（2026-11-14、Phase 11、AI 決定）：P1 を 4 ms に入れる道を作って試す。削るのは P1 ではなく `vrel` の判定（1.36 ms、
  P1 の上乗せの約 4 倍）で、画像を変えずに軽くする。P1 なしで同じ 4 ms での比べへは進まない（物体と太陽で DDGI 線形の 13 倍の
  まま比べることになり、条件を広げる計測も測り直しになる）。カメラが動くときのちらつきの増えた分の約 7 割は P1 の読む層の
  切り替わりで、2 層の補間で直してから既定に入れる。報告の Artifact：https://claude.ai/artifact/LtPefmG1GT1TNGKDT7yjE5
- `vrel` の判定を軽くした（2026-11-14、Phase 12、AI 決定）：押し出しと親の遮り判定を 1 プローブ 1 ワークグループにして読みを
  並べ、画素の判定は読む層と始点を 8 プローブで共有した。画像はビット単位で同じ。既定の GI は交互 3 組で 0.423 / 0.353 / 0.417 ms
  下がり、目安（3 組すべて 0.40 ms 以上）は 1 組で外れた。中央値が 0.2 ms 以上で、`p1` の GI が 3 組すべて 4 ms 以下（静止 3.34〜3.50、
  移動 3.37〜3.52 ms）なので、事前の規則どおり 13 へ進む。画素ごとの遮り判定（約 0.67 ms）は画像を変えない形では残る。
- P1 の読む層の補間（2026-11-14、Phase 13、AI 決定）：移動カメラのちらつきが 19.57 → 19.50% で目安（17.0% 以下）を外れ、既定に
  入れない（ほかの 8 つの目安は満たし、GI は 3 組すべて 3.66〜3.71 ms）。ちらつきは読む層の粗さで決まり（層を固定 16.92%、1 層上
  20.04%）、補間では直らない。補間は外して 1 層の読みに戻した。Phase 11 の控えどおり 15 へ進み、14（built）は置かない。
- 切り分けは終えた（2026-11-14、Phase 01・02・04）。原因ごとの寄与と書き直した見立ては
  [spec/40-dynamic-stability.md](../../spec/40-dynamic-stability.md)。E7（Phase 04）で、角度の点サンプリング（A）は
  一部（事前の目安で 30〜70%）。三角形で残る分には、物体の表面の 1 点の陰影（G）と、説明できていない残りもある。

## この列のきまり

- 画像を変える auto を 2 つ続けない。
- 診断用のスイッチは、結果を spec に書いたら消す。計測だけのフェーズでは、既定の構成（`world-48-voxel-rc2-vrel`、固定窓、
  P2 の動的レイヤ）の静的なシーンの画像を変えない（`sponza` の放射照度がビット単位で同じことで確かめる）。P1（`p1`）を
  既定に入れるときは静的なシーンの画像が変わるので、静止時のちらつき 0、超過変動 0、参照との誤差で確かめる。
- 明るさの正しさは参照（Mitsuba）で言う。三角形トレーサは参照より暗く（物体の近くの床で 0.53〜0.84 倍）、ボクセル近似の
  影響を分ける用途に限る。
- 予算に近い GPU 時間は 3 回測って範囲を書く。built のページの先頭には、悪くなった所と、まだ見ていない条件を書く。
- 層ごとの寄与は、更新を遅らせるのではなくマスクで測る（遅らせても総変動は減らない）。
- 動的なシーンのちらつきは本物の変化を含む。DDGI の値を「本物の変化の上限」として使わない。超過変動で比べる。
- サンプルを増やす方向（方向数、タップ数、プローブ密度）は試さない。見立ての確認は Phase 02 で済んだ（方向ビンの
  レイ 4 倍で 0〜40% しか減らない）。
- 場の明るさを変える診断（可視性を 1 にするなど）は、log2 と相対値だけで読まない。線形の絶対値を併せて読む。
- 予算は GI 4 ms、128 MB。変えない。計測はネイティブ（Dawn / Vulkan）だけ。GPU ジョブは同時に 1 本。
  参照（Mitsuba）を描いている間は GPU 時間を測らない。
- 数値の要約は `docs/reference/measurements/dynamic-stability/` に置く。
