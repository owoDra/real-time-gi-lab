## 目的

物体が動くときの跳び（太陽が動く分の 5 倍）を、遅れなしに減らす。E7 で、動く物体の遮りと放射を方向ビンの幅で
平均すると、球の跳びが三角形の約 1/4（ボクセルの約 1/5）になった。これを解析的な球ではなく、どの形の動的物体にも
使えるボクセルのレイヤで作る。

## 前提

- Phase 03 の決定（2026-11-14、ユーザー）：RC を続け、遅れ 0 の前置フィルタで跳びを抑える。
- Phase 05 の決定（2026-11-14、AI。技術の選択は AI が決めて報告する）：次は P2 を錐の幅で読む形。その後に P1。
- E7 と切り分けの数値（[spec/30-measurements.md](../../spec/30-measurements.md) の 10、11 節、
  [spec/40-dynamic-stability.md](../../spec/40-dynamic-stability.md)）。

## 決定済みの方針

- 静的な形状はいまの二値の占有のまま。動的三角形だけを別のレイヤに書く（静的ブリックに動的三角形を入れない）。
- 動的レイヤは、ボクセルごとに被覆率と平均放射（物体の表面の平均。1 点の陰影にしない）を持ち、細かい層から粗い層へ
  平均する。E7 で、1 点の陰影のまま錐で平均すると跳びが log2 で 2 倍になったため、放射の平均は必須。
- 区間のレイは、静的な占有を今どおり引いたうえで、動的レイヤをビンの錐の断面に合う層で読み、覆った分は動的レイヤの
  平均放射、残りは静的なトレースの結果で混ぜ、透過率を (1 − 被覆率) 倍する（E7 の解析版と同じ混ぜ方）。
- 平均放射の求め方（物体ごとの表面平均か、ボクセル単位の表面平均か）、被覆率の求め方（ボクセル化の細かさ、
  固定小数の加算など）、錐の断面と層の対応、層の間の補間は実装で決め、最終報告に書く。
- 代表三角形の規則は扱わない（C は 1%）。
- 費用は GI 4 ms と 128 MB の中に収める（いまの既定は 3.4〜3.5 ms、余り約 0.5 ms）。

## 測るもの

各 1 回、1920×1080、静止カメラ、写実の物体、ウォームアップ 60 ＋ 240 フレーム、局所更新、既定の構成
（`world-48-voxel-rc2-vrel`）の前後。超過変動（K = 16、log2 と線形の絶対値）、帯境界ちらつき率、場の平均の放射照度。

| # | シーン | 読むこと |
|---|---|---|
| 1 | `sponza-dynobj-objectsonly`（物体 3 つ） | 物体が動く分。前 0.0650、三角形 0.0348 |
| 2 | `sponza-dynobj-sphereonly`（球だけ） | E7 の解析版（0.0061）とレイ 1 本（0.0107）と比べる |
| 3 | `sponza-dynobj`（物体と太陽） | 両方動く場合 |
| 4 | `sponza-dynobj-sunonly` | 太陽だけ。P2 では変わらないはず（変われば理由を調べる） |
| 5 | `sponza`（静的） | 前後でビット単位で同じ |
| 6 | 費用 | GI の GPU 時間（GPU タイムスタンプ）とメモリ、`sponza-dynobj` で |

遮りの過小と漏れは、物体の真下と陰の床の平均の放射照度を、前（ボクセル）と三角形トレーサの値と比べて見る。

## 判定の目安（測る前に決める）

- **B が取れた**：1 の超過変動が 0.035 以下（三角形と同じ程度）。
- **A と G も取れた**：2 の超過変動が 0.0107 以下（E7 の解析的な球、レイ 1 本より小さい）。0.0061 に近いほど良い。
- **外れ**：1 が 0.050 より大きい（前から 2 割も減らない）か、2 が前（0.0303）より増える。
- **費用**：`sponza-dynobj` で GI が 4 ms 以下、メモリが 128 MB 以下。超えたら目安を満たしても採らない。

## 確かめる決定

| 決定 | 確かめ方 |
|---|---|
| 以前の数値を再現する | 入れる前の 1 と 2 が 0.0650 と 0.0303 |
| 静的なシーンの画像を変えない | `sponza` の静的な放射照度が前後でビット単位で同じ |
| 判定の目安を後から動かさない | 目安を書いたこのファイルを測る前にコミットしている |
| サンプルを増やさない、P1 を作らない | 差分に方向数・タップ数・密度の変更と P1 の実装がない |
| 予算を変えない | 6 の GPU 時間とメモリが 4 ms と 128 MB 以下 |
| 一方にだけ入れた改良で比べない | 列の README に、同じ対策を DDGI 側に入れて比べ直すフェーズ（10）が残っている |
