## 目的

同じ 4 ms での DDGI 系との比べ（Phase 16、review）の材料をそろえる。これまでの比べは静止カメラ、動的物体 3 つ、探索用に
広げた WebGPU の上限、確保メモリ 128 MB 超えの状態だった。比べの結論がこれらの条件で変わらないかを測る。

## 前提

- P1 は既定に入っていない（トークン `p1`）。Phase 13 で読む層の 2 層の補間を試したが、静的な `sponza` の移動カメラのちらつきが
  19.5% で目安（17.0%）を外れた。ちらつきは読む層の粗さで決まる（[spec/30-measurements.md](../../spec/30-measurements.md) の 18 節、
  [spec/40-dynamic-stability.md](../../spec/40-dynamic-stability.md)）。P1 を入れるかは Phase 16 で扱うので、ここでは既定と `p1` の両方を測る。
- 確保メモリは既定 159 MiB、`p1` 178 MiB（使用 48 / 68 MiB）。実行器は `maxStorageBufferBindingSize` などを探索用に広げている
  （`src/native/rc.ts`）。
- 動的レイヤは最大 256 ブリック、3 物体で 112〜116 個、毎フレーム全層を作り直す（0.25 ms）。
- 参照は `box/out/mitsuba/` にある（`sponza`、`sponza-dynobj-f0` など）。新しい場面の参照を描くときは GPU 時間と同時に走らせない。

## 決定済みの方針

- 計測だけ。既定の構成の静的なシーンの画像を変えない（`sponza` の放射照度のビット一致）。新しい指標や場面は足してよい
  （変えたら spec 10 と 30 を更新）。
- RC と DDGI を同じ条件で測る。一方にだけ入れた改良で比べない。予算（GI 4 ms、128 MB）と既存の指標は変えない。
- 診断用のスイッチは、結果を spec に書いたら消す。

## 確かめ方（測る前に決めた。2026-11-14）

すべて探索値。1080p、ウォームアップ 60 ＋ 240 フレーム、空なし（断りがなければ）、`--vox '{"anchor":"scene","local":true}'`、各 1 回
（GPU 時間だけ 3 回）。参照（Mitsuba）は描き直さない（既存の `sponza` 空なしと `sponza-dynobj-f0` の 512 spp × 2 本を使う）ので、
GPU 時間と重ならない。

設定（6 つ）：`world-48-voxel-rc2-vrel`（既定）、`world-48-voxel-rc2-vrel-p1`、`ddgi-75-128-u4-g1-noadapt`（0.75 m 線形）、
`ddgi-75-128-u4-g1-noadapt-p1`、`ddgi-100-128-u2`（RTXGI 既定）、`ddgi-100-128-u2-p1`。DDGI の `-p1` は一方にだけ入れた改良で
比べないための対（RC の `p1` と比べるときに使う）。

### 移動カメラの超過変動（定義。spec 10 にも書く）

- 移動カメラ（既定の経路）で、画素ごとに窓の状態（前フレームの l、窓の始めの l、Σ|Δl|）を、前フレームの再投影先の画素
  （帯境界ちらつき率と同じ判定：最も近い画素、ワールド位置が 2 画素の幅以内、法線の内積 0.9 超）から引き継ぐ。窓はフレーム番号で
  揃えた K = 16 の重ならない窓で、窓の始めのフレームで状態を作り直す。窓の途中で再投影が外れた画素、無効な画素、動的物体の画素
  （いずれかのフレーム）は、その窓を数えない。窓の終わりに Σ|Δl| − |l_end − l_start| を K − 1 で割って画素と窓で平均する（段 / フレーム）。
  l は静止カメラと同じ（log2、下限 10⁻³）。線形の相対値も同じ形で併記する。
- 測定の床：帯境界ちらつき率の対照と同じワールド固定の滑らかな場（法線に依存）を、同じ鎖でたどって同じ量を取る（最も近い画素への
  再投影で鎖が面の上をずれる分と、法線マップの分）。
- 確かめ：静止カメラでも同じ計算を走らせ、既存の静止カメラの K = 16 の値と 5 桁まで一致すること。
- 分布図：最後の窓（フレーム 224〜239）の画素ごとの超過変動を、静止カメラの分布図と同じ色（0.1 段 / フレームで白）で描く。
- 場面：`sponza`（静的。本物の変化は 0）、`sponza-dynobj-sunonly`、`sponza-dynobj`。6 設定すべて。

### 動的物体を増やした場面

- `sponza-dynobj-many<N>`：今の 3 物体（球 半径 0.7 m、輪、人形 1.4 m。写実の材質）の組を N 組。大きさは同じ。組 g（0 始まり）は
  視線の方向へ g × 16 / N m ずらし、奇数の組は左右を反転し、動きは 37 × g フレームずらす（太陽は今と同じに振れる）。
  N = 4（12 物体）と N = 8（24 物体）。
- 測るもの：動的ブリックの数と上限（256）からあふれた数、動的レイヤの作成の費用（`vox` の段。既定の構成では静的なブリックは
  作り直さないので、この段が動的レイヤの作成）、静止カメラの超過変動、GI。上限を 1024 に上げた形（`--vox` の `dynBricks`）でも測り、
  あふれの有無で画像と超過変動がどれだけ変わるかを見る。上限はパラメータとして残す（診断用のスイッチではない）。
- 設定は既定と `p1`、DDGI 0.75 m 線形と RTXGI 既定（各 `-p1` 無し・有り）。

### メモリ

- 数える範囲は今までと同じ（GI の場 + ボクセル + 動的レイヤ + P1。DDGI は DDGI の場 + 同じ 3 つ）。G-buffer、シャドウマップ、計測用の
  バッファは数えない。128 MB は 128 × 10⁶ バイト（122.07 MiB）で判定する（厳しい側）。
- 静的なブリックを 1 回だけ作る形では、作成用の一時バッファ（`vox.rep` 64 MiB、`vox.big` 16 MiB）を作った後に解放する（画像は
  変わらない。恒久の変更）。確保量は、作り終えた後の値と、作っている途中の最大の値を併記する。
- プールを場面に合わせて絞る形（`maxBricks` 12288、`maxVoxels` 1310720。使用は 9546 / 931775）も測る。
- WebGPU の既定の上限（`maxStorageBufferBindingSize` 128 MiB、`maxBufferSize` 256 MiB、`maxStorageBuffersPerShaderStage` 8 など）で
  デバイスを作って全設定を動かす（実行器の `--limits default`）。動けば実行器の既定を既定の上限にし、広げた上限を消す。
- 変わらないことの確かめ：絞った形と既定の上限で、`--dump-irr --static-only` の sha256 が今の既定と同じ（`sponza` 空あり・空なし、
  `sponza-dynobj --pose-frame 0`、既定と `p1`）。超過変動と GI も併記する。

### 参照との誤差

- `sponza`（空なし、Mitsuba sky0 の seed 0 / 1）と `sponza-dynobj --pose-frame 0`（`sponza-dynobj-f0` の 2 本）で、6 設定の
  平均絶対誤差（写実の画素、Σ|ours − ref| / Σref）と偏り（`mise run ref:compare`）。

### 費用

- 予算に近い GI（3.5 ms 以上）は、独立に 3 回、設定を交互に並べて測り、範囲を書く。`sponza-dynobj` の 6 設定、メモリを絞った形の
  既定と `p1`、`sponza-dynobj-many4` / `many8` の既定と `p1`（上限 256 と 1024）。各回の直前に GPU の使用率と GPU を使うほかの
  プロセスを記録する。

### 既定の画像のビット一致

- 実装の前に取った値（実装前の `build/native/rc-before.mjs`、`--dump-irr --static-only`、既定の構成）：`sponza` 空あり
  `b419acfd…`、空なし `9e2d8013…`、`sponza-dynobj --pose-frame 0` `7496723f…`。実装の後に同じ値であること。

### 再現（済、2026-11-14）

18 節と同じ）。GPU は Godot、ブラウザ、エディタと共有（使用率 5%）。
