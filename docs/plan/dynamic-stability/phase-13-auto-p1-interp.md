## 目的

P1 を既定に入れる。Phase 11 で、P1 を入れるとカメラが動くときの静的な場のちらつきが 15.8 → 19.6% に増え、その約 7 割が
読む層の切り替わりと分かった（層を固定すると 16.9%、ただし太陽だけの超過変動は 0.0022 → 0.0030）。錐の幅で層を選ぶ効き目を
保ったまま切り替わりを滑らかにするため、隣り合う 2 層を補間して読む。Phase 12 で `vrel` の判定を軽くし、`p1` の GI は
3.34〜3.52 ms（4 ms までの余り 0.48〜0.66 ms）になった。

## 前提

- 測った値：[spec/30-measurements.md](../../spec/30-measurements.md) の 14〜17 節、要約は
  `docs/reference/measurements/dynamic-stability/` の `phase10-p1-fixed.json`、`phase11-review-p1-cost.json`、`phase12-vrel-cost.json`。
- 決定：[spec/40-dynamic-stability.md](../../spec/40-dynamic-stability.md) の「方向の確認（Phase 11）」と「`vrel` の判定を軽くした（Phase 12）」。
- コード：`src/core/hitrad.ts` の `hitRadiance`（今は `round` で 1 層を選び、向きの合わない層は細かい層へ戻る）と `hrAt`。
  呼ぶのは `src/core/rc.ts` の `voxShade`（RC と DDGI が共有）。
- Phase 12 の GPU は、ブラウザ、エディタ、別の 3D アプリと共有していた。差は交互に測った組の中で読む。

## 決定済みの方針

- 読む層は、錐の幅 w = coneK·t の log2 を連続値のまま使い、隣り合う 2 層（今の下限 `max(Lh, 1)` より細かくしない）の値を
  その小数部で線形に混ぜる。片方の層が向きの外れで読めないときの扱い（もう片方だけを使う、細かい層へ戻る）は実装で決め、
  最終報告に書く。
- 履歴を足さない。サンプルを増やさない。予算（GI 4 ms、128 MB）と評価の指標は変えない。
- P1 は RC と DDGI が共有するトレーサに入れたまま。DDGI 側も同じ形で読み、両方を測る。
- 目安を 1 つでも外れたら既定に入れない（P1 は `p1` のまま 15 へ進む。14 は置かない）。結果を見てから目安を動かさない。
- 画像を変えるフェーズなので、次は built（Phase 14）でユーザーの OK を取る（既定に入れた場合）。

## 目安と確かめ方（測る前にコミット、2026-11-14）

再現（コミット `63d97383`、各 1 回、ウォームアップ 60 ＋ 240、空なし、`--vox '{"anchor":"scene","local":true}'`）：
`sponza-dynobj` の超過変動 既定 0.01192・`p1` 0.00408、GI 静止 / 移動 既定 3.349 / 3.382・`p1` 3.598 / 3.666 ms
（17 節より 0.15〜0.30 ms 遅いが差 +0.25 ms は 17 節の +0.24〜0.30 と同じ。GPU はブラウザ、エディタ、Godot、Wine のゲームと共有、
使用率 9%）。静的な `sponza` の移動カメラのちらつき（写実、細帯）既定 15.774%・`p1` 19.574%。5 桁まで一致。

前 = いまの `p1`（`world-48-voxel-rc2-vrel-p1`、`build/native/rc-before.mjs` に固めた）、後 = 補間版の `p1`。どれも各 1 回、
空なし（リークの部屋だけ空あり）、ウォームアップ 60 ＋ 240、既定の `--vox`。判定は後の値で行う。

| 目安 | シーンと設定 | 判定 |
|---|---|---|
| 太陽が動く分 | `sponza-dynobj-sunonly`、後の `p1` | 超過変動 K = 16 が 0.003 以下 |
| 物体が動く分 | `sponza-dynobj-objectsonly`、後の `p1` | 0.0045 以下 |
| 明るさ | 静的な `sponza` 空なし `--dump-irr`、Mitsuba 512 spp × 2（seed 0, 1、太陽だけ）と `ref:compare` | 平均絶対誤差 0.44 以下 |
| リーク | `leak-0.02` / `leak-0.1`、空あり | 中の明るさ（`meanFractionOfSun`）1.1% / 0.5% 以下 |
| 静止時 | 静的な `sponza` 空なし | 静止カメラのちらつき（細帯）と超過変動 K = 16 が 0 |
| 遅れ 0 | `sponza-dyn-switch200 --response 200,400` | 50% と 90% が 1 フレーム |
| 移動カメラのちらつき | 静的な `sponza` 空なし | 移動カメラ・写実・細帯 17.0% 以下 |
| 費用 | `sponza-dynobj`、前 → 後を 1 組として 3 組（GPU ジョブは 1 本ずつ、参照は描かない） | 後の GI の中央値が 3 組すべて、静止・移動とも 4.00 ms 以下 |
| メモリ | 後の `p1` の summary | 使用（場 + ボクセル + 動的レイヤ + P1）が 128 MB 以下 |

- 明るさの目安の場面：表は `sponza-dynobj-f0` と書いていたが、0.44 は Phase 10 で静的な `sponza`（既定 0.400）から決めた値で、
  Phase 10 もそこで判定した（`sponza-dynobj-f0` では P2 だけで 0.448、13 節）。判定は静的な `sponza` で行い、`sponza-dynobj-f0`
  は前後の差だけを参考に書く（判定に使わない）。参照は描き直さない（`box/out/mitsuba/` にある）。
- DDGI（`ddgi-75-128-u4-g1-noadapt-p1`）も同じトレーサで読むので、`sponza-dynobj-sunonly` の超過変動と静的 `sponza` の参照との
  誤差を前後で測って書く（判定に使わない。Phase 10 と同じ扱い）。
- 規則：9 項目すべてを満たせば `p1` を既定に入れ、次は 14 built。1 つでも外れたら `p1` のまま、次は 15（14 は置かない）。
  結果を見てから目安を変えない。
- 画像：後の静止の間接光、移動カメラのちらつきの分布図、超過変動の分布図、リークの部屋、参照との並びを、数値の前に前と並べて見る。

## やること

1. 再現：17 節の後の既定と `p1` の GI、`p1` の超過変動 0.00408、静的な `sponza` の移動カメラのちらつき（既定 15.774%、`p1` 19.574%）。
2. 目安と確かめ方（シーン、設定名、回数、判定の規則）をこのファイルに書いてコミットする。
3. `hitRadiance` を 2 層の補間にする。画像（静止の間接光、移動のちらつきの分布図、超過変動の分布図）を前と並べて見る。
4. 目安を全部測る（参照との誤差は GPU 時間と別の時間に）。GI は `p1` と補間版を交互に 3 回。
5. 目安を全部満たせば既定に入れる（`DEFAULT_PARAMS.p1`、設定名とトークンの扱い、spec 20 の「既定の構成」）。外れたら `p1` のまま。
6. spec（20、30、40、50）に結果を書き、要約を `docs/reference/measurements/dynamic-stability/` に置き、次のフェーズのファイルを
   作り（既定に入れたら 14 built、入れなければ 15 の条件を広げる計測）、列の表を更新し、このファイルを消す。
