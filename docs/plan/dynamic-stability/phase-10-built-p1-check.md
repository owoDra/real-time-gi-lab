## 目的

P1（ヒット放射の前置フィルタ）を作って測った（Phase 09）。太陽が動くときの跳びは 75% 減ったが、リークと費用で目安を外れ、
既定の構成には入れていない（トークン `p1`）。この built で、ユーザーが実物（画像、連番、数値）を見て、気になる所を挙げる。
最初から一覧の先頭にリークと費用を置き、直して、Phase 09 と同じ目安で測り直し、満たせば既定に入れる。

## 決定済みの方針

- 判定の目安は Phase 09 と同じ（太陽だけ 0.003 以下、物体だけ 0.0045 以下、参照との誤差 0.44 以下、静止時ちらつき 0、リーク
  1.1% / 0.5% 以下、応答 1 フレーム、GI は静止・移動カメラとも 3 回すべて中央値 4 ms 以下、使用メモリ 128 MB 以下）。動かさない。
  直した形を、測る前にこのファイルに書いてコミットしてから 1 回だけ測る。
- 直す所の先頭（AI が決めた順）：
  1. リーク：粗い層（2〜4）の平均に、薄い壁の向こうの同じ向きの面を入れない。候補は、子を平均に入れる前に、親の代表の面
     と子の間が静的な占有で遮られていないか（同じ側にあるか）を一度だけ調べて子の表に印を付けること（形状は静的なので
     毎フレームの費用は増えない。未検証）。
  2. 費用：注入（層 1、15.6 万個 × 16 点、約 0.25 ms）と平均を軽くする。サンプルを増やす方向は試さない。
- 予算（GI 4 ms、128 MB）を変えない。履歴を足さない。P2 の物体の近くの明るすぎは直さない。
- ユーザーに技術の選択を求めない。尋ねるのは見た目が良いか（OK）だけ。

## 確かめる決定

## 直した形（2026-11-14、測る前に書いた。AI 決定）

コードは `src/core/hitrad.ts` と `src/core/rc.ts` の `voxShade`（RC と DDGI が共有）。設定のトークンは `p1` のまま。

- **リーク 1：読むボクセルの向き。** 面の表裏を、読む粗いボクセルの法線ではなく、当たったボクセル自身の法線で選ぶ。読む
  ボクセルの法線が当たった面の法線から 60° より離れていたら、その層を読まずに細かい層へ戻る（どの層もだめなら、P1 の前と
  同じ 1 点の陰影）。屋根の下の壁に横から当たったレイが、角をまたいで屋根の照らされた上面を読んでいた（天井の縁の明るい帯）。
- **リーク 2：交わるボクセル。** 層 1 のボクセルのうち、中の層 0 のボクセルに法線が 60° より離れたものがある（壁と床の交わり、
  角）ものは注入しない。1 つの値では壁の内と外が混ざる（部屋の外の照らされた地面が、内の床に入る）。そこに当たったレイは
  1 点の陰影。一度だけ調べる（Sponza で層 1 の 6%）。
- **暗さ：奥を向いた面を平均に入れない。** 粗い層（2〜4）の平均で、子の面のうち、その向きのすぐ隣（同じ層、法線の主軸）が
  占有されている側は重み 0 にする（形状から一度だけ調べる）。レイがほとんど届かない奥の面まで同じ重みで平均していたことが
  暗さの元だった（探索で、読む層を細かくするほど暗さが減り、層 1 だけなら偏り −11%）。
- **費用：平均を子ごとに 1 スレッド。** 粗い層の平均を、親 1 つに 8 スレッド（子 1 つに 1 スレッド）で読み、先頭が足す。
  交わるボクセルは注入の一覧から外す。注入（層 1、4×4 点）はそのまま。
- 探索値（各 1 回、`sponza-dynobj-sunonly` の超過変動 K = 16、リーク部屋 60 フレーム、静的な `sponza` の参照との比べ）：
  太陽だけ 0.0022、リーク 0.74% / 0.41%、偏り −13.5%、誤差 0.380。費用は前と後を交互に 3 回（`sponza-dynobj`、
  GPU は別のプロセスと共有していた時間を含む）：既定 3.66〜3.78 ms（静止）・3.66〜3.93 ms（移動）、Phase 09 の P1
  3.94〜4.06 / 3.46〜3.96 ms、直した P1 3.96〜4.14 / 3.47〜3.58 ms。注入の 16 点（影の地図を広く読む、約 0.15 ms）が
  上乗せの大半で、点を減らすと跳びが増え（3×3 で 0.0033、2×2 で 0.0040）、1 スレッドに 16 点、四隅を先に引く形、記録の
  前計算は速くならなかった。**今日の機械では、静止カメラの GI が 4 ms を超える見込み。**
- 判定の計測はこのコミットの後に 1 回だけ行う（Phase 09 の表の 1〜9 と同じ条件、目安は動かさない）。

## やること

1. Artifact を作る（前後の画像、分布図、連番、数値、費用）。先頭に悪くなった所と、まだ見ていない条件（移動カメラの超過変動、
   空あり、動的物体の数、広い場面）を書く。ユーザーに平易に報告する。
   **済**（https://claude.ai/artifact/EmeHtnWw39ET5c9BaM2YKv）。一覧はリーク、費用、暗さの順（AI が決めた）。
2. ユーザーの気になる所を一覧にし、リークと費用を先頭に置いて直す。直した形を書いてコミットしてから測る（Phase 09 の表の
   1〜9 と同じ条件）。
3. 同じ URL へ再公開し、AskUserQuestion で OK を取る（選択肢：OK / まだ直してほしい（どこを））。
4. 目安を満たせば `p1` を既定に入れ、spec と要約 JSON に還元する。満たさなければ、直さずに残す分を spec に書き、
   続く Phase 11 の前に方向の確認（review）を置くかを決め直す。
