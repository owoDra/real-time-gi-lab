## 目的

P2 の後に残る跳びの主な分は、太陽が動く分である（太陽だけ 0.0090、物体と太陽 0.0119、物体だけ 0.0030。DDGI 線形は
0.0009〜0.0012）。原因は、ヒット点の太陽の可視性を 1 点で取っていること（D。その可視性を 1 にすると 91% 減る）。
これを、遅れなしに、ヒット放射の前置フィルタで減らす。

## 前提

- Phase 08 の決定（2026-11-14、AI）：RC と遅れ 0 の前置フィルタを続ける。P1 は共有のトレーサに入れ、RC と DDGI を
  同じフェーズで測る（[spec/40-dynamic-stability.md](../../spec/40-dynamic-stability.md) の「方向」）。
- 切り分けと P2、見直しの数値：[spec/30-measurements.md](../../spec/30-measurements.md) の 10、12、13 節。
- 動的物体の上の陰影（G）は P2 で点ごとの陰影の平均にした。P1 の対象は静的なヒット点。

## 決定済みの方針

- 毎フレーム、層 0 の占有ボクセルに直接光（太陽、シャドウマップ、トゥーンは放出側演算子）を注入し、上の層へ平均する。
  静的なヒットは、方向ビンの錐の幅に合う層の放射を読む。形状（占有、一度だけ作る）と放射（毎フレーム）の更新を分ける。
- **注入する太陽の可視性を、ボクセルの中心の 1 点で取らない。** 層 0 のボクセルの広がりで平均する（E7 で、1 点の陰影の
  まま読む幅だけ広げると跳びが増えた。c0 と c1 のレイは層 0 と 1 を読むので、上の層への平均だけでは 1 点の切り替わりが残る）。
  平均の取り方（シャドウマップの何点か、フィルタ済みの深度など）は実装で決め、最終報告に書く。
- **薄い壁の表の光を裏へ回さない。** 粗い層への平均は面の向きを分けて持つ（表裏 2 値か、軸 6 方向かは実装で決める）。
  リーク部屋で確かめる。
- RC と DDGI が共有するヒットの陰影（`voxShade` / `shadeHit` の経路）に入れる。DDGI にだけ、RC にだけ入れない。
- 静的な `sponza` の画像は変わる（ヒット放射の読み方が変わるため）。「静的なシーンの画像を変えない」というこれまでの
  きまりは、このフェーズでは「静止時のちらつき 0 と超過変動 0 を保ち、参照との誤差と偏りを悪くしない」に置き換える。
- 費用は GI 4 ms と 128 MB の中に収める。P2 の後の既定は 3.62〜3.75 ms で、余りは 0.25〜0.4 ms。トレース中の影の参照が
  無くなる分で相殺する見込み（未検証）。収まらなければ、目安を満たしても既定にしない。
- 予算に近い GPU 時間は、独立に 3 回測って範囲を書く。
- 明るさの正しさは参照（Mitsuba）で言う。三角形トレーサはボクセル近似の影響を分ける用途に限る。

## 測るもの

各 1 回（GI の時間だけ 3 回）、1920×1080、静止カメラ、太陽だけ、ウォームアップ 60 ＋ 240 フレーム、既定の構成
（`world-48-voxel-rc2-vrel`、固定窓、P2）の前後。超過変動（K = 16、log2 と線形の絶対値）、帯境界ちらつき率、
場の平均の放射照度。

| # | シーン | 方式 | 読むこと |
|---|---|---|---|
| 1 | `sponza-dynobj-sunonly` | RC | 太陽が動く分。前 0.0090（D を外した上限は 0.0012） |
| 2 | `sponza-dynobj` | RC | 両方動く場合。前 0.0119 |
| 3 | `sponza-dynobj-objectsonly` | RC | 物体だけ。前 0.0030。増えないこと |
| 4 | `sponza-dyn`（トゥーンの物体） | RC | 前 0.0121、ランプの帯の切り替わり 1.40%（対照 1.15%） |
| 5 | 1〜3 と同じ | DDGI 0.75 m 線形、RTXGI 既定、1 m 線形でヒステリシス 0.8 | 前 0.0009〜0.0013（h 0.8 は入れる前も測る）。前置フィルタで低いヒステリシスが使えるようになるか |
| 6 | `sponza`（静的） | RC | 静止時のちらつき 0、超過変動 0。参照との誤差と偏り（前 0.399 / −14%、太陽だけ）。DDGI も併記 |

## 判定の目安（測る前に決める）

- **D が取れた**：1 の超過変動が 0.003 以下。
- **一部**：1 が 0.003 より大きく 0.006 以下。既定に入れ、残りを spec に書く。
- **外れ**：1 が 0.006 より大きい（前から 3 割も減らない）。既定に入れず、負の結果として残す。
- **悪化させない**：3 が 0.0045 以下。6 の誤差が 0.44 以下で、静止時のちらつきと超過変動が 0。7 のリークが
  1.1% / 0.5% 以下（前の 1.5 倍）。8 が 1 フレーム。どれかを外したら既定に入れない。
- **費用**：9 の RC の GI が、3 回とも中央値 4 ms 以下、使用メモリ 128 MB 以下。超えたら目安を満たしても既定に入れない。

## 確かめる決定

| 決定 | 確かめ方 |
|---|---|
| 以前の数値を再現する | 入れる前の 1〜3 が 0.0090、0.0119、0.0030 |
| 判定の目安を後から動かさない | 目安を書いたこのファイルを測る前にコミットしている |
| 可視性を 1 点で取らない、表の光を裏へ回さない | 実装の説明と、7 のリークの値 |
| 一方にだけ入れた改良で比べない | 5 の DDGI の値がある。差分で DDGI も同じヒット放射を読んでいる |
| 遅れを入れない | 8 が 1 フレーム。差分に履歴がない |
| サンプルを増やさない、P2 を直さない | 差分に方向数・タップ数・密度の変更と動的レイヤの読み方の変更がない |
| 予算を変えない | 9 の GPU 時間（3 回）とメモリが 4 ms と 128 MB 以下 |

## やること

1. 再現（画像を先に見る）。入れる前の 4、5（h 0.8）、7 も同じ実行で測る。
2. 実装で決めたこと（注入の可視性の平均、面の向きの持ち方、読む層）をこのファイルに書き、測る前にコミットする。
3. 注入と上の層への平均を作り、ヒット放射を錐の幅に合う層から読む。
4. 表の 1〜9 を測り、分布図とリーク部屋の画像を見て、目安で判定する。
5. spec と要約 JSON に還元し、診断用のスイッチと生の出力を消す。
6. Phase 10（built）のファイルを書く。先頭に、悪くなった所と、まだ見ていない条件（移動カメラ、空あり、動的物体の数）を
   書く形にする。外れのときは、built の代わりに方向の確認（review）を置く。
