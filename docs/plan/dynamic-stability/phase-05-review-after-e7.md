## 目的

E7 で、三角形トレーサでも残る跳びの中身が分かった（角度の点サンプリングは一部）。これを踏まえて、次に何を作るか
（P2 の中身と順番）をユーザーが決める。Phase 03 で決めた方向（RC に遅れ 0 の前置フィルタ）は前提で、ここでは
変えない。変えたいとユーザーが言った場合は、その旨を spec に書き、方向の確認として扱う。

## 前提

- Phase 03 の決定（2026-11-14、ユーザー）：RC を続け、遅れ 0 の前置フィルタ（P2、P1）で跳びを抑える。
- Phase 04（E7）の結果（2026-11-14、探索値、`sponza-dynobj-sphereonly`、静止カメラ、太陽だけ、各 1 回、K = 16 の
  超過変動。数値は spec 30 の 11 節、表は spec 40 の「原因ごとの寄与」）。

## E7 の結果（Artifact に載せる中身）

- 球だけを動かす。三角形 0.0228、球を GI のレイから外す 0.0020、解析的な錐（放射は球の表面の平均）0.0061、
  解析的な球のレイ 1 本（同じ放射）0.0107、ボクセル（既定）0.0303。物体 3 つのとき DDGI 線形は 0.0022。
- 事前に決めた目安で **A（角度の点サンプリング）は一部**：錐にすると、レイ 1 本の解析的な球に比べて残りが 48%
  （線形の絶対値で 45%）。
- 三角形で残る球の分（0.0208）の内訳（差の連鎖、log2 / 線形の絶対値）：解析化そのもの 12 / 19%、物体の表面の 1 点の
  陰影（G）46 / 1%、錐の幅（A）22 / 35%、錐にした後に残る分 20 / 45%（説明できていない）。
- **錐で平均しても、放射を 1 点の陰影のままにすると跳びは増える**（log2 で 2 倍）。遮蔽と放射の両方を、ビンの幅で
  平均したときだけ効く。
- 解析的な錐と表面の平均を両方入れた版（0.0061）は、球だけのボクセル（0.0303）の約 1/5、三角形の約 1/4。
  同じ球の DDGI の値は測っていない。

## 選べる案（準備でまとめ直してよい）

- **P2 を錐の幅で読む形で作る**：動的物体だけの被覆率レイヤに、被覆率と平均の放射を書き、ビンの錐の幅に合う層から
  読む（B、A、G を一度に狙う）。良くなる：E7 の解析版の 0.006 に近づける見込み（未検証。ボクセルの被覆率は解析的な
  球ほど正確ではない）。失う：実装が大きく、錐の幅で読む層の選び方で漏れや遮りの過小が出る恐れ。
- **P2 を被覆率だけで作る（元の案）**：B だけを狙う。良くなる：小さく作れる。失う：A と G が残り、物体だけで三角形並み
  （0.035 前後、DDGI 線形の約 16 倍）が残る見込み。
- **P1 を先に作る**：ヒット放射を層ごとに平均して錐の幅で読む。太陽が動く分（D）に加え、物体の上の 1 点の陰影（G）にも
  効く見込み（未検証）。良くなる：静的な物も含めて放射の前置フィルタが先に入る。失う：G は線形の絶対値では 1% しか
  ないので、見た目の跳びの多くは残る。
- **錐の後に残る分を先に切り分ける（E8）**：上のカスケードのプローブの位置、ボクセルの押し出しと遮蔽判定、区間の奥行き。
  良くなる：説明できていない 20%（線形の絶対値 45%）の正体が分かる。失う：物ができるのが 1 フェーズ遅れる。

AI の推奨は準備で 1 つに絞る（いまの見立て：P2 を錐の幅で読む形。E7 が、遮蔽と放射を同じ幅で平均すれば大きく減る
ことを示したため）。

## 確かめる決定

| 決定 | 確かめ方 |
|---|---|
| 次に作る物はユーザーが決める | AskUserQuestion の回答が会話にある。AI は回答の前に spec を書き換えない |
| 判断できる形で見せる | Artifact に、同じ画角・同じフレームの分布図（三角形、球を外した版、解析的な錐、レイ 1 本、ボクセル）と、内訳の図、各案の見込みと費用が載っている |

| 一方にだけ入れた改良で比べない | 後のフェーズに、同じ対策を DDGI 側に入れて比べ直すフェーズが残っている |
