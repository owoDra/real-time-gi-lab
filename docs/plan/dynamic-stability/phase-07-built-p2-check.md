# Phase 07（built）：P2 の結果をユーザーが見て確かめる

## 開始プロンプト

```
AGENTS.md と docs/plan/README.md と docs/plan/dynamic-stability/README.md と docs/plan/dynamic-stability/phase-07-built-p2-check.md を読み、Phase 06 で入れた P2（動的物体の被覆率と平均放射のレイヤを錐の幅で読む）の結果を、ユーザーが実物で確かめられるようにする。P2 の前（コミット ae259ec4）と後（いまの既定の構成）の同じ画角・同じフレームの画像、超過変動の分布図、物体が動く連番、数値と費用を 1 枚の非公開の Artifact にまとめ、悪くなった所（物体の近くの遮りが弱い）を先頭に書いて、平易に報告する。ユーザーが挙げた気になる所を直して測り直し、同じ URL に再公開し、AskUserQuestion で OK を取って終える。技術の判断は自分で決めて報告する。予算（GI 4 ms、128 MB）は変えない。P1 は作らない。GPU ジョブは同時に 1 本。
```

## 目的

物体が動くときの跳びは数値では 95% 減った。数値が目安に届いたことを OK の代わりにせず、ユーザーが画像と連番で
確かめる。悪くなった所を隠さずに見せ、直すかどうかをユーザーの指摘で決める。

## 前提（Phase 06 の結果、2026-11-14、探索値）

詳しくは [spec/30-measurements.md](../../spec/30-measurements.md) の 12 節、
[spec/40-dynamic-stability.md](../../spec/40-dynamic-stability.md)。

- 超過変動（K = 16、静止カメラ、写実の物体）：物体だけ 0.0650 → 0.0030、球だけ 0.0303 → 0.0023、両方 0.0625 →
  0.0119、太陽だけ 0.0130 → 0.0090。事前の目安（B、A と G）を両方満たした。
- 費用（`sponza-dynobj`）：GI 3.34 → 3.62 ms、使用メモリ計 48 MiB（動的レイヤ 10 MiB）。
- **悪くなった所**：物体の近くの遮りが弱い。姿勢 0 フレームで、球の接地点の床が三角形の 3.5 倍、球の手前の陰の床が
  1.9 倍、輪の下の床が 1.8 倍明るい（P2 の前の二値のボクセルは接地点で 0.2 倍と暗すぎた）。離れた陰の床も 2.8 倍
  （値は小さい）。
- 画像：超過変動の分布図は、手前の床と左右の壁の飽和が消え、物体の接地線のすぐ下に細い帯が残る。球の表面の
  ブロック状のむらが消えた。両方動くときは、太陽による斑が手前の床の中央に残る（P1 の対象）。

## 決定済みの方針

- P2 は既定の構成に入っている。P2 を外すスイッチは無い。前の画像は、コミット `ae259ec4` の実行器を別にバンドルして
  描く（`git stash` か worktree で `src/native/rc.ts` を `build/native/rc-before.mjs` にバンドルする。Phase 06 で
  そうした）。
- P1 は作らない（07 の OK の後、Phase 08）。
- 直すときも、サンプルを増やす方向（方向数、タップ数、プローブ密度）は試さない。予算は変えない。

## 確かめる決定

| 決定 | 確かめ方 |
|---|---|
| 悪くなった所を先頭に書く | Artifact の最初の節が物体の近くの遮り |
| 前後を同じ画角・同じフレームで比べる | 画像の対が同じフレーム番号・同じカメラ |
| 直したら測り直す | 直した版の超過変動（物体だけ、球だけ）と遮りの領域の値を Artifact と spec に書く |
| 予算を変えない | 直した版の GI 時間とメモリが 4 ms と 128 MB 以下 |
| 数値で OK の代わりにしない | AskUserQuestion で OK を取っている |

## やること

1. 前後の画像と連番を描く（GPU ジョブは 1 本ずつ）。
2. Artifact を作って公開し、URL をここに書く。ユーザーに平易に報告する。
3. 気になる所の一覧を作って直す。遮りが弱い件を直すなら、候補は（未検証）被覆率の足し合わせ方と、物体の中に残った
   プローブの扱い（動的レイヤで押し出す、物体の中のプローブを使わない）。直したら 06 と同じ条件で測り直す。
4. AskUserQuestion で OK を取る（選択肢：OK / まだ直してほしい（どこを））。
5. spec に結果を書き、生の出力を消し、Phase 08（P1、auto）のファイルを作り、このファイルを消す。

## 完了条件

- ユーザーの OK がある。
- 直した所があれば、その数値と画像が spec と Artifact にある。
- Phase 08 のファイルがある。
