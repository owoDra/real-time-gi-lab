## 開始プロンプト

```
/goal AGENTS.md と docs/plan/README.md と docs/plan/large-dense/README.md と docs/plan/large-dense/phase-18-auto-dynlayer-cost.md を読み、Phase 18 を最後まで進めてください。動的レイヤの作成を splat の段から軽くし、sponza-dynobj-n64 と -n64-deform で RC 既定の GI を 4 ms 以下（3 回とも）、作成を 0.8 ms 以下にしてください。ブリックがあふれても落とすブリックを決定的に選び、上限は 64 個分を確保してください。最初に Phase 17 の数値（64 物体の作成 3.33〜3.39 ms、超過変動 0.00909、3 物体の 0.01192）を再現し、目安は測る前にコミットしてください。変えた画像は数値の前に見て、見た画像を一覧で示してください。目標か予算に関わる判断は AskUserQuestion で尋ね、技術の判断は自分で決めて最終報告に書いてください。完了の根拠として、コマンドの出力（数値と保存先）、目安ごとの判定、見た画像の一覧、更新した spec の節、コミットのハッシュを会話に示してください。
```

## 目的

ユーザーの目標（動く物体 64 個、変形するメッシュを含む、GI 4 ms・128 MB）に、RC 既定で届かせる。Phase 17 の内訳で多い段から削る。

## 前提（Phase 17、[spec/30-measurements.md](../../spec/30-measurements.md) の 21 節）

- 64 物体（上限 2048）：作成 3.33〜3.39 ms（物体 1 つ 0.052 ms）。splat 2.57〜2.62 ms（77%、小片 128.5 万 = 三角形あたり 2.95、
  1 小片 2.0 ns、1 小片は 8 近傍 × 10 語の原子加算）、resolve 0.57〜0.58 ms（17%、上限の全スレッドを 5 層ぶん起動）、mark 0.11〜0.12 ms
  （訪問 516 万）、clear 0.06 ms。GI は RC 6.34〜6.41 ms、作成を除いて 3.01〜3.07 ms。
- 変形ありは GPU の段が変わらないか約 1 割軽い。CPU で頂点を動かすのに 1 フレーム約 20 ms かかり、GPU がフレームの間で空くためと
  見ている（未検証）。
- ブリックは 64 物体で最大 1241。上限 1536 で動的レイヤ 35.0 MiB、128 MB に入る（計算値）。上限 256 → 2048 で resolve と clear に
  約 0.04 ms の固定費（3 物体）。
- 超過変動 K = 16（RC 既定）：3 物体 0.01192、64 物体 0.00909、64 物体・変形 0.00860。DDGI 線形 0.00086〜0.00094。
- 測り方：`--dyn-stages`（段ごとのパスと CPU での仕事の数え。`src/native/rc.ts` の先頭）。

## 決定済みの方針

- 予算（GI 4 ms、128 MB、作っている途中も含む）と指標は変えない。
- 軽くする順は内訳の多い順：splat → resolve → mark。候補は、小片を 1 ボクセル程度にする（小片を約 3 分の 1 に）、原子加算の語数や
  近傍の数を減らす、resolve と clear を使ったブリックだけに起動する（画像を変えない）、遠い物体を粗い層だけに置く、物体ごとの局所座標の
  ブリック（`legacy/object-local/`）（未検証）。どれをどの順で入れるかは AI が決める。
- ブリックの上限は 64 個分（1241 を入れる 1536 以上）を既定にし、あふれても落とすブリックを決定的に選ぶ（今は原子操作の順で決まり、
  実行ごとに値が変わる）。
- RC と DDGI は同じ動的レイヤを読むので、両方を測る。DDGI 線形は作成を除いて 3.5〜3.7 ms あり、作成を 0.8 ms にしても 4 ms に入らない
  （比べのときに併記する）。
- 変形ありの GPU 時間は、CPU で頂点を動かす待ちのない条件で測る（実行器で頂点の姿勢と変形を GPU の計算パスにする等。GI の時間には
  数えない）。作り方は AI が決める。

## やること

1. 再現。目安（上の表）をこのファイルに書いた状態でコミットする。
   - 済（変更前の実行器、静止カメラ、空なし、60 ＋ 240 フレーム、1 回）：`sponza-dynobj-n64` 上限 2048 の作成 3.30 ms（段の合計、
     `--dyn-stages`。splat 2.549、resolve 0.566、mark 0.115、clear 0.065）、通常の実行の `vox` 3.285 ms、超過変動 K = 16 0.00909
     （通常・段ごと同じ）、`sponza-dynobj` 0.01192。どれも Phase 17 の範囲（作成は ±10%）に入る。
2. 変形ありの GPU 時間を CPU 待ちのない条件で測れるようにする。
3. splat から順に軽くし、段ごとの時間を測る。目安に届いたら止める。
4. 上限を 64 個分にし、あふれたときの落とし方を決定的にする。
5. RC 既定と DDGI 線形で、上の表をすべて測る（GPU 時間は 3 回、前後を交互に）。
6. spec（20 の動的レイヤ、30 に節、40、50）を更新し、要約を `docs/reference/measurements/large-dense/` に置き、Phase 19（built）の
   ファイルを作る。このファイルを消し、列の表を更新する。
