多い場面（R3）を DDGI 系と比べ、P1 の既定入りと多重バウンスを測る。

[spec/30-measurements.md](../../spec/30-measurements.md) の 19〜23 節、全体の順は [spec/50-roadmap.md](../../spec/50-roadmap.md) の 5。

## この列で決めたこと

- 動く物体の目安は 64 個、変形するメッシュを含む（2026-11-14、ユーザー）。
- 64 個で動的レイヤの作成を約 0.8 ms 以下（物体 1 つ約 0.0125 ms）にする。物体なしの GI が約 2.9 ms のため（2026-11-14、Phase 16、AI 決定）。
  Phase 18 で届いた（0.70〜0.76 ms）。見た目はユーザーが確かめた（Phase 19）。64 個の場面は `sponza-dynobj-n64`（格子に置く）と `-n64-deform`。
- ブリックの上限は 1536 を既定にし、あふれても落とすブリックを決定的に選ぶ（粗い層から割り当て、落とした場所は粗い層で読む。Phase 18）。
- 計測では動的物体の姿勢を全フレーム分、計測の前に CPU で計算しておく（Phase 18）。
- P1 は `p1` のまま。既定入りは 64 個を 4 ms に入れた後に測る。多重バウンスはその後（2026-11-14、Phase 16）。

## この列のきまり

- 画像を変える auto を 2 つ続けない。計測だけのフェーズでは、既定の構成（`world-48-voxel-rc2-vrel`、`--vox '{"anchor":"scene","local":true}'`）の
  画像を変えない（`sponza` と `sponza-dynobj --pose-frame 0` の `--dump-irr --static-only` の sha256 で確かめる）。
- RC と DDGI は同じ動的レイヤを読む。動的レイヤを変えたら両方を測る。一方にだけ入れた改良で比べない。
- 明るさの正しさは参照（Mitsuba）で言う。三角形トレーサは参照より暗く、ボクセル近似の影響を分ける用途に限る。
- 予算に近い GPU 時間は 3 回測って範囲を書く。GPU はほかのアプリと共有していることがあるので、前後は交互に測る。
- 動的なシーンのちらつきは本物の変化を含む。超過変動で比べる。ブリックがあふれた場合の値は実行ごとに変わるので、あふれの有無を必ず併記する。
- サンプルを増やす方向（方向数、タップ数、プローブ密度）は試さない。
- 予算は GI 4 ms、128 MB（作っている途中も含む）。変えない。計測はネイティブ（Dawn / Vulkan）だけ。GPU ジョブは同時に 1 本。
  参照（Mitsuba）を描いている間は GPU 時間を測らない。
- 数値の要約は `docs/reference/measurements/large-dense/` に置く。
