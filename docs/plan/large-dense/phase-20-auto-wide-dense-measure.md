## 目的

列の次の目標（R2：GI の時間とメモリが広さにほぼ依存しない、R3：三角形数ではなく表面積と解像度で決まる）に向けて、今の構成が
広い場面と三角形の多い場面でどこで崩れるかを測る。窓のスクロールとストリーミングを作る前の基準にする。

## 前提

- 静的な形状は固定窓（`local`）で最初に一度だけボクセルにする。窓はシーンの中心に固定で、Sponza は層 0 の窓 51 m に入る。
  カメラ相対の窓（`anchor: 'camera'`）は毎フレームの全再構築で動く。窓のスクロールの更新は未実装（spec 20）。
- 場面 `sponza-wide10`（262 万三角形）と `sponza-dense9`（236 万三角形）はある（spec 10）。三角形トレーサの BVH は 128 MiB を超えうる（未確認）。
- 動く物体 64 個で RC 既定の GI は 3.80〜3.94 ms、ユーザーが見た目を確かめた（spec 30 の 22・23 節）。

## 決定済みの方針

- 予算（GI 4 ms、128 MB）と指標は変えない。計測だけで、既定の構成の画像を変えない。
- RC と DDGI は同じボクセルと動的レイヤを読む。両方を同じ条件で測る。
- 予算に近い GPU 時間は 3 回、前後を交互に測る。

## 確かめる決定と、その確かめ方

| 決定 | 確かめ方 |
|---|---|
| 予算と指標を変えない | `docs/spec/10-evaluation.md` と予算の記述が変わっていない |
| 既定の画像を変えない | `sponza` と `sponza-dynobj --pose-frame 0` の `--dump-irr --static-only` の sha256 が前後で同じ |
| 以前の数値を再現する | 最初に 64 物体の RC 既定の GI（3.80〜3.94 ms の範囲）と超過変動 0.00914 を再現する |
| 画像を先に見る | 2 つの場面の間接光と最終画像（固定窓、カメラ窓）を数値の前に見て一覧を示す |
| 広さと密度の内訳 | 両方の窓で GI、ボクセルの作成、メモリ、あふれを表にし、Sponza との比を書く |
| 次のフェーズ | 窓のスクロールで要るもの（毎フレームの差分の量、ストリーミングの単位、メモリ）を書き、次のフェーズのファイルを作る |
