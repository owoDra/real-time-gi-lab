# Phase 17（auto、計測だけ）：動く物体 64 個と変形するメッシュで動的レイヤを測る

## 開始プロンプト

```
/goal AGENTS.md と docs/plan/README.md と docs/plan/large-dense/README.md と docs/plan/large-dense/phase-17-auto-many-objects-measure.md を読み、Phase 17（計測だけ）を最後まで進めてください。動く物体 64 個の場面と変形するメッシュの場面を作り、動的レイヤの作成の段ごとの GPU 時間、動的三角形と小片の数、ブリック数、確保メモリを、物体 3 / 24 / 64 個と変形ありで、RC 既定と DDGI 0.75 m 線形について測ってください。既定の構成の画像は変えず、sha256 で確かめてください。新しい場面は数値の前に画像を見て、見た画像を一覧で示してください。目標か予算に関わる判断は AskUserQuestion で尋ね、技術の判断は自分で決めて最終報告に書いてください。完了の根拠として、コマンドの出力（数値と保存先）、sha256 の一致、見た画像の一覧、更新した spec の節、コミットのハッシュを会話に示してください。
```

## 目的

動く物体 64 個（変形するメッシュを含む、ユーザーの目標）を GI 4 ms に入れるために、動的レイヤの作成のどの段が物体の数に比例して重く
なるかを測る。Phase 18 で軽くする段と目安を、この結果で決める。

## 前提

- Phase 15・16（spec 30 の 19・20 節）：物体 3 / 12 / 24 個で動的レイヤの作成（`vox` の段）は 0.26 / 0.81〜0.88 / 1.35〜1.65 ms、ブリックは
  112〜116 / 368 / 535 個。上限（`VoxParams.dynBricks`、既定 256）を超えると場が跳び、値は実行ごとに変わる。24 個・上限 1024 で GI は
  RC 既定 4.20〜5.08 ms、DDGI 線形 4.50 ms（1 回）。
- 動的レイヤの作り（`src/core/dynlayer.ts` の先頭）：reset、begin、mark（三角形ごとに置く層と触れるブリック）、clear、splat（三角形を約
  半ボクセルの小片に割って 8 近傍へ三線形に置く）、resolve（細かい層から粗い層へ足す）。物体の姿勢は `dynamicSponza`（`src/core/scenes.ts`）の
  回転と平行移動だけで、変形するメッシュの場面は無い。
- `vox` の段の時間には、動的三角形の変換、動的レイヤの作成、`p1` の注入が入っている（段ごとには分けていない）。

## 決定済みの方針

- 予算（GI 4 ms、128 MB）と指標は変えない。計測だけで、既定の構成の画像を変えない。
- 64 個の場面は今の 3 物体の組を増やす形（`sponza-dynobj-many<N>`）を基本にし、変形するメッシュを含めて 64 個にする。変形は毎フレーム
  頂点が動く形（例：球の表面を波打たせる、人形の腕を曲げる）で、トポロジは変えない。作り方は AI が決める。
- 段ごとの時間は GPU タイムスタンプで測る（`--vox-bench` と同じく、計測用の実行で段ごとにパスを分けてよい。そのときは合計が通常の
  `vox` の段とずれないことを確かめる）。

## 確かめる決定と、その確かめ方

| 決定 | 確かめ方 |
|---|---|
| 予算と指標を変えない | `docs/spec/10-evaluation.md` と予算の記述が変わっていない |
| 既定の画像を変えない | `sponza`（空なし）と `sponza-dynobj --pose-frame 0` の `--dump-irr --static-only` の sha256 が変更の前後で同じ（RC 既定、DDGI 線形） |
| 以前の数値を再現する | 最初に `sponza-dynobj` の超過変動 0.01192 と、24 物体・上限 1024 の 0.0111 を再現する |
| 新しい場面は画像を先に見る | 64 個と変形ありの場面の間接光と超過変動の分布図を数値の前に見て、一覧を会話に示す。動的な場面は参照ではなく、場面の物体がフレーム間で動いていることを画像で確かめる |
| 64 個の内訳 | 段（変換、reset、begin、mark、clear、splat、resolve）ごとの GPU 時間を 3 / 24 / 64 個と変形ありで表にし、物体の数・動的三角形・小片の数との比を書く（3 回） |
| ブリックとメモリ | 64 個で要るブリック数と、それを入れる上限での確保メモリ（作っている途中を含む）を書き、128 MB に入るかを書く |
| 次のフェーズの目安 | 内訳から Phase 18 で軽くする段と目安（64 個で GI 4 ms 以下、超過変動、あふれの扱い）を決め、Phase 18 のファイルを作る |

## やること

1. 再現（上の 2 つの値）。
2. 64 個の場面と変形するメッシュの場面を作り、画像を見る。
3. 段ごとの時間を測れるようにし、既定の画像が変わらないことを sha256 で確かめる。
4. 3 / 24 / 64 個と変形ありで、RC 既定と DDGI 線形の GI、段ごとの時間、ブリック数、メモリ、超過変動を測る（GPU 時間は 3 回）。
5. spec 30 に節を足し、spec 40 と 50 を更新し、要約を `docs/reference/measurements/large-dense/` に置き、Phase 18 のファイルを作る。
   このファイルを消し、列の表を更新する。
