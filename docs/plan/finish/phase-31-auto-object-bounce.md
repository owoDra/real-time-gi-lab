## 目的

段階 F。目的 2（トゥーンのキャラが写実の部屋に立ち、互いに照り返す）の主役は動く物体だが、今は多重バウンスの輪の外にいる。

## 前提（[spec 20](../../spec/20-renderer.md)）

- **最初に、空いた機械で今の既定の GI の時間を測る**（Phase 29 の S5。Phase 29・30 とも機械を空けられず、ユーザーの判断で 2026-11-15 にここへ回した）：
  GPU と CPU が空いているのを確かめてから（`gpu_busy_percent` と CPU を使うプロセス）、建物が波打ち物体 64 個の場面で独立 3 回、静止と移動を、ネイティブと
  ブラウザ（`build/native/browser.mjs`、[project-structure.md](../../project-structure.md)）の両方で、交互に測る。空かなければ、空けられるかを AskUserQuestion で尋ねる。
  3 回とも 4.0 ms 以下ならそのまま進む。超えたら（Phase 30 では CPU が使われた状態でブラウザの静止 4.05〜4.12 ms、ネイティブ 3.87〜4.10 ms。
  [spec 30 の 34 節](../../spec/30-measurements.md)）、物を足す前に Phase 29 の既定の費用を下げる（太陽の可視性 `vox.sun` 0.27 ms、ボクセルの段 `vox.voxBits` 0.44 ms：
  spec 30 の 33・34 節）。どちらにしても、この値が O3 の出発点になる。**余裕は 0 か負として計画する**（空いた機械の Phase 28 の値 3.83〜3.88 ms に Phase 29 の差を足した見積もりで 3.8〜3.9 ms）。

- 動的レイヤの放射は直接光だけ（物体に当たったレイは、物体が受けている間接光を返さない）。跳ね返りボリュームの光線は動的物体を見ない
  （物体は跳ね返りの光を遮らない）。
- P2 の物体の近くの床は参照の 1.0〜1.9 倍明るく、球の真下の暗がりが出ない（原因は分かっていない）。
- 動く物体の画素の参照との誤差（8 × 8 ブロック）と偏り（Phase 27、[spec 30 の 31 節](../../spec/30-measurements.md)。参照は多重バウンス 128 spp 1 本、
  `box/out/mitsuba/sponza-dynobj-n64-deform-f0`・`-f100`。DDGI はウォームアップ 2400 フレームで姿勢を止めて収束させた値）：
  `sponza-dynobj-n64-deform` 姿勢 0（太陽が物体に当たる）RC 0.354 / −28%、DDGI 線形 0.526 / −45%。姿勢 100（物体は日陰）RC 0.276 / −17%、DDGI 線形 0.490 / −43%。
  物体 3 つ（`sponza-dynobj` 姿勢 0）RC 0.396 / −32%。参照には物体どうしの色の照り返しと、物体の下と間の床の暖色の照り返しがあり、RC と DDGI のどちらにも無い。
  比べ方：`--pose-frame N --static-only --dump-irr --frames 60`（DDGI は `--warmup 2400` を足す）の後、`ref:compare -- --objects`。
- トゥーンのランプの帯の切り替わり（静止カメラ）：RC 1.26〜2.19%、DDGI 線形 1.03〜1.05%、対照 1.15%（Phase 25）。

## 決定済みの方針

- 作り方は AI が決める。最初の候補（未検証）：動的レイヤの点の陰影に、その点の跳ね返りボリュームの放射照度 × アルベド / π を足す
  （1 フレーム遅れの読み）。跳ね返りボリュームの光線が動的レイヤの被覆率を読む。
- トゥーンの物体は、受けた間接光を放出側の演算子に通さない（演算子は太陽の項だけ。今の決まりを変えない）。
- 余裕に入らない分は入れない。入れる順は「受ける」が先、「遮る」が後。

### 進み具合（2026-11-15、実装の前に書いた）

- **GI の時間（最初）**：機械は空かなかった（winmugen.exe が CPU 約 130%、godot 約 90〜100%。AskUserQuestion でユーザーは「今は空けられない」）。この状態で
  ネイティブ → ブラウザを交互に 3 組（建物が波打ち物体 64 個、空あり、60 ＋ 240 フレーム）：静止 ネイティブ 4.373 / 4.090 / 4.227、ブラウザ 4.333 / 3.604 / 4.230 ms、
  移動 ネイティブ 4.017 / 3.822 / 3.434、ブラウザ 3.304 / 3.292 / 3.858 ms、81.3 MiB。**空いた機械の 3 回は未実行**。O3 は前後を交互に測った差で読み、
  空いた機械での絶対値の判定は未実行と書く。
- **再現**（Phase 30 の実行器、`box/out/p31/base`）：`sponza` 誤差 0.3405 / −15.7%、`town` 0.2204、遅れ 1.317%、`sponza-dynobj` の跳び 0.00554、トゥーンの帯 1.268%（対照 1.151）、
  静止時のちらつき 0、リーク 0.707 / 0.378%、応答 4 / 2。すべて Phase 29 の値を再現した。
- **O1 の「今の値」**：前提の −28% / −17% は Phase 27（Phase 29 の前）の値で、Phase 29 の既定で変わった。今の値は姿勢 0 で物体の画素の偏り −21.85%（8 × 8 ブロックの偏り −22.1%）、
  姿勢 100 で −14.9%（同 −16.2%）。判定は今の値に対して行い、両方の読みで満たすことを求める：**姿勢 0 で |偏り| ≤ 10.9%、姿勢 100 で ≤ 7.45%**（厳しい側）。
- **O2 の参照**：既定は多重バウンスなので、比べる参照は多重バウンスの `box/out/mitsuba/sponza-dynobj-f0/E-b0-…-128spp` の 2 本の平均（前提の 1.0〜1.9 倍は 1 バウンスの参照と
  1 バウンスの実装の値）。今の値は 4 か所（接地点、手前の陰、輪の下、離れた陰）で **0.31 / 0.71 / 0.89 / 1.07 倍**（判定は 0.7〜1.4 倍のまま）。
