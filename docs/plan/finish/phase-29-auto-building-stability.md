## 目的

段階 D の出口。建物そのものが毎フレーム変わっても、場が跳ばず、黒く欠けない（R1、R4）。

## 前提（Phase 28、[spec 30 の 32 節](../../spec/30-measurements.md)、[spec 40](../../spec/40-dynamic-stability.md) の「建物が動くときの跳びと黒い欠け」）

- 跳びの内訳（超過変動 K = 16、法線マップなし、静止カメラ。既定に対する割合）：
  - `town-dynobj-bwave`（0.239）：プローブの押し出し (b) と gather・合成の遮り判定 (c) を止めた形状に固定すると 0.031（−87%）。トレース (d)・跳ね返り (f) は 0〜3%。
  - `sponza-dynobj-n64-deform-bwave`（0.114）：b ＋ c で 0.065（−43%）、さらに d ＋ f で 0.054、さらに太陽を止めて 0.038。残り 0.035 は説明できていない（日の当たる上のアーチ。DDGI にも出る）。
  - `sponza-dynobj-n64-deform-bcut`（0.0345）：形はほぼ効かない（b ＋ c ＋ d ＋ f で −4%）。ヒット点の太陽の可視性を 1 にすると 0.0038（−89%、線形 −92%）、太陽を止めると 0.0075。
    動く太陽で影の地図の格子が動き、ヒット点 1 点の可視性が縁で行き来する分と見ている（見立て）。
- 黒い欠け（8 プローブとも遮られた画素）：`town-grid` 35.8%、`town` 1.48%、建物が波打つ `town` 3.0〜3.7%、`sponza` 3.4%。92〜99% が c（遮り判定の起点から先の線分が、
  面の手前にはみ出した保守的なボクセルに当たる）。gather の遮り判定を外すと暗くなる（`town` 偏り −17 → −28%）ので、判定は残して判定の仕方を変える。
- 短い履歴の見積もり（オフライン、画面の上。c0 にかけるより楽観的）：90% まで 4 フレームで、b ＋ c を止めた波打つ Sponza が 0.065 → 0.032、`town` の既定が 0.239 → 0.089、
  現れて消える場面が 0.0345 → 0.017。履歴だけではどの目安にも届かない。
- 三角形トレーサでも跳びは減らない（波打つ Sponza で 0.182）。ボクセルの近似そのものは直す所ではない。
- 余裕：建物が波打ち物体 64 個の場面で GI 3.83〜3.88 ms（空いた機械、独立 3 回。移動 3.46〜3.51）。余裕は 0.12〜0.17 ms。別のプロセスが CPU を使うと 3.9〜4.2 ms になる
  （APU は CPU と GPU で電力枠を分ける）。測る前に GPU の使用率と CPU を使っているプロセスを見て、前後は交互に測る。

## 決定済みの方針（Phase 28、AI 決定）

1. **ボクセルに面の平面を持たせ、押し出しと遮り判定を平面で決める**（RC）。
   - 占有したボクセルに、代表三角形の平面のボクセル中心からの符号付きのずれを足す（法線と合わせて平面。`resolveAttr` がすでに中心を三角形へ射影しているので、そこで求める）。
     ボクセルごとに 1 語（約 1.3 MB）か、今の 2 語に詰める。粗い層のボクセルは、今の代表の規則（子の代表で最大のもの）と同じ子の平面を持つ。
   - 押し出し（`relocateVox`）：近くの占有したボクセルの平面に対するプローブの符号付き距離で、面から lift × 間隔だけ前へ出す。占有の行進（17 歩）はやめる。
     面が隣のボクセルへ移っても同じ面の平面は連続に動くので、プローブの位置は連続に動く。
   - 遮り判定（gather の `segOccluded`、合成の `linkParents`）：線分のサンプルが占有したボクセルに入ったとき、線分がそのボクセルの中でその平面を横切る（両端が平面の
     両側にある）ときだけ遮ったとみなす。面の手前にはみ出したボクセルは遮らない。起点のずらしと 2 ボクセル先からの再試行は、要らなくなれば外す。
   - DDGI 系はこの 2 つを持たない（押し出しは DDGI 自身の 26 方向の判定、トレースは変わらない）。DDGI 系の値は前と同じになることを確かめる。
2. **ヒットの太陽の可視性を、ボクセルの面の平均にして、ボクセルごとに毎フレーム 1 回だけ求めて持つ**（共有のトレーサ：RC のカスケード、跳ね返りボリューム、DDGI）。
   - 影の地図を描いた後、占有したボクセルごとに、面の平面の上にボクセルの大きさで広げた 2 × 2 点（各点はハードウェアの 2 × 2 比較）の平均を 1 語に書く。
     ヒットは影の地図を引かずにそれを読む。今はヒットごとに 1 回引いている（数百万回）ので、費用は増えないか減る見込み（−0.05〜+0.1 ms、未計測）。
   - サンプルを増やす向きではなく、1 点の可視性を面の平均に置き換える前置フィルタ（P1 の考え方を、層ごとのボクセルの大きさで、層の平均と錐の幅の読みなしに）。
     点の配置と数は最初に決めた 2 × 2 から動かさない（増やして跳びを抑える調整はしない）。
3. **1 と 2 を入れて S2 が届かないときだけ、c0 の放射照度に短い履歴**（RC）。
   - c0 のプローブの SH を、前のフレームの同じ格子点（同じキーと LOD）のプローブの SH と混ぜる。新しいフレームの重み 0.44（90% まで 4 フレーム）。前のフレームに同じ格子点が
     無ければ（最初のフレーム、カメラの切り替え、LOD の切り替え）そのフレームの値。c0 のハッシュと SH を 2 枚持つ（数 MiB）。
   - 静止時のちらつき 0 を保つ（収束した値で SH の f16 への詰め直しが行き来しないこと）。
- 共有のトレーサと形状の表現に入る直しは DDGI 系にも入れて測る。一方にだけ入れた改良で比べない。
- サンプルを増やす方向（方向数、タップ数、プローブ密度）は試さない。

## 確かめる決定と、その確かめ方

| 決定 | 確かめ方 |
|---|---|
| 以前の数値を再現する | 実装の前に S1〜S6 の今の値を再現する。GI の時間は CPU も空いているときに測る |
| 目安を動かさない | 判定の列が実装の前から変わっていない |
| 直しの順と、3 を入れる条件 | 1、2 の順に入れて測り、S2 が届かないときだけ 3 を入れる。各段で S1〜S6 を測り、どの段でどの目安が動いたかを書く |
| 2 の点を動かさない | 2 × 2 点のまま。点を増やして跳びを抑えていない |
| 画像を先に見る（AI の確認） | 前後の並び（静止・移動、`sponza`、建物が変わる 2 場面、`town`、`town-grid`、トゥーンの物体）、建物が変わる連番、超過変動の分布図、黒い画素の分布図、等倍の切り抜き。気付いた悪い所を spec 30 に書く |
| RC と DDGI の両方 | DDGI 線形の S1〜S6 を併記する。1 の後に DDGI の値が変わっていないこと、2 は DDGI にも入っていること |
| あふれ | ブリックのあふれの有無を併記する |

## やること

1. 再現。2. 実装（1 → 測る → 2 → 測る → 要れば 3 → 測る）。3. 画像を見てから目安を測る。4. 平易な報告（良くなった所、まだ悪い所、同じ画角の並べた画像の保存先）。
5. 還元：spec 20、30、40、50、要約。後のフェーズの「今の値」と前提を書き直す。
