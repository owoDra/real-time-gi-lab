## この列で決めたこと

- **途中に人の確認（built）のフェーズを置かない**（2026-11-15、ユーザー）。画像を変えるフェーズは、AI が前後の画像、連番、分布図を自分で見て、
  気付いた悪い所を spec に書き、目安を測り、何が良くなり何がまだ悪いかを平易に報告して終える。ユーザーに尋ねるのは目標と予算、
  最後の結論の後の進め方（Phase 35）だけ。
- 順番の理由（2026-11-15、Phase 26、AI 決定）：建物が動くときの跳びは「完全動的」の定義そのものに対する欠点なので最初。ブラウザは余裕が 0.2〜0.3 ms しか
  なく、割れば後の設計が変わるので、機能を足す前。動く物体の跳ね返りは目的 2 の主役なので広さより前。
- P1 は試さずに消す（Phase 27）。カメラ移動時のちらつきは大半が測り方の見かけだったので独立の段階にせず、指標の直し（Phase 27）と跳びの内訳（Phase 28）に含める。
- 短い履歴は、R1 が許す範囲（応答 90% まで 4 フレーム以内、履歴が無くても破綻しない）でだけ候補にする。DDGI 系の遅い場で補う形は採らない
  （遅れ 26〜45% を持ち込む）。

- 動く物体の跳ね返り（Phase 31、AI 決定）：受けて遮る形は `obj` で選べる形にとどめ、既定に入れない（GI +0.15 ms、空いた機械で 4 ms に入るかを判定できなかった。予算を守る側）。
  余裕ができたら（Phase 32 の作成の費用の削減の後）既定に入れられるかを O3・O4 で測る。
- 広さと密度（Phase 32、AI 決定）：建物が欠けない場面はすべてワールド（区画とまとめた形）として持ち、層 0 のまとめは三角形が半分以下に減る区画だけに使う
  （Sponza では使われず画像は変わらない）。ブリックポインタは 32³（Sponza の既定の画像が少し変わった）。RC の広さ 100 倍が 4.0 ms を超えたのは、窓の中の形が
  Sponza より多い分で、削れる所を試した後なので止める条件に従った。`obj` は余裕ができず（Sponza の作成は下がっていない）既定に入れない。空いた機械で測り直しても広さ 100 倍は 4.42 ms で、ユーザーが限界として閉じると決めた（2026-11-15）。
- WebGL2（Phase 33、AI 決定）：画面の外の光を空と環境の一定値で代える最初の候補は、画面の中の光線が光の約 11% しか運ばず（偏り −36%）採らなかった。太陽から見た RSM で画面の外の
  1 回の跳ね返りを集める形にし、H1〜H3 を満たしたので残す。RSM には遮りが無く、リークと建物が現れて消える跳びが大きいことは限界として書いた。

## この列のきまり

- 一方にだけ入れた改良で比べない。明るさの正しさは参照（Mitsuba）で言う。
- DDGI 系は 1 つの設定ではなく、応答と安定の並び（線形 `ddgi-100-128-u8-g1-noadapt` と、応答の速い `…-u8-h0.5`、`ddgi-150-64-u1-h0.8-g1-noadapt`、
  `ddgi-125-64-u2-h0.5-g1-noadapt`）で比べる。
- 予算は GI 4 ms、128 MB（作っている途中も含む）。変えない。予算に近い GPU 時間は 3 回測って範囲を書き、前後は交互に測る。
- 判定は「建物を含む全形状が同じフレームに変わる」場面で行う（2026-11-14、ユーザー）。
- サンプルを増やす方向（方向数、タップ数、プローブ密度）は試さない。
- 計測だけのフェーズでは既定の構成の画像を変えない（`sponza` と `sponza-dynobj --pose-frame 0` の `--no-sky --static-only --dump-irr --frames 60` の sha256）。
- 計測はネイティブ（Dawn / Vulkan）で行う。ブラウザでの値は節目で確かめる（Phase 30 で、同じ機械ではネイティブと画像も時間も差が見えないと分かった）。自分で起動したブラウザは閉じる。GPU ジョブは同時に 1 本。参照を描いている間は GPU 時間を測らない。
