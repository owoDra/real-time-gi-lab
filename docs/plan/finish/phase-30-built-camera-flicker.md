# Phase 30（built）：カメラ移動時のちらつきの直しを、ユーザーが実物で確かめる

## 開始プロンプト

```
AGENTS.md と docs/plan/README.md と docs/plan/finish/README.md と docs/plan/finish/phase-30-built-camera-flicker.md を読み、Phase 30（built）を進めてください。Phase 29 で入れたカメラ移動時のちらつきの直しについて、前後の移動カメラの連番、ちらつきの分布図、数値、費用を 1 枚のページにまとめて非公開の Artifact に公開し、悪くなった所とまだ見ていない条件を先頭に書いてください。私が気になる所を挙げたら直して測り直し、同じ URL へ再公開してください。最後に AskUserQuestion で OK を取ってください。報告は専門用語の表にせず、何が良くなり何がまだ悪いかを平易に書いてください。
```

## 目的

段階 E の出口。Phase 29 が止める条件で終わった場合は、このフェーズを消す。

## 決定済みの方針

- ページに載せる場面：静的な `sponza`、物体と光が動く場面、トゥーンの物体（ランプの帯）、建物が変わる場面。どれも
  移動カメラの連番で、前後と DDGI 系を並べる。
- 先頭に書くもの：Phase 29 で外れた目安、静止カメラで悪くなった所があればそれ。

## 確かめる決定と、その確かめ方

| 決定 | 確かめ方 |
|---|---|
| 連番で見て、ちらつきが減っている | ユーザーが連番を見る（数値だけで代えない） |
| 直した後に測り直す | 直すたびに Phase 29 の E1〜E3 を測り直して載せる |
| ユーザーの OK | AskUserQuestion（OK / まだ直してほしい（どこを）） |

## やること

1. ページを作って公開する（URL をここに書く）。2. 指摘を直して再公開する。3. OK を取り、spec と列の表を更新する。

## 完了条件

- ユーザーの OK がある。共通の完了定義（[`../README.md`](../README.md)）を満たしている。
