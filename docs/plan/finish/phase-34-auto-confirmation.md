# Phase 34（auto）：確認実験（条件を先に書いて、1 回だけ測る）

## 開始プロンプト

```
/goal AGENTS.md と docs/plan/README.md と docs/plan/finish/README.md と docs/plan/finish/phase-34-auto-confirmation.md を読み、Phase 34 を最後まで進めてください。まず確認実験の条件、比較相手、指標、判定の規則を文書に書いてコミットし、その後で 1 回だけ測ってください。結果を見てから条件や閾値を変えず、測り直しは手続きの失敗（ビルド、設定、スクリプトの不具合）のときだけにしてください。参照を描いている間は GPU 時間を測らないでください。目標か予算に関わる判断は AskUserQuestion で尋ね、技術の判断は自分で決めて最終報告に書いてください。完了の根拠として、条件を書いたコミットのハッシュ、計測のコミットのハッシュ（条件のコミットより後であること）、主張ごとの結果（成立 / 不成立）、保存先、更新した spec の節を会話に示してください。
```

## 目的

段階 I の前半。ここまでの数値はすべて「探索値」。最後に、主張を先に書いて 1 回だけ測り、探索の結論が再現するかを確かめる
（[spec/10-evaluation.md](../../spec/10-evaluation.md) の原則 2）。

## 前提

- 構成は固まっている（段階 D〜H の後）。このフェーズでレンダラを変えない。
- 比較相手は DDGI 系（同じ形状の表現、同じ予算、両方に効く改良は両方に入っている）。

## 決定済みの方針

- 条件の文書は `docs/spec/60-confirmation.md` に置き、計測の前にコミットする。書くもの：主張の一覧、場面、設定（RC と DDGI）、
  フレーム数、回数と順序、指標、判定の規則、測り直してよい場合。
- 主張は、Phase 26 の決定で「優位」と書いたものと、必須要件 R1〜R6 のそれぞれについて 1 つ以上。見立ての一覧（未検証。
  段階 D〜H の結果で書き直す）：
  - 建物が変わり物体 64 個が動く場面で、GI が 4.0 ms 以下、128 MB 以内（R1）。
  - 広さ 100 倍と三角形 10 倍で、GI が Sponza の 1.1 倍 / 1.25 倍以内（R2、R3）。
  - 何も動かない場面で静止時のちらつき 0。光源の切り替えへの応答（Phase 27 で直した指標）が 4 フレーム以内（R1、R4。Phase 29 の c0 の履歴で 4 フレームちょうど）。
  - 応答が 14 フレーム以下の DDGI 系のどの設定よりも、物体が動く跳びと静止時のちらつきが小さい。DDGI 系は 1 つの設定ではなく、
    応答と安定の並び（Phase 26 の表の設定）で比べる。
  - 建物が動く場面の跳びが Phase 29 の到達値（`town` 0.194、波打つ Sponza 0.090、現れて消える 0.017）を再現する（R1、R4）。S1〜S3 は Phase 29 で届かず、残っている限界として書いてある。
    DDGI 系の並びとの比（Phase 29 で DDGI 線形の 2.4〜31 倍）をそのまま書く。
  - リークが DDGI 系より小さい。動く物体の画素の偏りが Phase 31 の O1 を満たす（R5）。
  - ブラウザ（Phase 30 で確かめた機械）で GI が 4.0 ms 以下（R6）。
  - トゥーンの物体のランプの帯の切り替わりが、対照の 2 倍以下（R4、R5）。
  - 参照との誤差、リーク、動く場面の跳びを、DDGI 系と並べて書く（優劣はそのまま書く）。
- 跳びとちらつきは、カメラが動く場面と建物が動く場面では法線マップを外した値で判定する（Phase 27、[spec 10](../../spec/10-evaluation.md)）。応答は姿勢を止めて収束させた終わりの値で測る。
- 場面は、探索で調整に使っていない場面を少なくとも 1 つ含める（Phase 25 の W2 とは別の場面か、別のカメラの道筋）。
- GPU 時間の比べは、独立のプロセスを複数回、AB/BA の順序を釣り合わせ、中立な対照（同じ設定どうし）で最小の検出できる差を
  先に測る。
- 不成立の主張は、不成立と書く。直さない（直すなら Phase 35 で決める）。

## 確かめる決定と、その確かめ方

| 決定 | 確かめ方 |
|---|---|
| 条件を先に書いた | 条件のコミットが計測のコミットより前にある |
| 1 回だけ測った | 測り直した場合は、その理由（手続きの失敗）が書いてある |
| 閾値を動かしていない | `docs/spec/60-confirmation.md` の判定の規則が、条件のコミットから変わっていない |
| 健全性 | 新しい場面は、画像を見て、動く物が見え、フレーム間で変わることを確かめてから測る |

## やること

1. 主張と条件を書いてコミットする。2. 新しい場面の健全性を確かめる。3. 中立な対照を測る。4. 1 回測る。
5. 結果を `docs/spec/60-confirmation.md` に足し、要約を `docs/reference/measurements/finish/` に置く。

## 完了条件

- 主張ごとに成立 / 不成立が書いてある。共通の完了定義（[`../README.md`](../README.md)）を満たしている。
