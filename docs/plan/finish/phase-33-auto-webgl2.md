# Phase 33（auto）：WebGL2 の縮退版を作る

## 開始プロンプト

```
/goal AGENTS.md と docs/plan/README.md と docs/plan/finish/README.md と docs/plan/finish/phase-33-auto-webgl2.md を読み、Phase 33 を最後まで進めてください。WebGL2 で動く、機能を絞った GI の版を作り、WebGPU の版と同じ場面で、何ができて何ができないかを画像と数値で示してください。成り立たないと分かったら、理由を測った値と一緒に書いて終えてください。画像は自分で見て、縮退版を残すかどうかも理由をつけて自分で決め、平易に報告してください。人の確認のフェーズはありません。目標か予算に関わる判断は AskUserQuestion で尋ね、技術の判断は自分で決めて最終報告に書いてください。完了の根拠として、できる事とできない事の一覧、画像の一覧、時間とメモリ、更新した spec の節、コミットのハッシュを会話に示してください。
```

## 目的

段階 H。WebGL2 は「望ましいもの」（必須ではない）。計算シェーダもストレージバッファも無い環境で、同じ考え方の縮退版が
成り立つかを 1 フェーズで確かめる。

## 前提

- spec 20 のティアの表の予定：スクリーン空間のみ ＋ 空・環境のフォールバック、フラグメントパスだけ。
- 分かっていること（WebGPU で測った）：深度バッファだけのトレースは誤差とちらつきが大きい（空ありで +1827%、移動時 42%）。
  スクリーン配置のプローブはワールド格子の約 1.6 倍ちらつく。
- 予算：同じ解像度で 4 ms 以内、機能は縮退（[spec/10-evaluation.md](../../spec/10-evaluation.md)）。

## 決定済みの方針

- 作り方は AI が決める。まず「何を残すか」を 1 つに絞る：スタイル混在（放出側と受光側の演算子）と、近くの照り返しと遮りを
  残し、画面の外の光は空と環境の一定値で代える形を最初の候補にする（未検証）。
- WebGPU の版と同じ品質は求めない。**できない事を一覧で先に書く**ことを成果にする。
- WebGPU の版のコードと既定の画像は変えない。
- 計測は、ネイティブで WebGL2 相当の制限（フラグメントパスだけ、テクスチャだけ）を守った経路を作って行い、WebGL2 そのものは
  ブラウザで動かす（Phase 30 のブラウザの実行器 `src/web/` と駆動 `src/native/browser.ts` がある。作業機の Brave は `scripts/run_with_vulkan.sh` 経由、
  `--browser-flags "--ozone-platform=wayland"` で実 GPU になる。使い終わったブラウザは閉じる）。

## 目安（先に書く）

| # | 目安 | 判定 |
|---|---|---|
| H1 | 時間 | 1080p で 4.0 ms 以下 |
| H2 | 静止時のちらつき | 0（履歴を使うなら、使った長さと応答のフレーム数を書く） |
| H3 | スタイル混在 | トゥーンの物体の照り返しが写実の面に出て、ランプの帯の切り替わりが WebGPU の版の 2 倍以下 |
| H4 | 画面の外の光 | 「できない」と書いてよい。代わりに何が出るかを画像で示す |

## やること

1. 何を残すかを決める。2. 作る。3. 画像を見てから測る。4. 残すかどうかを決める（残す条件：H1〜H3 を満たす）。5. 還元：spec 20（ティア）、30、50、要約。

## 止める条件

H1 か H2 が満たせないとき。測った値と理由を spec に書き、作ったコードを消して段階 I へ進む。

## 完了条件

- 縮退版が動いて一覧があるか、成り立たない理由が spec にある。共通の完了定義（[`../README.md`](../README.md)）を満たしている。
