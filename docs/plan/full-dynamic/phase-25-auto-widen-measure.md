
## 目的

段階 C の前半。2026-11-14 の全体のレビューで、判断の材料が足りないと分かった所をまとめて測る。Phase 26 の比べ直しが、
Sponza・写実の物体・太陽だけ・静止カメラに寄った値で決まらないようにする。

## 前提

- 段階 A・B の後の構成（Phase 22・24 は AI の確認。ユーザーの確認は Phase 26 にまとめる、2026-11-15、ユーザー）。多重バウンスが既定（Phase 23・24）。
  Phase 24 の値：建物が波打ち物体 64 個の場面で RC 3.67〜3.75 ms、`sponza-dynobj` の跳び 0.0113、リーク 0.77 / 0.36%（spec 30 の 28 節）。
- 既定の画像の確かめ：`sponza` と `sponza-dynobj --pose-frame 0` を `--no-sky --static-only --dump-irr --frames 60` で出した sha256 が
  RC e5a44335320fce9c… / 19a21466463c5805…（全桁は `docs/reference/measurements/full-dynamic/phase24-bounce-fixes.json`）。多重バウンスは数フレームかけて
  収束するので、フレーム数を変えずに比べる。
- 多重バウンスの参照は重い（打ち切りなしで 256 spp 1 本 26 分、GPU の計測と重ねると 30 分以上）。`sponza` は 256 spp × 2 本（差 23.5%）、`sponza-dynobj-f0` と
  `sponza-toon` は 128 spp × 1 本だけある。
- DDGI 系の設定は、同じ 4 ms に入る中で最良のものを選び直す（段階 A・B で費用が変わっているため。試した範囲を書く）。Phase 23 の後、
  `ddgi-75-128-u4-g1-noadapt` は建物が変わり物体 64 個が動く場面で多重バウンスを含めて 6.1〜6.5 ms で 4 ms に入っていない（spec 30 の 27 節）。

## 決定済みの方針

- 計測だけ。既定の構成の画像を変えない。診断のためのスイッチ（要素を外す）は、結果を spec に書いたら消す。
- 判定の閾値は置かない。結果の解釈と方向は Phase 26 で決める。
- 新しい場面は健全性チェック（[spec/10-evaluation.md](../../spec/10-evaluation.md)）を通す。
- 一方にだけ入れた改良で比べない。

## 測るもの

| # | 項目 | 測り方 |
|---|---|---|
| W1 | トゥーンの物体が動く場面 | `sponza-dyn`（物体と太陽）と建物が変わる場面にトゥーンの物体を置いたもの。ランプの帯の切り替わり（対照を併記）、写実の画素の超過変動、静止・移動カメラ |
| W2 | Sponza ではない場面 | 1 つ足す（屋内と屋外があり、細い形状と広い面があるもの。入手できる公開の資産か、[legacy/scenes/](../../../legacy/scenes/) の生成器）。静止・移動カメラ、物体と光が動く形。GI、メモリ、あふれ、ちらつき、超過変動、参照との誤差。Sponza に合わせたプールの大きさがそのまま使えるかを書く |
| W3 | 参照のノイズを下げる | 独立な 2 本の差を、RC と DDGI の誤差の差より小さくする（目安：差 5% 以下）。静的な `sponza`、`sponza-dynobj` 姿勢 0、W2 の場面。1 バウンスと多重バウンスの両方。画素ごとの差を 5% にするには多重バウンスで 1 本 9 時間以上かかる見積もりなので、比べ方（ブロック平均での誤差など）も AI が決め、決めた比べ方で RC・DDGI の誤差を出し直す |
| W4 | カメラ移動時のちらつきの切り分け | 静的な `sponza`、移動カメラ（RC 18.0%、DDGI 18.2%、測定の床 4.0% が最後の値。Phase 21 で層 0 を 0.2 m にして RC 15.8 → 18.0%）。要素を 1 つずつ外して寄与を測る：プローブの登録の変化（カメラで変わる LOD とハッシュの登録）、押し出しと遮り判定、法線マップ、再投影の半画素のずれ。移動カメラの超過変動の測定の床も、この切り分けで決める |
| W5 | 応答の並べた連番 | 光源の切り替えと、建物が変わる瞬間（壁が現れる・消える）の前後 16 フレームを、RC と DDGI で同じ画角・同じフレームに並べる。応答のフレーム数と、動いている途中の遅れ（姿勢を止めて収束させた値との差）を添える |
| W6 | 広さと密度 | `sponza-wide10-bwave` と `sponza-dense9-bwave` を今の構成で測る（Phase 20 の値との前後：層 0 が 0.2 m で RC 4.86 / 4.27 ms。Phase 21 で粗い層の作り方と c0 間隔の下限が変わったので、最初に測り直す）。GI、メモリ、あふれ、画像。カメラが大きく動くときのフレーム時間の跳ね（最大値と 99% 値）。広さ 10 倍は Sponza に合わせたプールではあふれる（0.2 m で 5512 ブリック要る）ので、要るプールと確保を書く。DDGI の固定格子は広さ 10 倍で 128 MiB の上限を超えて動かない（Phase 20）ので、DDGI は「動かない」と書く（カメラに付く体積は Phase 27） |

## 確かめる決定と、その確かめ方

| 決定 | 確かめ方 |
|---|---|
| 既定の画像を変えない | `sponza` と `sponza-dynobj --pose-frame 0` の `--dump-irr --static-only` の sha256 が前後で同じ |
| 以前の数値を再現する | 最初に Phase 24 の時点の目安（M1 3.67〜3.75 ms、M5 0.0113）を再現する |
| 画像を先に見る | W1、W2、W5、W6 の画像を数値の前に見て一覧を示す |
| DDGI の設定を選び直している | 試した間隔、レイ数、更新の割合、時間混合の範囲と、選んだ設定の GI ms を書く |
| 参照と GPU 時間を重ねない | 時間帯を分けたことを書く |

## やること

1. 再現。DDGI の設定を選び直す。
2. W1〜W6 を測る（参照の描き直しは時間がかかるので、GPU 時間の計測の後にまとめて流す）。
3. 還元：spec 10（場面、参照のサンプル数）、spec 30（節）、spec 50（残っている課題の更新）、要約を
   `docs/reference/measurements/full-dynamic/`。Phase 26 のファイルの「比べる材料」に、測った値と画像の場所を書く（画像は `box/in/phase25-check/`）。
