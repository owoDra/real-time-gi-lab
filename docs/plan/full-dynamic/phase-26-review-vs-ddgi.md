## 後半：比べ直し（review）

## 前提

- Phase 16 の比べ（2026-11-14）では優位が割れていた：応答、遅れのなさ、静止時のちらつき 0、GI の軽さは RC。静的な誤差と
  動く場面の安定は DDGI 系。カメラが動くときのちらつきはほぼ同じ。
- Phase 25 の W1〜W6。

## 決定済みの方針

- 判定は [spec/50-roadmap.md](../../spec/50-roadmap.md) の「続けるための条件」の 2 つで行う：(1) 完全動的な Sponza（建物、物体、
  光源が動く）で GI が 4 ms に入るか、(2) 同じ 4 ms で、品質（参照との誤差、ちらつき、リーク）か対応範囲（応答、履歴なしでの
  破綻のなさ）に優位があるか。
- 優位の読み方を先に決めておく：
  - 参照との誤差の差は、参照自身のノイズ（W3 の後の値）より大きいときだけ「差がある」と書く。
  - ちらつきは、静止カメラと移動カメラを分けて書き、移動カメラは W4 で決めた測定の床を引いて読む。
  - 応答と遅れは、フレーム数だけでなく W5 の連番で、目で見て分かる差かを書く。
  - スタイル混在（W1）で DDGI 系より悪ければ、目的 2 に対する欠点として先頭に書く。
- 中止と方向転換は正当な結果である。

## 選べる案（決める前に、測った値で各案の「何が良くなり、何を失うか」を書く）

| 案 | 内容 |
|---|---|
| 続ける | RC を土台に、仕上げの列（広さと密度、カメラ移動時のちらつき、P1 の最後の判定）へ進む |
| 組み合わせる | RC の遅れのない場を主にし、弱い所（動く場面の安定か静的な誤差）だけ DDGI 系の遅い場で補う形を試す（1 フェーズ足してから仕上げへ） |
| 土台を変える | DDGI 系を土台にし、RC で分かったこと（動的レイヤ、前置フィルタ、全形状を毎フレーム作る形状の表現）を持ち込む |
| 中止 | 優位が無く、道も見えないとき。分かったことをまとめて終える |

## 確かめる決定と、その確かめ方

| 決定 | 確かめ方 |
|---|---|
| 条件を 2 つとも判定している | spec 50 の「続けるための条件」に、日付つきで「当たる / 当たらない」と根拠の数値がある |
| 一方にだけ入れた改良で比べていない | 比べた設定の一覧（RC、DDGI の両方に入っている改良）をページに載せる |
| 画像で比べている | 同じ画角・同じフレームの並べた画像と連番がページにある |
| ユーザーに選ばせていない | 報告は決めた案と理由。ユーザーが変えたいと言えば従う |
| 後の計画を書き直している | [`../finish/`](../finish/README.md) の各ファイルが決めた方向と合っている（合わないファイルは消すか書き直す） |
