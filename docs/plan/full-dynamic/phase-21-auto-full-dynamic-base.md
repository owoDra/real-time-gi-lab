# Phase 21（auto）：建物を含む全形状を毎フレーム作る土台を 4 ms に入れる

## 開始プロンプト

```
/goal AGENTS.md と docs/plan/README.md と docs/plan/full-dynamic/README.md と docs/plan/full-dynamic/phase-21-auto-full-dynamic-base.md を読み、Phase 21 を最後まで進めてください。Phase 20 で決めた作り方（このファイルの「決定済みの方針」）で、建物を含む全形状を毎フレーム作り直す形を既定の構成にし、建物が毎フレーム変わり物体 64 個が動く場面で GI を 4.0 ms 以下、確保メモリを 128 MB 以内にしてください。目安はこのファイルに先に書いてある数値で判定し、結果を見てから変えないでください。RC と DDGI の両方を測ってください。前後の画像は数値の前に見て、見た画像を一覧で示してください。目標か予算に関わる判断は AskUserQuestion で尋ね、技術の判断は自分で決めて最終報告に書いてください。後のフェーズの前提が変わったら、後のフェーズのファイルを書き直してください。完了の根拠として、目安ごとの数値（3 回の範囲と保存先）、見た画像の一覧、良くなった所と悪くなった所、更新した spec の節、書き直した後のフェーズのファイル、コミットのハッシュを会話に示してください。
```

## 目的

段階 A の本体。「最初に一度だけ作る」前提を外し、建物を含む全形状が同じフレームに変わっても予算に入る構成を既定にする。

## 前提

- Phase 20 の棚卸し表と、決めた作り方（[spec/30-measurements.md](../../spec/30-measurements.md) の Phase 20 の節）。
- 建物が変わる場面（Phase 20 で作った 2 つ。物体 64 個と組み合わせたもの）。
- 「前」の画像を描くための実行器を、実装の前に `build/native/rc-before.mjs` へ写しておく。

## 決定済みの方針

- **作り方**：（Phase 20 が書く。決めた案、理由、棚卸し表での見込みの ms）
- 出口の判定は「全部が同時に変わるフレーム」で行う。変わっていない所を省く工夫は足してよいが、判定の場面では効かない
  ことを確かめる（建物の全頂点が毎フレーム動く場面で測る）。
- 予算（GI 4 ms、128 MB。作っている途中も含む）と指標は変えない。サンプルを増やす方向は試さない。
- RC と DDGI は同じ形状の表現を読む。両方を測る。
- 既定の構成の名前と `--vox` の既定が変わる。変えたら [spec/20-renderer.md](../../spec/20-renderer.md) を同じ変更で書き直し、
  使わなくなった経路（一度だけ作る固定窓など、要らなくなった物）は消す。

## 目安（先に書く。結果を見てから変えない）

「今の値」は Phase 20 が再現した値に置き換える。許す悪化の割合はここで決めてあり、Phase 20 は変えない。

| # | 目安 | 条件 | 今の値 | 判定 |
|---|---|---|---|---|
| G1 | GI の GPU 時間 | 建物が毎フレーム変形し、物体 64 個（変形を含む）が動く場面。静止カメラと移動カメラ、独立 3 回、前後を交互 | （Phase 20 が測る。見立て 約 5.6 ms） | 3 回とも中央値 4.0 ms 以下 |
| G2 | 同上、トポロジが変わる場面 | 建物の一部が現れて消える場面 ＋ 物体 64 個 | （同上） | 3 回とも 4.0 ms 以下 |
| G3 | 確保メモリ | G1 の場面、作っている途中を含む | 80.8 MiB（建物を一度だけ作る形） | 128 MB 以内 |
| G4 | 静止時のちらつき | 何も動かない `sponza`、静止カメラ | 0 | 0 |
| G5 | 跳び（超過変動 K = 16） | `sponza-dynobj`、静止カメラ / 物体 64 個 | 0.0119 / 0.00914 | 1.1 倍以下（0.0131 / 0.0101） |
| G6 | 参照との誤差と偏り | 静的な `sponza`、Mitsuba | 0.400 / −14.5% | 誤差 0.42 以下、偏り −20% 〜 0% |
| G7 | リーク | 閉じた部屋、壁 2 cm / 10 cm | 0.74 / 0.31% | 1.1 倍以下（0.81 / 0.34%） |
| G8 | 建物が変わらない場面の GI | `sponza-dynobj-n64-deform` | 3.80〜3.94 ms | 4.0 ms 以下（軽くなる必要はない） |

G1〜G4 と G8 は必須。G5〜G7 のどれかが外れたら、既定には入れるが Phase 22 のページの先頭に「悪くなった所」として書き、
直せるものは Phase 22 で直す。

## 確かめる決定と、その確かめ方

| 決定 | 確かめ方 |
|---|---|
| 予算と指標を変えない | `docs/spec/10-evaluation.md` の予算と指標の記述が変わっていない |
| 以前の数値を再現する | 実装の前に、G5〜G8 の「今の値」を再現する |
| 目安を動かさない | 上の表の判定の列が、コミットの履歴で実装の前から変わっていない |
| 全部が変わるフレームで測っている | G1 の場面で、建物の全頂点が毎フレーム動いていること、作り直しを省く経路が働いていないことをカウンタで示す |
| 画像を先に見る | 前後の間接光と最終画像（静的、物体 64 個、建物が変わる 2 場面、移動カメラ）を数値の前に見て一覧を示す |
| RC と DDGI の両方 | DDGI 0.75 m 線形でも G1、G5、G6 を測る |

## やること

1. 再現と、`rc-before.mjs` の用意。
2. 実装。段ごとの時間を見ながら進める（`--dyn-stages` と同じ形の段ごとの計測を、新しい作り方にも用意する）。
3. 画像を見てから、目安を測る。
4. 還元：spec 20（構成）、spec 30（節を足す）、spec 50（現在地、続けるための条件の 1 つ目）、要約を
   `docs/reference/measurements/full-dynamic/`、Phase 22 のファイル（前後の画像の場面、悪くなった所の一覧）を更新する。
   後のフェーズ（23 以降）の前提が変わったら、そのファイルも書き直す。

## 止める条件

G1 か G2 が、決めた作り方を作り切っても 4.3 ms を超えたまま、削れる所の見込みが残っていないとき。その場合は既定に入れず、
作った物を設定のトークンで残して測った値を spec に書き、Phase 22 を review に差し替える（選べる道：品質を落とす、1 フレームに
作り直す量に上限を置く、土台を変える、中止）。4.0〜4.3 ms のときは、このフェーズの中で削る所を探し続ける。

## 完了条件
