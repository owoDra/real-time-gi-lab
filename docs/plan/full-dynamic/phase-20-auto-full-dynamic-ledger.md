## 目的

段階 A（[README.md](README.md)）の最初。「建物を含む全形状が毎フレーム変わる」という目的（2026-11-14、ユーザー）に対して、
今の構成がどれだけ 4 ms を超えているかを段ごとに測り、どこを削れば入るかを表にして、土台の作り方を 1 つ決める。
作るのは次のフェーズ（21）で、このフェーズは既定の画像を変えない。

## 前提

- 既定の構成は、建物（静的な三角形）を固定窓で最初に一度だけボクセルにする（`anchor: 'scene'`、`local: true`）。
  カメラ相対の窓（`anchor: 'camera'`、`local: false`）は毎フレームの全再構築で動く（[spec/20-renderer.md](../../spec/20-renderer.md)）。
- 全再構築は Sponza 1.89 ms、広さ 10 倍 4.16 ms、三角形 9 倍 3.63 ms（[spec/30-measurements.md](../../spec/30-measurements.md) の 3 節。
  その後の変更を入れた今の値は未計測）。
- 物体 64 個で、動的レイヤの作成は 0.70〜0.76 ms（動的三角形 43.4 万）、RC 既定の GI は 3.80〜3.94 ms、うち作成を除いた分は
  約 3.0 ms（22 節、21 節）。
- 足し算の見立て（未計測）：場 約 3.0 ms ＋ 全再構築 1.9 ms ＋ 動的レイヤ 0.7 ms ＝ 約 5.6 ms。4 ms まで約 1.6 ms 足りない。
  多重バウンス（段階 B）の分はまだ入っていない。
- 全再構築で動的三角形がどう扱われるか（動的レイヤへ入るか）、全再構築を毎フレーム回したときの確保メモリ（作成用の
  一時バッファは解放できない）は、コードで確かめる。

## 決定済みの方針

- 予算（GI 4 ms、128 MB。作っている途中も含む）と指標は変えない。計測だけで、既定の構成の画像を変えない。
- 出口の判定は「全部が同時に変わるフレーム」で行う。変わっていない所を省く工夫は候補に入れてよいが、それだけで
  4 ms に入る案は採らない。
- RC と DDGI は同じボクセルと動的レイヤを読む。両方を同じ条件で測る。
- 予算に近い GPU 時間は 3 回、前後を交互に測る。
- サンプルを増やす方向は試さない。品質を落として時間を作る候補（層 0 を粗くする、P を上げるなど）は、参照との誤差、
  リーク、ちらつきを一緒に測って棚卸し表に書く。

## 確かめる決定と、その確かめ方

| 決定 | 確かめ方 |
|---|---|
| 予算と指標を変えない | `docs/spec/10-evaluation.md` の予算と指標の記述が変わっていない（場面の行を足すだけ） |
| 既定の画像を変えない | `sponza` と `sponza-dynobj --pose-frame 0` の `--dump-irr --static-only` の sha256 が前後で同じ |
| 以前の数値を再現する | 最初に 64 物体の RC 既定の GI（3.80〜3.94 ms の範囲）と超過変動 0.00914 を再現する |
| 動く場面の健全性 | 建物が変わる場面で、画像がフレーム間で変わること（建物の画素が変わること）を生成時に assert し、建物の変化がカメラから見えていることを画像で確かめる |
| 画像を先に見る | 新しい場面と、広さ 10 倍・三角形 9 倍の間接光と最終画像を数値の前に見て一覧を示す |
| 棚卸し | 段ごとの今の ms、要る機能、削れる候補と測った見込みを 1 つの表にし、合計が 4 ms に入る組み合わせがあるかを書く |
| 次のフェーズ | 作り方を 1 つ決め、理由を書き、品質の目安の数値を先に書いた Phase 21 のファイルを作る（道が無ければ review のファイルにする） |

## やること

1. **再現**。上の表の値と sha256。
2. **建物が変わる場面を作る**（`src/core/scenes.ts`、[spec/10-evaluation.md](../../spec/10-evaluation.md) に行を足す）。少なくとも次の 2 つ。
   どちらも物体 64 個（`sponza-dynobj-n64-deform` と同じ物体）と組み合わせられるようにする。
   - 建物が毎フレーム変形する（トポロジは同じ。たとえば柱や壁が波打つ）。
   - 建物の一部が現れたり消えたりする（トポロジの変化。たとえば壁や床の一部が数十フレームごとに入れ替わる）。
   建物の頂点を毎フレーム書き換える経路が無ければ作る（CPU の時間は GI に数えない。姿勢は計測の前に計算しておく）。
3. **今の姿を測る**。全形状を毎フレーム作り直す形（カメラ相対の窓の全再構築）で、RC 既定と DDGI 0.75 m 線形。場面は
   `sponza`、`sponza-dynobj-n64-deform`、2 の場面（物体 64 個あり）、`sponza-wide10`、`sponza-dense9`。測るもの：GI の合計と
   段ごと（ボクセルの作成、動的レイヤ、押し出し、トレース、合成、gather）、確保メモリ、ブリックのあふれ、静止カメラの
   ちらつき（建物が変わらない場面で 0 のままか）、超過変動、画像。予算に近い値は 3 回。
4. **棚卸し表を作る**。行は段、列は「今の ms」「全部が変わるフレームで要る ms」「削れる候補と測った見込み」。多重バウンスの
   分は見立て（未検証と書く）で 1 行入れ、余裕 0.2 ms も 1 行入れる。
5. **候補を小さく試して 1 つ決める**（試した実装は既定に入れず、決めた後に消すか Phase 21 で作り直す）。候補（どれも未検証。
   ほかの案を足してよい）：
   - 建物の三角形も、Phase 18 で軽くした動的レイヤと同じ作り方（並べ替えた三角形を窓ごとに配る）で毎フレーム作る。
     二値のブリックと動的レイヤを 1 つの作り方にまとめる。
   - 層ごとに作り直す範囲を変える（細かい層はカメラの近くだけ、粗い層は細かい層からまとめて作る）。
   - 場の側を軽くして作成の時間を作る（画素ごとの遮り判定 約 0.67 ms、押し出し）。面の表裏を持つ占有にすれば判定が
     要らなくなる見立て（未検証）。
   - 変わっていないブリックの作り直しを省く（全部が変わるフレームの費用は下がらないので、これだけでは採らない）。
6. **還元**。spec 30 に節を足し、spec 10（場面）、spec 20（確かめた挙動）、spec 50（現在地、続けるための条件の 1 つ目の値）、
   列の表を更新し、要約を `docs/reference/measurements/full-dynamic/` に置き、Phase 21 のファイルを作る。Phase 21 の
   ファイルには、段階 A の出口（[README.md](README.md)）に加えて、品質の目安を数値で先に書く：静止カメラ・変わらない場面の
   ちらつき 0、`sponza-dynobj` の超過変動、静的な `sponza` の参照との誤差と偏り、リーク（2 cm / 10 cm）。それぞれ、
   このフェーズで再現した今の値からどこまでの悪化を許すかを決めて書く。

## 止める条件

棚卸しで、どの候補の組み合わせでも「全部が変わるフレームで 4 ms」に届く見込みが立たないとき。その場合は Phase 21 を
review のファイルにして、選べる道（品質を落とす、1 フレームに作り直す量に上限を置いて残りを次のフレームへ回す、土台を
変える、中止）を比べる材料をそろえる。目的か予算を変える必要があると見たら AskUserQuestion で尋ねる。
