# 作業計画：完全動的（建物を含む全形状が毎フレーム変わる）

進め方、プロンプトの使い方、共通の完了定義は [`../README.md`](../README.md)。

2026-11-14 の見直し（別のモデル（Claude Fable）による全体のレビュー）で、ユーザーが目的を確かめた：
**「完全動的」は、建物そのもの（今「静的」と呼んでいる形状）が毎フレーム変わる場合まで含む。** 今の既定の構成は建物を
最初に一度だけボクセルにしていて、建物が変わると全再構築（Sponza で 1.9 ms）が要り、GI は 4 ms に入らない
（場の約 2.9 ms ＋ 全再構築 1.9 ms ＋ 物体 64 個の動的レイヤ 0.7 ms）。Phase 20（2026-11-15）で通しで測ると、建物が毎フレーム
変わり物体 64 個が動く場面で RC 5.7〜6.7 ms、層 0 のボクセルを 0.2 m にした形で 3.6〜4.0 ms（[spec/30-measurements.md](../../spec/30-measurements.md) の 24 節）。
大規模・高密度の列は閉じ、この列を始めた。全体の順と理由は [spec/50-roadmap.md](../../spec/50-roadmap.md)。

ブランチは `p2`。数値の要約は `docs/reference/measurements/full-dynamic/` に置く。

## 段階と出口

段階は 3 つ。段階ごとに出口の条件が 1 つあり、出口に関係しない作業はこの列に入れない（気付いた課題は
[spec/50-roadmap.md](../../spec/50-roadmap.md) の「残っている課題」に 1 行足すだけにする）。

| 段階 | 問い | 出口の条件 | フェーズ |
|---|---|---|---|
| A 土台 | 建物を含む全形状が毎フレーム変わっても、4 ms・128 MB に入るか | Sponza の規模で、建物が毎フレーム変わり（変形とトポロジの変化）、物体 64 個（変形を含む）が動く場面で、GI が独立 3 回とも 4.0 ms 以下、確保メモリが作っている途中を含めて 128 MB 以内、品質の目安（Phase 20 が Phase 21 のファイルに先に書く）を満たし、ユーザーが画像を見て OK | 20〜22 |
| B 多重バウンス | 多重バウンスを入れても 4 ms に入り、見た目が良くなるか | RC と DDGI の両方に入り、参照も多重バウンスで描き直してあり、段階 A の場面で GI が 4.0 ms 以下、ユーザーが画像を見て OK | 23〜24 |
| C 比べ直し | 本当の条件で、DDGI 系に対して優位があるか | 継続・方向転換・中止を決めて報告している（[spec/50-roadmap.md](../../spec/50-roadmap.md) の「続けるための条件」の 2 つを判定し直す） | 25〜26 |

段階 A の出口に届く道が無いと分かったら（Phase 20 の棚卸しか Phase 21 の結果で）、次のフェーズを review に差し替えて
方向を決める。予算（4 ms、128 MB）と目的は AI が変えない。変える必要があると見たら AskUserQuestion で尋ねる。

## この列で決めたこと

- 「完全動的」は建物そのものが毎フレーム変わる場合まで含む（2026-11-14、ユーザー）。「最初に一度だけ作る」ことを前提にした
  構成は、出口の判定に使わない。変わっていない所の作り直しを省く工夫は使ってよいが、**全部が同時に変わるフレームでも
  4 ms に入る**ことを出口の条件にする。
- 動く物体 64 個（変形するメッシュを含む）の目標は変えない（2026-11-14、ユーザー）。
- 多重バウンスは広いワールドより前に入れる（2026-11-14、見直し、AI 決定）。見た目を最も変え、DDGI 系には仕組み上ほぼ
  無料で入るので、比べ直しの前に両方へ入れる。
- P1 は `p1` のまま、段階 C の後まで触らない。
- 土台の作り方（2026-11-15、Phase 20、AI 決定）：建物と物体を含む全形状をカメラに付いた窓で毎フレーム作り直し、層 0 のボクセルを
  0.2 m にする。測った候補でこれだけが判定の場面を 4 ms に入れ、品質は目安の中、メモリも下がる（spec 30 の 24 節）。
- 建物が変わる場面は場面名の末尾 `-bwave`（全頂点が毎フレーム動く）と `-bcut`（一部が現れて消える）。判定は物体 64 個と組み合わせた
  `sponza-dynobj-n64-deform-bwave` と `-bcut` で行う。

## この列のきまり

- 画像を変える auto を 2 つ続けない。計測だけのフェーズでは、既定の構成（`world-48-voxel-rc2-vrel`、
  `--vox '{"anchor":"scene","local":true}'`）の画像を変えない（`sponza` と `sponza-dynobj --pose-frame 0` の
  `--dump-irr --static-only` の sha256 で確かめる）。
- RC と DDGI は同じボクセルと動的レイヤを読む。形状の作り方を変えたら両方を測る。一方にだけ入れた改良で比べない。
- 明るさの正しさは参照（Mitsuba）で言う。
- 予算に近い GPU 時間は 3 回測って範囲を書く。GPU はほかのアプリと共有していることがあるので、前後は交互に測る。
- 動的なシーンのちらつきは本物の変化を含む。超過変動で比べる。ブリックのあふれの有無を必ず併記する。
- サンプルを増やす方向（方向数、タップ数、プローブ密度）は試さない。
- 予算は GI 4 ms、128 MB（作っている途中も含む）。変えない。計測はネイティブ（Dawn / Vulkan）だけ。GPU ジョブは同時に 1 本。
  参照（Mitsuba）を描いている間は GPU 時間を測らない。
