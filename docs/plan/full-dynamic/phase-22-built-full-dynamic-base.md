# Phase 22（built）：全形状を毎フレーム作る土台を、ユーザーが実物で確かめる

## 開始プロンプト

```
AGENTS.md と docs/plan/README.md と docs/plan/full-dynamic/README.md と docs/plan/full-dynamic/phase-22-built-full-dynamic-base.md を読み、Phase 22（built）を進めてください。Phase 21 で既定に入れた「建物を含む全形状を毎フレーム作る」構成の前後の画像、連番、ちらつきの分布図、数値、費用を 1 枚のページにまとめて非公開の Artifact に公開し、悪くなった所とまだ見ていない条件を先頭に書いてください。私が気になる所を挙げたら直して測り直し、同じ URL へ再公開してください。最後に AskUserQuestion で OK を取ってください。報告は専門用語の表にせず、何が良くなり何がまだ悪いかを平易に書いてください。
```

## 目的

段階 A の出口。建物が変わる場面を含めて、見た目が良いかをユーザーが確かめる。

## 前提

- Phase 21 の結果（[spec/30-measurements.md](../../spec/30-measurements.md) の 25 節、要約は
  `docs/reference/measurements/full-dynamic/phase21-full-dynamic-base.json`）。目安 G1〜G8 は RC で**すべて満たした**：建物が波打ち物体 64 個が
  動く場面で GI 3.57〜3.65 ms（移動 3.22〜3.28）、一部が現れて消える場面 3.47〜3.62 ms、確保 70.3〜70.8 MiB、参照との誤差 0.414・偏り −14.3%、
  リーク 0.39 / 0.12%、跳び 0.0106 / 0.0077、静止時のちらつき 0。
- 「前」は Phase 21 の前の実行器（`build/native/rc-before.mjs`、コミット cb426bfa の実行器。作業機にだけある。無ければ cb426bfa を
  別の作業ツリーに出してバンドルする）。既定の固定窓の「前」は `--vox '{"anchor":"scene","local":true}'`、全再構築 0.1 m の「前」は
  `--vox '{}'`（建物が変わる場面はこちらでしか描けない）。「後」は `build/native/rc.mjs`（`--vox` なし）。Phase 21 が見た前後の並びは
  `box/in/phase21-check/`（作業機だけ）。
- Phase 21 で変わったもの：層 0 のボクセル 0.1 → 0.2 m、粗い層を層 0 から作る、c0 のプローブ間隔を層 0 のボクセルより細かくしない（近くの
  画素の間接光が少しぼける）、DDGI のレイの区間ごとのボクセルを以前と同じ大きさに保つ。
- Phase 21 が見つけた悪くなった所（ページの先頭に書く）：
  - カメラが動くときのちらつき：静的な `sponza` で RC 15.8 → 18.0%（DDGI 17.4 → 18.2%）。
  - 建物が波打つ場面の跳び：RC 0.147 → 0.182（DDGI 0.114）。一部が現れて消える場面は RC 0.033、DDGI 0.003。
  - DDGI 線形は建物が変わり物体 64 個が動く場面で 4.6〜5.0 ms と 4 ms に入らず、参照との誤差は 0.362 → 0.386。
  - P1（`p1`）は動かなくなった（Phase 31 で直すか消す）。
  - 細かい形（柱の溝、手すり、葉）の近くの陰影の変化と、カメラの近くの間接光のぼけ（Phase 21 は縮小表示でしか見ていない）。

## 決定済みの方針

- ページに載せる場面：何も動かない `sponza`、物体 64 個（変形あり）、建物が変形する場面（`sponza-dynobj-n64-deform-bwave`）、
  建物の一部が現れて消える場面（`-bcut`）、
  移動カメラ、空あり、トゥーンの物体（`sponza-dyn`）。同じ画角、同じフレームで並べる。動きは連番（スプライトシート）。
- 先頭に書くもの：悪くなった所（上の一覧）、まだ見ていない条件（空あり、トゥーンの物体、等倍の細部）。建物が動く場面の跳び（超過変動の
  分布図。RC は DDGI 線形の約 1.6 倍〜11 倍、Phase 21）も悪い所として載せる（直すのはこの段階ではない）。
- 数値が目安に届いたことを OK の代わりにしない。

## 確かめる決定と、その確かめ方

| 決定 | 確かめ方 |
|---|---|
| 建物の変化が画像に出ている | 建物が変わる 2 場面の連番で、建物の形と、その照り返しと影が一緒に変わっている |
| 悪くなった所を隠さない | ページの先頭に一覧がある |
| 直した後に測り直す | 直すたびに Phase 21 の目安 G1〜G8 を測り直して載せる |
| ユーザーの OK | AskUserQuestion（OK / まだ直してほしい（どこを）） |

## やること

1. ページを作って公開する（URL をここに書く）。
2. ユーザーの指摘を一覧にして直す。画像を変えたら同じ URL へ再公開する。
3. OK を取り、spec 30 に節を足し、spec 50 の現在地と「続けるための条件」の 1 つ目の判定を書き直し、列の表を更新する。
   Phase 23 のファイルの「今の値」を、この時点の構成の値に置き換える。

## 完了条件

- ユーザーの OK がある。共通の完了定義（[`../README.md`](../README.md)）を満たしている。
