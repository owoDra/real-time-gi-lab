# 評価方法 — Program 2

数値はすべて**仮置き**である。実測を見て一度だけ確定し、確定後は変えない。確定はチェックポイント C1 で行う
（[roadmap](../research/roadmap.md)。S1 の時点では、ボクセルのトレースを含む GI 全体の時間がまだないので確定しなかった）。

## 原則

1. **同じコストでの品質を比べる。** 予算を固定し、その中での品質と対応範囲を測る。
2. **探索と確認を分ける。** 探索では事前登録をしない。確認実験は最後に1回、条件を
   先に書いてから行う。
3. **実用に近い条件で測る。** RGB、テクスチャ付き、フル解像度。
4. **データの健全性を先に確かめる。**（下の「健全性チェック」）

| 項目 | 値 |

## 指標

| 対象 | 指標 | 測り方 |
|---|---|---|
| 写実品質 | 放射照度の相対誤差、知覚指標（FLIP など） | 参照パストレーサとの比較。非写実物体は放出側プロキシに置き換えたシーンを参照にする |
| 時間安定性 | 帯境界ちらつき率 | 連続フレーム間に量子化帯が変わる画素の割合。静止とカメラ移動の両方。S1 の実装：間接放射照度の輝度を log2 で 1/4 段と 1 段の帯にし、移動時は前フレームへ再投影して同じ面の画素だけ数える。ワールド固定の対照場で測定の床を併記する（`src/core/post.ts`） |
| 応答性 | 光源切替後、定常値の 90% に達するまでのフレーム数 | |
| リーク | 遮蔽された領域に届く偽の放射照度 | N004 のリークシーン |
| 広さ非依存（R2） | ワールドを 10 倍・100 倍にしたときの時間とメモリの変化 | |
| 密度非依存（R3） | 表面積を保って三角形を 10 倍にしたときの時間の変化 | |
| ストリーミング | 高速移動時のフレーム時間スパイク | |
| コスト | GPU 時間（タイムスタンプ）、GPU メモリの真のピーク | |

## 健全性チェック（必須）

Program 1 では「光源移動」と名付けたシーケンスが全フレーム同一で、「剛体運動」の6本が
画像上は静止していた（[記録](program-1/dev-sequence-validity-check.md)）。再発させない。

- 動的シーケンスを作ったら、**参照画像がフレーム間で参照ノイズを超えて変化すること**を
  生成時に assert する。
- 動く物体がカメラから見えていることを確認する。
- 新しいシーンと新しい結果は、数値だけでなく**画像を目で見る**。
- 「最良の比較相手」と書くときは、試した設定の範囲を併記する。

## 計測の作法

- 性能判断は GPU タイムスタンプで行う。CPU の壁時計は補助。
- 確認実験の時間比較は、Program 1 の 045 の方法を使う：独立プロセスを複数回、
  AB/BA の順序を釣り合わせ、中立な対照で最小検出可能効果を先に測る。
  （実装はタグ `archive/program-1` の `scripts/research/lane_m_gi_competitiveness/` にある。）
- 探索中はこの手続きを省いてよい。ただし探索の数値は「探索値」と明記する。
- 負の結果は残す。ただし短く。

## 参照レンダラ

**Mitsuba 3（`llvm_ad_rgb`）に決めた**（2026-11-13、[決定](../research/decisions/2026-11-13-reference-renderer.md)）。
シーンはこちらの glTF 読み込みから変換して渡す。以下は決める前の検討。

参照はオフラインで正解画像を作る道具で、
製品と同じ API である必要はない。RGB、テクスチャ、スタイルの放出側プロキシを扱えること。
Program 1 の CPU オラクル（スカラー、Lambert のみ）は拡張せず、必要ならタグから参照する。

候補（2026-11-13 時点）：

- Mitsuba 3：信頼性が高い。AMD 機では CUDA が使えず LLVM（CPU）バリアントになる。
  Vulkan バックエンドはない。glTF からの変換が要る。
- Vulkan のハードウェアレイトレーシングによる GPU パストレーサ：開発機の RADV は
  `VK_KHR_ray_tracing_pipeline` と `VK_KHR_ray_query` に対応している。既存のもの
  （nvpro の vk_gltf_renderer。AMD で動くかは未確認）か自前。自前なら Mitsuba との
  点検が要る。
- 放出側プロキシは glTF の材質（放射のみ、反射率 0）としてデータで表せる見込みで、
  その場合はどの候補でもレンダラの改造が要らない。
